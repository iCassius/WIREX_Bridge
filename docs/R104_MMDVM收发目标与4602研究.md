# R104：MMDVM 收发目标、TG91 无声与 BM 4602

基线源码：`e93c340`（alpha.3），交接记录提交：`32e2cb6`。本记录依据 MMDVMHost 源码、Pi-Star 主机列表、本机 alpha.3 运行日志及当前 Bridge 源码；未运行电台或发射网络语音。

## 查明的 TG91 无声原因

alpha.3 实际运行日志在 `build/releases/v0.1.0-alpha.3/private/user-config/ui-runs/` 下，只有一份 209 条记录。它记录 BM 会话达到 `ready`，收到 1,881 个 application DMRD 数据报，其中 1,809 个被本机过滤器丢弃。过滤计数落在 `destination_id` 和 `call_kind`，时隙拒绝为 0。日志曾记录 TG91 组呼头，例如 `src=3175445, dst=91, TS2, group`；这里列出该帧说明过滤类别，不表示它是日志最后一帧。

该会话连接的发射目标是鹦鹉私呼 `460997/P/TS2`。`src/probe_main.cpp` 当时又从同一个发射模板生成接收过滤器；私呼接收目的因此取本机 Source ID `4611355`。结果是 BM 网络连接正常、界面出现 TG91 来话，而 TG91 帧在音频解码前被本机目的 ID 与呼叫类型过滤器丢弃。日志中的 TG91 头字段和计数直接支持这一结论。

因此 R104 将 TX 与用户选择的 RX 目标分别保存、传给核心并显示。鹦鹉预设为 TX `460997/P/TS2`，其返回流 `本机 Source ID/P/TS2` 必须作为回音接收路径保留；TG91 预设为主 RX `91/G/TS2`，并由核心禁用所有上行。若用户同时把 TX 设为鹦鹉而主 RX 设为 TG91，核心还须接受一条窄范围的私呼返回：仅当 TX 发射许可开启且 TX 类型为 private 时，匹配 `src=TX destination`、`dst=本机 Source ID`、`type=P`、`slot=TX slot`。该规则不放行其他来源或目的的私呼；listen-only 时不增加返回规则。旧配置没有 RX 字段时，保持旧推导：组呼接收目的沿用 TX 目的，私呼接收目的使用本机 Source ID。首版支持一个用户选择的 RX 目标，加上满足上述条件的单通本机私呼回包；它不是多组并发订阅。运行实现的显式规则仍须由 Native 与 UI 联合验收确认。

## MMDVM 收发路径对照

G4KLX [MMDVMHost `DMRNetwork.cpp`](https://github.com/g4klx/MMDVMHost/blob/master/DMRNetwork.cpp) 将网络收到的 DMRD 字段解析为 Source ID、Destination ID、slot 和组呼/单呼类型；slot 1/2 的启用条件是独立的网络配置。在 [MMDVMHost `DMRSlot.cpp`](https://github.com/g4klx/MMDVMHost/blob/master/DMRSlot.cpp) 中，网络到 RF 的媒体由 `writeNetwork` 处理，再进入 `writeQueueNet`；RF 到网络的媒体由 `writeNetworkRF` 组装 DMRD 并调用 network write。两个方向分别处理。

MMDVMHost 在 `CDMRNetwork::write` 的网络上行边界检查 `g_listenOnly`，只收时不把 RF 解出的 DMR 数据写往网络。[源码位置](https://github.com/g4klx/MMDVMHost/blob/master/DMRNetwork.cpp#L176-L180) 因此 WIREX Bridge 的 TG91 预设也应在 Native 核心禁止手咪/键盘/其他来源的 BM 上行；只把发送 UI 灰掉或把 TX 目标改成别的 ID，都不足以构成只收策略。

MMDVMHost 的通话 slot 由每帧携带的时隙标志解出，随后进入相应时隙处理。它并不要求 RX 目标与当前 RF TX 的 TG/Radio ID 使用同一个 UI 字段。Bridge 采用单一显式 RX 过滤器来决定哪些到达的 DMRD 可以进入语音 Receiver；发射目标保留为独立的 DMR CallConfig。后续若要多 TG 同时收听，应再定义接收集合和并发媒体仲裁，本轮不把单 RX 冒充多组订阅。

## PTT 与回音日志边界

该 alpha.3 日志有 168 次 HRI PTT 状态观察、4 次 `tx_started_from_radio_ptt_down` 和 4 次对应结束。三个成功接收的 BM 私呼流均出现 T3、`hri_t3_observed_playback_enabled`、BM EOT、音频排空、T0；最后一次共记 186 个播放帧和 176,058 个 PCM 样本。下行区间的累计 PTT start/end 数没有增加，4 次 TX start 的日志事件都明确来自 `radio_ptt_down`。

这份旧日志证明 alpha.3 曾处理完下行 PCM 和 T0 收尾，也证明日志里的 TG91 被过滤；它没有记录用户本轮报告的“鹦鹉回音继续触发 PTT”，所以不能用来解释该现象或声称已经修复。`hri_ptt_gate` 的启动动作来自 HRI PTT observation；R104 需要在禁发和收发配置后保留这条事件来源证据，并在下一份实机日志确认回音期间没有新的 radio PTT down/上行 DMRD。

最小实机对照应各执行一次并分别保存日志：

1. `parrot-cn`：确认 TX `460997/P/TS2`、RX `4611355/P/TS2`；手咪按下讲话后松开，等待一次回音。检查日志中手咪 PTT start/end 各一次、回音 `playback_frames` 大于零、T0 收尾，回音期间无第二个 `radio_ptt_down`、无额外 TX stream。
2. `listen-91`：确认 RX `91/G/TS2` 且核心 `transmit_enabled=false`；接收一通 TG91。检查 DMRD 头通过目的、类型、时隙过滤，语音帧进入 Receiver，WaveOut 播放结束；整个 run 的 BM 上行语音数据报为零。

T3 身份字段只能通过以上两个场景确认不会影响既有音频和 PTT。单看 UI 的身份标签或 Native PCM 计数，不能替代电台扬声器听音和真实 PTT 观察。

## T3 Source ID 字段编码核对

当前源码中 `hri_call_header::source_callsign_offset=0x12`，T body 头部从 body 偏移 7 开始，因此被修改的位置为 body `[25..34]`，共 10 字节。T3 body 的基础内容由 ASCII 字符组成；`overlay_source_id_label` 用普通可打印 ASCII 写入 `ID` 加十进制 Source ID，右侧补 ASCII 空格。R100 对 `4611355` 写入字节串 `ID4611355 `，不是把字符串转成 ASCII HEX，也不是把整数按十六进制写入。`hri_call_header` 字段访问器验证固定宽度可打印 ASCII，`hri_lcd_identity_candidate_test` 断言输出与 `ID4611355 ` 相同。

这只能确认程序构造出的 T body 字节。官方 DLL 静态记录显示 T 正文被交给记录 factory，再经 `WM 0x618` 送入 EXE `WriteFile` 参数；factory 的额外 9 字节布局和 FTX-1 对字段内容的解释尚未恢复，详见 [R103 静态摘要](R103_HRI记录到WriteFile路径摘要.md)。因此不能声称电台 LCD 一定把这些字节显示成 Source ID。

这个字段是 HRI 头部中的 `source_callsign`，与 `local_callsign`（头部 `+0x1c`）分开。当前 `overlay_source_id_label` 只改 source 字段，不改 local/destination 字段；在当前基础 T3 body 中，local 与 destination 仍是基础构造器给出的内容。源码已有注释说明 local 字段来自 `DGRP_COMMON` 配置，但基础 body 构造函数返回的全零字符模板没有调用该复制路径。因此本轮只能确认“本机 Source ID 不会写入 HRI local 字段”，不能据此确认电台最终显示或 DIRECT 中本机身份语义。对照测试应固定同一个回音流和电台状态，先用原 source 字段，再用 `ID...` ASCII 标签；比较 HRI 发射状态、回放、PTT 与屏幕文字，任一配置仅单次运行并保留字节记录。

## BM China 4602 预设

Pi-Star 当前 [DMR hosts 列表](https://www.pistar.uk/downloads/DMR_Hosts.txt) 将 `BM_4602_China` 指向 `4602.master.brandmeister.network`，UDP 端口 `62031`。地区资料也列出 IPv4 `43.129.83.124`，但另有一处列 `62023`；本项目已成功会话使用用户提供的 `43.129.83.124:62031`。因此 UI 预设采用 `BM China 4602 / 43.129.83.124 / UDP 62031`，同时保留自定义服务器地址和端口。预设不填入密码；连接认证继续从本机既有密码文件读取。

该端点用于 BM Master 控制/DMRD 网络，不表示 TG91 已为本机 hotspot 开启静态订阅。TG91 收听仍需 Master 发送对应组呼流，并由本机 RX filter 接受。网络预设、RX 目标和 TX 目标分别呈现。
