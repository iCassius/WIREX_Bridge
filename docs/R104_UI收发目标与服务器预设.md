# R104：收发目标与服务器设置界面

## 界面约定

设置页分别保存 BrandMeister 发射目标和接收目标。发射目标由 Radio ID、呼叫类型和时隙组成，接收目标也由独立的 ID、呼叫类型和时隙组成。`transmit_enabled` 单独保存手咪到 BM 的发射许可。

主界面显示本次运行的接收目标、发射目标和发射许可。连接启动时，程序冻结本次生效的设置；运行期间切换主界面目标只更新“下次连接”说明，不改当前运行会话显示。保存设置后，主界面也保留本次运行的冻结值，同时在收发状态区列出下次连接将使用的 RX、TX 和发射许可。

主界面预设的生效规则如下：

| 主界面目标 | 接收目标 | 发射目标 | 发射许可 |
|---|---|---|---|
| 中国鹦鹉 | 本机 Source ID / P / TS2 | 460997 / P / TS2 | 开启 |
| 全球收听 TG91 | 91 / G / TS2 | 保留设置中的目标 | 关闭 |
| 本地收听 TG46001 | 46001 / G / TS2 | 保留设置中的目标 | 关闭 |
| 使用已保存目标 | 保留保存的 RX | 保留保存的 TX | 保留保存的许可 |

若在设置中勾选“允许向 BrandMeister 发射”，主界面仍选择 TG91 或 TG46001 时，当前生效发射许可继续为关闭。界面说明用户需在主界面选择“使用已保存目标”才能应用保存的发射许可。

私呼发射且许可开启时，Bridge 还接收精确匹配的本机私呼回话：来源为 TX 目标、目的为本机 Source ID、呼叫类型为 P、时隙与 TX 相同。主接收目标若已是本机 Source ID / P / 同一时隙，不重复显示这条规则；TG91 与 TG46001 只收预设不启用发射或额外回程接收。鹦鹉目标的额外回话显示为“鹦鹉回声”，其他私呼目标显示为“发射目标私呼回话”。

旧配置未保存 RX 字段时，读取层沿用旧行为：组呼接收目的 ID 使用旧 TX 目标；私呼接收目的 ID 使用本机 Source ID；接收呼叫类型与时隙沿用旧 TX 类型及时隙。写回配置时将 RX 三元组和发射许可一起保存。明确的空对象、空值、部分 RX 字段和错误类型均作为配置错误处理。

## BrandMeister 服务器设置

服务器预设列出 `BM China 4602`，地址为 `43.129.83.124`，UDP 端口为 `62031`。用户也可以选“自定义服务器”并填写地址和端口。读取或打开设置不会改写本机私有连接配置；只有保存设置才会写入所选值。

密码正文不会写入发布内容。设置仍使用本机密码文件路径引用，由既有用户配置模块管理。

## 启动参数与用户配置

UI 向核心传递独立的 `--profile-receive-destination-id`、`--profile-receive-slot`、`--profile-receive-call-kind` 参数。接收参数必须完整且通过 ID、slot 和类型校验。`transmit_enabled=false` 时，UI 额外传递 `--listen-only`；未知启动参数、重复参数或缺少接收参数都会在创建核心进程前被拒绝。

本轮不变更用户配置目录解析。直接启动 release 目录时，用户配置继续位于该包的 `private/user-config`；个人入口可传入工程的 `app/private/user-config` 作为共享配置目录。运行中修改设置只影响下一次连接。

## 当前验证与未覆盖项

本轮 Windows PowerShell 5.1 离线检查覆盖旧 schema 读写、RX 与发射许可字段校验、UI 启动参数允许列表、设备选择、生命周期、状态摘要、收发目标预设和 UI 渲染。`test-ui-render.ps1` 使用当前源 UI 和 alpha.3 核心目录运行离线预览，并检查 1024×728 工作区。

本机 alpha.3 日志记录了 BM 收到 TG91 头字段，但 Bridge 当时将大部分应用数据报按目的 ID 或呼叫类型丢弃。当前 UI 能把 RX 与 TX 分别配置和展示；本轮没有启动电台或连接 BM，因此尚未验证 TG91 音频以及鹦鹉回音期间是否再次触发 PTT。相关日志分析和后续实机检查见 [R104 MMDVM 收发目标与 4602 研究](R104_MMDVM收发目标与4602研究.md)。
