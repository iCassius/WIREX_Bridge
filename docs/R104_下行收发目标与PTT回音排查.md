# R104：下行收发目标与 PTT 回音排查

## 目的与证据范围

本记录针对 alpha.3 实际运行时出现的两项现象：TG91 界面有活动但电台没有声音；中国鹦鹉回音后用户观察到电台继续显示或触发 PTT。数据来自本机 alpha.3 状态日志及 Native 源码。未打开电台、串口、音频设备或 BM 网络作本次实测。

本次日志位于 `build/releases/v0.1.0-alpha.3/private/user-config/ui-runs/` 下；汇总记录有 209 行。日志中没有密码内容。

## alpha.3 日志发现

- BM 会话到达 `ready`，日志记录 1,881 个应用层 DMRD 数据报，其中 1,809 个被 Native 接收过滤器拒绝。拒绝计数指向目标 ID 和呼叫类型；日志中的 TG91 组呼包头包含 `source=3149876, destination=91, TS2, group`。
- 同一会话将 TX 私呼的参数也用于 RX 过滤。接收规则因而期待本机私呼 ID `4611355/P/TS2`，TG91 群呼 `91/G/TS2` 被丢弃。UI 在读到包头时可显示活动，Native 媒体过滤随后拒收该流；旧界面没有区分“收到包头”和“通过 RX 过滤并开始播放”。
- 日志另有发往本机 ID `4611355` 的私呼回音，并经过 T3、PCM 解码和播放排空路径。T3 来源字段插入了 `ID460997`。Native 日志没有记录实际电台 LCD 确认。
- 本次运行合计记录 4 次 PTT start/end。接收播放期间 HRI PTT 状态为 `unknown`，且没有 PTT start；另外两次 PTT start 发生在各接收播放排空、T0 收尾之后。仅凭该日志无法确认这些边沿来自手咪操作还是电台在回音后的行为，也没有证据显示 Bridge 在播放期间把回音再次送入 BM。

这项 PTT 问题仍需本轮版本的实机听音与屏幕观察。测试时应分别记录手咪动作、红色 X/PTT 图标变化、回音播放开始和停止时刻；Native 的 PTT start 计数与电台屏幕图标需分开记录。

## Native 收发规则

R104 将收听规则从发射呼叫目标中分离。独立接收配置由 DMR ID、Timeslot 和呼叫类型组成；省略时为旧连接配置保持原行为：组呼按 TX 目标收听，私呼按本机 Source ID 收听。TX 的目标、时隙和呼叫类型仍由原连接配置决定。

当 TX 目标是可发射的私呼时，Native 还允许一条窄回音路径：来源 ID 必须等于 TX 目标，目标必须等于本机 Source ID，类型必须为私呼，时隙必须等于 TX 时隙。该规则与单一用户选择的 RX 规则取并集。明确启用只收时，Native 不创建回音接收规则，且现有手咪/键盘 TX 入口都受同一只收策略阻止。TG91/46001 的既有禁发策略仍然生效。

此设计对应 MMDVM/BrandMeister 的使用方式：BM 静态订阅控制网络下行组，而用户当前发射呼叫有自己的目标。一个目标字段不能同时准确表达 TG91 收听和 460997 私呼测试回音。MMDVM 对照与 BM China 4602 信息见 [R104 MMDVM 收发目标与 4602 研究](R104_MMDVM收发目标与4602研究.md)。

过滤计数保持旧状态 JSON 字段。每个被拒包只增加一次 `rx_filtered_datagrams`；目标、时隙、呼叫类型原因按失败条件最少的接收规则统计。窄回音规则的 source ID 拒绝归入现有 `rx_filtered_protocol`，避免为该规则扩大 UI 状态 schema。

## 音频与实际验证边界

TG91 和鹦鹉回音在 Native 层都必须通过同一个 DMR decoder、PCM 播放队列和 HRI T3/T0 收尾状态机。离线回归验证两条路径都能接受语音帧、产出 PCM，并处理 EOT；这不能替代实际 FTX-1 扬声器听音或 RF 发射观察。UI 选择的回放增益按配置生效，不在代码中私自提高。

本轮不宣称 PTT 回音现象已通过实机修复；也不宣称已在电台屏幕看到 `ID460997`。最终实机测试使用 TG91 作为 RX、460997 单呼作为 TX，并确认只收开关关闭时才执行鹦鹉回音。
