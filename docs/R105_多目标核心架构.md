# R105：多监听目标、来源过滤与独立发射目标的核心架构

## 目的和结论

本文基于 WIREX Bridge Native 仓库 HEAD `71a45c7c`、alpha.4 交接入口、现有语音管线、BM session、UI 控制协议和 R104 文档提出架构契约。本文后附一个独立纯内存路由/租约模型及单测；该模块没有接入正式 pipeline、BM、HRI、设备或 UI。没有进行 BM 网络或真实设备操作。

多目标模型分成三个互不代替的层：

1. **BM 网络订阅**记录 BM 端静态或动态组的远端配置、请求和可观察状态。
2. **本地 RX 策略**决定已经到达本机的 DMRD 通话是否进入唯一的语音管线。
3. **本机 TX 策略**决定是否允许发射以及下一通发射要使用的目标。

BM 没有报告订阅状态时，本地 RX 仍按本地策略处理收到的合法 DMRD。远端状态为 `unknown` 不能用来拒收数据，也不能显示成“已订阅”。网络是否把某组呼送到本机由 BM 决定；本机 allowlist 只影响收到后的处理。

## 当前源码边界

- `include/wirex/bm_voice_pipeline.hpp` 只有主 `ReceiveFilter` 和一个 secondary filter。`src/bm_voice_pipeline.cpp` 在 TX/RX 忙时拒绝修改 filter；单条 pipeline 同时只持有一个活动 RX 通话和一套 PCM 播放队列。它不是多路并行解码器。
- 当前 `process_receive_result` 在新通话与已有 TX/RX 冲突时发出 collision 并清理 RX。未来仲裁必须在把新流交给当前 Receiver 前完成，不能让一个晚到流取消已取得播放权的通话。
- `include/wirex/bm_session.hpp` 的 session 阶段涵盖登录、认证、配置、可选 options、保活和 DMRD；仓库当前没有 BM TG 加入/离开控制 API。静态订阅的远端事实和动态控制能力都不能从现有代码推断。
- `include/wirex/ui_control_protocol.hpp` 的 Native UI 管道协议只接受 `Q` 加换行或 EOF 作为停止请求。`src/probe_main.cpp` 输出 schema version 1 的 JSONL 状态快照。现有协议没有运行时目标更新命令。
- R104 定义了一个显式 RX 目标和一个有限的私呼回音 secondary filter；它没有实现多组接收集合或 BM 订阅控制。

以上是源码事实。下文结构、状态值和 IPC v2 均为 R105 建议，不表示当前版本已经支持。

## 领域模型

### 1. BM 网络订阅

每个订阅条目描述一个组呼通道，至少包含：

| 字段 | 含义 |
|---|---|
| `subscription_id` | 在当前 profile 内稳定且唯一的标识 |
| `kind` | `static` 或 `dynamic` |
| `destination_id` | 组号 TG；只用于 group 条目 |
| `bm_subscription_slot` | BM API 的订阅 slot 值 0、1 或 2；0 的含义由该 API 定义，不能直接当作媒体时隙 |
| `desired_state` | 用户希望 BM 侧维持的状态 |
| `observed_state` | `unknown`、`requested`、`active`、`inactive`、`failed`、`expired` 或 `unsupported` |
| `request_id` | 当前动态控制请求的关联 ID；静态条目可为空 |
| `last_error` | 可选的稳定错误代码，不放凭据或原始语音数据 |

静态组由 BM API 管理并可通过 API readback 核对。API Key 与 BM hotspot 的设备密码是两类不同凭据，必须分别取得、分别保管；状态、profile 与日志不得包含密钥正文。没有 API Key 或 readback 失败时，静态订阅状态应显示 `unknown` 或 `failed`，不能假设已启用。

动态加入通过 SharkRF Quick call 发出短 DMR 组呼，是一次真实网络 TX，不是本地订阅元数据更新。必须由用户明确点击“呼叫加入”才可请求；发现新 TG、创建候选卡片、点击本地收听或应用启动都不得发送 Quick call，也不得自动续期。TG91/TG46001 只收策略禁止动态加入。动态加入必须经过当前 TX permission 与媒体 owner 检查；只收、TX 禁用或 TX/RX 正忙时拒绝请求，不得把 Quick call 排队到稍后自动发射。短呼已发送只说明本机发出了请求；没有 BM API/readback 或其他可靠证据时，远端订阅保持 `requested`/`unconfirmed`，不得标成 confirmed。到期后只显示 expired，不自动重加。

主连接地址、账号或设备 profile 改变可能需要重连；单独更改本地 RX 过滤不需要重连。

静态 API 请求的 `accepted` 只说明本机接受或排队；readback 才能报告 BM 当前配置。Quick call 若因发送许可或媒体忙被拒绝，必须立即返回 busy/denied，不能延后发送。Quick call 命令 accepted 表示已创建当前 TX lease 并开始本次真实 TX；发送成功后仍未必有远端加入确认。网络订阅状态用于呈现和诊断，不作为下面本地 RX 的额外准入条件。

### 2. 本地 RX allow/block

推荐把当前单个 RX 目标替换成一个原子更新的 `RxPolicy`。组呼策略有两个显式模式：`Selected` 只接收用户勾选的通道；`AllDelivered` 接收 BM 实际送达的所有合法组呼，再减去本地屏蔽项。私呼策略独立配置：关闭、只接收所选 peer，或接收发给本机 ID 的所有 peer。私呼永远不接受目的 ID 是其它用户的通话。

| 字段 | 匹配语义 |
|---|---|
| `group_mode` | `Selected` 或 `AllDelivered` |
| `allow_groups[]` | 每项匹配 `(destination_id=TG, slot, call_kind=group)`；仅 `Selected` 用于准入 |
| `private_mode` | `disabled`、`selected_peers` 或 `all_peers_to_local` |
| `allow_private_peers[]` | 每项匹配入站私呼的 `(source_id=远端peer, destination_id=本机ID, slot, call_kind=private)` |
| `blocked_groups[]` | 按 `(destination_id=TG, slot, call_kind=group)` 排除通道；只屏蔽对应 slot，不影响同 TG 的另一 slot |
| `blocked_source_ids[]` | 排除发话人的 Source ID；对组呼和私呼都优先于 allow 项 |

DMR 身份必须按作用区分：

- 组呼的目的 ID 是 TG；Source ID 是本通话的发话人。TG 按 `(TG, slot, G)` 识别，发话人不参与 TG 键。
- 入站私呼 peer 是远端 Source ID，来话仍需满足 DMR destination ID 指向本机 ID、呼叫类型为 P 且时隙匹配。用户选择私呼收听对象时选择 peer；用户排除一个人时在 `blocked_source_ids` 增加该人的 Source ID。
- 本机 TX 目标的 DMR destination ID 是发射去向。它不会自动成为一个 RX TG 或 speaker。既有鹦鹉回包是一个独立的精确 RX 例外：发射许可开启、TX 为私呼时，仅匹配 `src=TX peer, dst=本机ID, P, TX slot`。

AllDelivered 会为每个首次出现的合法 TG 创建候选卡片；候选卡出现本身不改变本地策略或远端配置。Selected 下新候选默认不播；AllDelivered 下新候选可以收听，但仍受屏蔽规则约束。发现新 TG 不能自动添加 allow、清除 block、切 TX 目标或加入 BM 远端订阅。

候选报告带观察级别：`outer_header_seen`、`link_control_validated`、`router_reserved` 或 `playback_started`。外层 DMRD 头中可见 Source ID/TG 只说明观察到一个候选；它不能证明 LC 已验证、BM 已订阅、本机已播放，或来话身份已确认。Native/UI 应按实际证据逐级更新，不能把候选卡画成已订阅、已播放或已确认身份。纯路由模块只接收前置 DMRD/LC 验证结果并返回观察值，不执行 codec、密码学验证或网络订阅。

本地判定顺序为：先校验 DMRD 和呼叫头；按 group mode/private mode 检查本地 allow；再套用 blocked route/source；最后交给半双工仲裁。block 总是胜过 allow。Group block 使用与通道按钮相同的 TG+slot 键，同一 TG 的另一个 slot 不受影响；Source ID block 作用于所有本地 RX 路由。网络订阅状态不参与此判定。过滤前不解码语音、不建立 HRI 播放，也不创建可延迟重放的音频队列。

从来话创建快捷按钮时，group 按 `(TG, slot)` 建立；private 按 peer 建立。通话卡片显示 Source ID。排除某个发话人只编辑 `blocked_source_ids`，不为该人创建 TG 卡片；这一排除影响所有本地 RX 路由。普通“停止本地收听”移除对应 `(TG, slot)` allow；显式排除通道则写入相同键的 `blocked_groups`，block 胜过 allow，但同 TG 的另一个 slot 不受影响。之后重新收听时，应在同一次原子策略更新中清除该 route block 并添加 allow，不能留下看似已启用但仍被 block 的状态。停止本地收听或排除通道只改 RX policy，不隐式离开 BM 的动态组或删除远端静态配置。

同一时隙上本地允许多个 TG，只表示本地接受策略覆盖多个目标。BM 可能因该时隙已路由另一组而不向本机发送指定组；本地策略无法要求 BM 同时下送同一时隙上的多组。

### 3. 独立 TX 目标和通话租约

`TxPolicy` 与 `RxPolicy` 独立保存：

- `tx_target = {destination_id, kind, slot}` 允许 group 或 private。
- `transmit_enabled` 是核心发送门，必须在每个 TX 开始入口检查，不能只由 UI 灰化按钮实现。
- 手咪 PTT down 获准开始时，核心建立不可变 `active_tx_lease`，复制当时的 TX target、策略 revision 和 call ID。
- PTT 按下期间更改 TX target 只更新下一通的候选目标。当前通话的所有语音帧及终止 LC/EOT 都使用租约里的原目标。
- PTT release 后停止取新麦克风 PCM，按原租约排空已接收的有效语音并发送 EOT。正常路径只有在 EOT 已交给 BM 发送路径且该 TX generation 完成后才释放租约并允许新目标生效。断网或发送失败时结束租约但记录 `eot_sent=false` 或明确失败原因，不伪报正常 EOT。
- 半双工忙时拒绝新的 PTT 请求，不排队等待 RX 结束后自动发射。用户需先松开 PTT，下一次按下才可建立租约。
- `transmit_enabled` 从 true 改为 false 时，核心立即停止给当前租约采集新的 PCM，返回需要外层停止的 lease ID，并进入 EOT drain；owner 继续占用到 EOT/清理确认。若权限重新打开时原手咪仍按下，必须先观察到松开，再允许新的 PTT。
- TG91 和 TG46001 组呼始终是只收目标。即使调用方没有提供动态加入 deny list，也必须由核心策略门拒绝发向这两个 group 的 PTT 和 Quick call。
- 动态 Quick call 的 TX permission 或媒体 busy 检查失败时立即拒绝，不排队等待。显式加入产生的短呼使用独立的 Quick call lease；完成当前 EOT 后释放。

## 单流半双工仲裁和旧媒体清理

语音设备同一时刻只能拥有一个媒体租约：`idle`、`rx_active`、`rx_draining`、`rx_stopping`、`tx_active`、`tx_draining` 或 `fault`。R105 多监听表示“可接受多个来源”，不表示同时混音或并行播放。

RX 仲裁器在调用现有 `Receiver::ingest` 前，依据上游 DMRD/呼叫头验证结果、本地策略和流身份作出准入。第一个通过策略且满足通话启动条件的流占有唯一 RX generation；活动流键至少包含 `stream_id, source_id, destination_id, slot, kind`。占用期间其它流直接丢弃并计数，不进解码器、不进入队列，也不能取消当前流。槽位释放前不得切换到其他通话。

TX 或 TX drain 占有媒体时，所有 BM 来话不进入 RX 解码和播放队列。RX 或 RX drain 占有媒体时，PTT 开始立即返回 busy；不得把 PTT 延后执行。未被准入的网络流没有本地缓存；媒体 owner 空闲后不能从旧流的中间帧开始播放，等新的有效通话启动。

RX owner 采用显式停机确认：策略更新移除活动通话时，立即拒绝该 generation 的后续包并进入 `rx_stopping`，同时返回应清理的 generation；owner 仍被占用，直到外层完成 PCM/WinMM 清理及 HRI T0 收尾，再调用 `complete_rx_stop(generation, cleanup_result)`。清理失败进入 fault 并继续拒绝新 RX/PTT，不能提前释放 owner。自然 EOT 走 `rx_active -> rx_draining -> playback_finished -> rx_stopping -> complete_rx_stop`，在 HRI stop 完成前也不接受下一流或 PTT。

EOT 的正常收尾继续排空**当前 generation** 已经接受的 PCM。若用户新加的 block 命中当前活动来话，或更新策略后当前活动来话不再匹配，核心立即取消该 generation：拒绝后续包，清掉待解码 burst、PCM 播放队列、在途播放确认和 HRI 待播数据，执行已有的安全停止/收尾流程；晚到的播放 ack 因 generation 不同而丢弃。绝不能把旧 generation 的 PCM 播给下一通话。

## 运行中更新规则

1. `rx_policy.replace` 对完整的新策略做严格校验，再以单个 revision 原子替换。新规则从命令处理成功时起生效。revision 是事件循环里的 stale-write/CAS 检查，不是线程安全保证；Router 按单线程事件循环调用。
2. 若活动 RX 在新策略下不再获准，立即拒绝该 generation 后续包并进入 `rx_stopping`；返回取消 generation。外层清理 WinMM/HRI 后显式确认，成功前仍占媒体 owner；若活动 RX 仍获准则保留当前流和 generation。未影响活动流的其他规则变化不打断播放。
3. 新增 allow 项不回放此前缓存的包。它对命令处理后出现的有效 call start 生效；此前已被拒绝的通话不在中途加入，等待新的 stream/call start。
4. 新增 `blocked_source_ids` 即刻阻止该来源；若它是当前 speaker，按规则 2 立即停止该流。blocked TG 对正在播放的同 TG 活动通话执行相同处理。
5. 本地 RX policy 更新不发 BM 控制包、不重建 BM session、不重连设备。BM 订阅请求是独立命令和独立状态更新。
6. TX target 更新只改待用 target。活动租约不变；新的 target 在 PTT 已释放且 EOT/终止处理结束后用于下一次 TX。
7. `transmit_enabled=false` 立即禁止新租约；若已有 TX lease，返回该 ID、停止新增 PCM 并进入 `tx_draining`，按界限完成 EOT。owner 到 EOT 发送和清理完成前仍保持忙。权限再次打开也不能绕过原手咪的释放观察。

## 配置迁移

当前 R104 配置用 `connection` 保存 TX 目标，用 `receive` 保存一个 RX 三元组，并以 `transmit_enabled` 控制发射许可。建议新 profile 明确写入 schema version，并保存 `rx_policy`、`tx_target`、发射许可和可选 `network_subscriptions`。

- 旧配置的 `connection.destination_id/kind/slot` 迁移到 `tx_target`。
- 旧配置的 `receive` 若为 G，迁移为一项 `allow_groups`，保持原 TG 与时隙。
- 旧配置的 `receive` 若为 P，原规则只限制呼叫类型、时隙和本机目的 ID，并未限制远端 speaker；迁移为本机目的 ID 和时隙上的“任意私呼 peer”规则，不能错误地把本机目的 ID 当远端 Source ID。
- 若没有 `receive`，保持 R104 回退：TX group 目标成为单项 RX allow；TX private 目标接收发往本机 Source ID、同类型和时隙的私呼。
- 仅在发射许可开启且 TX 是 private 时派生 R104 的精确鹦鹉回包例外。它仍受 blocked source 规则约束。
- 缺少旧版 `transmit_enabled` 时保持既有默认值 true；只收预设仍显式 false。
- 缺失 `network_subscriptions` 不清空或猜测 BM 上的静态订阅，本机该状态标成 unknown/未声明。它不影响本地 RX allow。
- 不完整旧 RX 三元组、重复/冲突条目、超范围 ID、非法时隙或未知呼叫类型必须拒绝保存或启动，不能做部分迁移。

迁移应先在内存中完成验证，只有完整的新对象有效时才替换旧对象；读配置不产生副作用。写回后保留未知字段的现行策略需要沿用配置模块的明确约定，不能在本架构文档中臆定。

## IPC 与状态报告建议（协议 v2）

现有 `--ui-pipe` 的 Q/EOF 停止管道不能直接把多字节目标命令拼进 v1。新协议必须显式协商版本或使用独立控制端点，严格区分 v1 和 v2。

推荐 v2 命令为带换行的 JSON 对象，至少带 `schema_version=2`、当前 `run_id`、每次唯一的 `request_id`、命令名和参数。第一批命令：

| 命令 | 行为 |
|---|---|
| `rx_policy.replace` | 提交完整 allow/block 集合，并带 `expected_revision` 做 compare-and-swap |
| `tx_target.replace` | 更新下一通 TX 候选目标，不改变活动租约 |
| `transmit_permission.set` | 更新新 TX 租约的发送门 |
| `network_subscription.static_set` / `static_readback` | 通过 BM API 改变或读取静态订阅；API Key 走独立的安全凭据来源，结果带 readback 状态 |
| `network_subscription.quick_call_join` | 用户显式操作才发起的动态组 Quick call；真实占用 TX 媒体 lease，不自动续期 |
| `shutdown` | 执行现有有界停止流程 |

每条命令先完整校验，再原子应用；部分字段错误不得改变状态。`request_id` 在 run 内去重；同 ID 不同正文拒绝。`expected_revision` 不匹配返回 conflict。建议回报 `command_result` 为 `accepted/rejected/busy/conflict/unsupported` 并回显 `request_id`。动态 Quick call 若被接受，应立即建立 TX lease 并开始本次发送；它不进入等待发送队列。随后状态报告 call 已发出/未确认/已确认/已到期或失败。超时不自动重试，不自动续期。静态 API 状态以 readback 为依据。UI 分开展示远端静态订阅 readback、动态请求状态、本地 RX allow/block；三种状态不可互相推断。

状态事件保留 `run_id`、严格递增的 `seq`，并增加配置 revision 和明确的租约/策略字段，例如：

- `rx_policy_revision`、`tx_target_revision`、`network_subscription_revision`；
- `active_rx` 的 source、destination、slot、kind、stream_id、generation、观察级别和匹配规则 ID；
- `active_tx_lease` 的被冻结 target、PTT release 观察、EOT 状态与结果；
- `media_owner`、因半双工仲裁而丢弃的包数；
- 每项网络订阅的 desired/observed state、request_id 和 last_error。

UI 只在读到当前 run、合法 sequence 和校验通过的状态后更新“生效”标签。命令被接受、用户保存配置、BM 收到普通 DMRD 或本机过滤器允许该 TG，都不能单独证明远端订阅已启用。

## 最小实现切片与验证矩阵

按风险隔离实现；当前已完成一个不接实时 pipeline 的纯内存 model/lease 切片。配置迁移、BM 订阅、IPC 和正式运行链仍属于后续工作：

1. **纯内存 policy/model**：本轮实现 `RxPolicy`、`TxPolicy`、call identity、revision、Selected/AllDelivered、allow/block 匹配、私呼 peer 解析和媒体租约状态机。NetworkSubscription 与旧配置迁移仍未实现；本切片不连接 socket、设备或 UI。
2. **离线仲裁器**：用合成、已标注验证级别的 DMRD 呼叫身份验证唯一媒体 owner、busy 行为、活动流保护、更新时取消、generation 清理与无陈旧回放。Router 按单线程事件循环使用；revision 仅防止陈旧更新，不提供线程安全。候选值由调用方持有，Router 不保留候选缓存。随后才接入真实 pipeline 生命周期。
3. **lease 与 IPC v2**：在 fake BM sender/HRI ack 下验证 TX 目标冻结、release/EOT 顺序、request_id 去重、revision 冲突和异步订阅状态。然后再接 UI 状态呈现。
4. **BM 订阅适配器**：静态 API 读取/写入与 API Key 保管独立实现；动态 Quick call 必须由显式操作触发并作为真实 TX 仲裁。静态状态未知时仍应能按本地 RxPolicy 收听已经到达的帧。

| 检查场景 | 期望结果 |
|---|---|
| TG91 与另一 TG 同时在 allow；不同 slot | 两者可各自准入，但同一时刻只播放一通 |
| 同一 slot 多 TG 均在 allow | 本机按实际到达流匹配；不声称 BM 一定同时下送 |
| 某 speaker 命中 blocked source，但其 TG 在 allow | 整通丢弃；计入 source block 原因 |
| 某 TG 命中 blocked group，但 speaker 未被 block | 整通丢弃；其它 TG 不受影响 |
| 入站 private peer 匹配源 ID，目标为本机 ID | 按 peer allow 准入；改用 peer ID 作为 TG 不得匹配 group |
| 活动 RX 时第二条流开始 | 第二条在解码/播放前丢弃；当前 generation 保持不变 |
| RX/RX drain 时 PTT down | 立即 busy；RX 结束后不自动 TX |
| 活动 TX 时关闭 transmit_enabled | 返回当前 lease ID，立刻停止采集新 PCM，维持 owner 到 EOT/清理确认；若之后重开且 PTT 未松开则拒绝新 TX |
| empty deny list 下 PTT/Quick call 目标为 TG91 或 TG46001 | 内建只收策略仍拒绝这两种 group 上行 |
| TX/TX drain 时收到 BM 流 | 不进入 RX 队列；TX 租约目标不改变 |
| 添加 allow 时旧流 PCM 曾被拒收 | 不补播旧数据；只处理命令后有效的新 call start |
| 活动 RX 的 speaker 被 block | 当前 generation 立刻停止；旧 PCM 和迟到 ack 不污染下一通 |
| PTT down 后修改 TX target，再 release | 语音和 EOT 都仍使用旧 lease；下一次 PTT 才用新 target |
| EOT 发送失败或 BM 断开 | 记录失败/未发送，不伪报正常结束；清除媒体租约后才允许新通话 |
| Dynamic request 返回 accepted 但没有远端确认 | 状态保持 requested/unknown/timeout；不标 active，也不阻止本地已收到流 |
| 旧 R104 配置迁移 | RX 语义、发射许可、私呼任意来源回退和精确回音规则逐项一致 |
| v2 旧 run、重复 request_id、revision 冲突或部分非法策略 | 丢弃命令且不部分应用；v1 Q/EOF 行为不变 |

以上矩阵中后续集成项仍需独立测试。模型覆盖项的实际离线编译结果将在下一节记录。任何 BM 动态控制能力、真实设备播放、PTT、RF 和 HIL 结论都需要独立证据。

## 当前实现切片和验证记录

本轮在不修改现有 build/test 注册表和运行链的前提下，新增三个文件：

- `include/wirex/talkgroup_routing.hpp`：纯内存策略、候选、RX/TX owner、generation 和 lease 类型。
- `src/talkgroup_routing.cpp`：Selected/AllDelivered、slot 级 group block、跨路由 source block、private peer/local destination 校验、原子 revision 更新、单流仲裁、外部 RX stop 确认、TX target 冻结、权限撤销和显式 Quick call gate。
- `tests/talkgroup_routing_test.cpp`：独立可执行测试，覆盖上述策略和状态转换。

Router 按单线程事件循环使用，revision 用于 CAS 拒绝旧更新，不提供线程安全。候选由调用方持有，Router 不保存候选缓存。`admit_rx(call, call_start)` 只允许已验证的新通话起始帧或当前 stream 的后续帧；旧 stream 停止后，迟到的非起始帧不会重新取得 owner。RX 取消与自然 EOT 都保持 `rx_stopping` 直到外层确认 PCM/WinMM 与 HRI T0 清理；清理失败进入 fault 并继续阻止 RX/PTT。关闭 TX permission 时返回活动 lease ID，要求外层停止采集 PCM 并完成 EOT；普通 TX target 更新只影响后续租约。内建门拒绝 TG91/TG46001 group PTT 和动态 Quick call，即使调用方 deny list 为空。
