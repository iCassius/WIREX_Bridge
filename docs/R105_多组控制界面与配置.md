# R105：多组与单呼控制界面和配置提案

状态：2026-10-27，UI/配置提案与离线原型。字段和动作仍需根会话完成架构冻结；本文不表示 UI、Native、IPC、BrandMeister API 或动态订阅已经实现。

## 范围与已有证据

本设计把 BrandMeister 远端订阅、本机接收策略、已收到的通话来源和发射目标分开显示。它服务于两种组呼接收模式、多组本机监听、单呼联系人选择，以及有明确提示的静态/动态订阅管理。

当前运行界面是 WPF：[`ui/windows/bridge-ui.ps1`](../ui/windows/bridge-ui.ps1) 与 [`ui/windows/BridgeSupervisor.cs`](../ui/windows/BridgeSupervisor.cs) 管理桌面与核心生命周期；Native [`include/wirex/ui_control_protocol.hpp`](../include/wirex/ui_control_protocol.hpp) 的停止输入只接受 `Q` 行或 EOF。用户配置仍是一组三元组 `receive.destination_id/slot/call_kind`，UI 只传递该组参数。Native BM pipeline 有主、次两个接收过滤器，见 [`include/wirex/bm_voice_pipeline.hpp`](../include/wirex/bm_voice_pipeline.hpp) 和 [`src/bm_voice_pipeline.cpp`](../src/bm_voice_pipeline.cpp)。这些现有部分尚无 R105 多组策略、BM 订阅 API 或 Quick call 加入命令；历史 Python `ui/core_protocol.py` 是离线 UI 契约实验，不是当前运行版协议。

以下是供 R105 根会话冻结的 UI 与配置草案。所有状态都必须来自当前 Native run 的明确快照或事件；静态 API 读回、动态加入请求和音频播放结果由不同字段表达。

## 术语与分开维护的状态

| 名称 | 代表什么 | 不能据此推断什么 |
| --- | --- | --- |
| BM 订阅来源 | 静态、动态或来源未知，描述订阅如何建立 | 不能推断本机正在播放这个组 |
| BM 远端状态 | API 读回、核心观察或远端确认提供的 active、requested、expired、failed、unknown 等状态 | 本地按钮的点击不能把它改成 active |
| 本地监听策略 | 当前运行允许哪些 BM 已送达的有效呼叫进入本机播放仲裁 | 停止本地监听不会向 BM 删除订阅 |
| 已观察通道 | 从合法 DMRD 头部发现的 `(TG, slot)` 组呼，或远端 `source_id` 标识的私呼 peer | 不能推断 BM 订阅属于静态还是动态 |
| 当前发话人 | 本通话 `source_id`，以及数据源实际提供的呼号（若有） | 数字 ID 不可显示成推测的呼号 |
| 发射目标与 lease | 下一次发射请求使用的目标，和当前已开始发射 lease 固定的目标 | 修改下一目标不会改写正在进行的 lease |

组呼通道按 `(destination_id=TG, slot, kind=group)` 形成卡片。私呼通道按远端 peer `source_id`、本机目的 ID 和时隙形成卡片。组呼目标与当前发话人的 `source_id` 是两个不同字段：组卡控制 TG/TS 监听，发话人动作按 `source_id` 屏蔽所有接收路由，不按当前 TG/TS 限定。

## 单页控制台

### 顶栏与状态条

- 持续显示 `模拟预览 / 本页固定示例数据 / 无 BM、设备或本机配置访问`。真实界面分别报告核心、BM 会话和 BM API 读取状态，不从保存的地址、已登录信息或按钮外观推断在线。
- 当前来话区固定显示通话目的、TS、来源 ID、呼号字段来源和通话持续时间。没有呼号数据时显示“呼号未知/未提供”；示例也使用明确的数字 ID 与“呼号未知”。
- 展示本次运行的 RX mode、RX policy revision、TX 目标版本，以及当前 active TX lease。活动通话中的 TG/slot/source 和活动 TX lease 的目标在通话/lease 期间按核心快照冻结。

### BM 订阅和本地监听区

列表每行分别呈现：频道键、BM 来源（静态/动态/未知）、远端证据状态、过期时间（如有）、本地监听结果，以及与远端操作有关的独立动作。未知订阅来源仍可显示已观察到的通道卡，卡片提供本地收听控制；未知来源不被补写为静态或动态。

两种 RX mode 的效果只对合法且实际送达的 BM DMRD 组呼成立：

- **Selected（选中通道）**：只收听 `allow_groups` 中的 `(TG, slot)`。旧单目标配置迁移为 Selected，并只把旧接收目标加入列表。
- **AllDelivered（BM 已送达）**：收听 BM 已送达且通过组呼校验的组呼，再应用按 `(TG, slot, kind=group)` 记录的本机频道屏蔽。发现新 TG 会生成候选卡，但不会清除既有屏蔽，也不会改 TX 目标。

私呼另设 `private_mode`：`disabled`、`selected_peers` 或 `all_peers_to_local`。peer allow 项按远端 `source_id`、本机 destination ID 和 slot 组成；目的地址必须是本机 ID。私呼 peer 列表提供“本地私呼监听”按钮，和同一行的“设为 TX 私呼”按钮分别控制。peer source 屏蔽继续经 `blocked_source_ids` 对所有 RX 路由生效。

频道卡上的收听切换按当前模式写入本地策略。Selected 模式的“停止本地收听”移除该 `(TG, TS)` 的 allow 项；AllDelivered 模式的“停止本地收听/排除此通道”只屏蔽该 `(TG, TS, kind=group)`，不屏蔽同 TG 的另一个时隙。存在屏蔽项时，“收听”动作要原子解除对应频道屏蔽并恢复相应 allow（Selected 模式），或只解除频道屏蔽（AllDelivered 模式）。频道屏蔽优先于 allow；校验应拒绝重复或冲突值。`blocked_source_ids` 则按 speaker ID 跨所有接收路由生效。

频道卡还提供一个独立的“设为发射”小动作。它只提交 TX 目标切换，不改变 RX mode、本地监听集合、BM 订阅或 speaker block。当前 PTT lease 按开始时的 TX 目标固定；松开按键且核心完成 EOT/lease 收尾后，核心确认的新 TX 目标用于下一次 lease。请求已接受时继续显示“等待目标更新”，不提前把它画成已生效。

### 单流音频与来话身份

- 多组监听表示多种来源可以通过本地策略；FTX-1 扬声器同一时刻只输出一条 stream。仲裁器必须选择一路播放，其他同时到达的语音帧直接丢弃；不得混音、排队或在占用结束后重播旧帧。
- 当前通话卡单独列出 `source_id`，以及 Native 确认的呼号（无数据时为未知）。按钮“本地屏蔽此发话源”只写 `blocked_source_ids`；该 speaker ID 的后续来话在所有 TG/TS 路由都受屏蔽。此动作不屏蔽整个 TG，也不删除 BM 订阅。
- 如果用户在活动 RX 通话中停止该组、关闭私呼监听或屏蔽该发话源，核心应立即停止本地后续播放并丢弃该 stream 的剩余帧；通话头中冻结的目标与来源仍用于显示这通已观察到的来话，媒体状态从 playing 切为 stopped/filtered。UI 不保留排队数据。恢复 allow 不续播同一 generation；下一通 call start 才能取得播放资格。
- 同一 TS 上本机停止收听 TG91，不会要求 BrandMeister 立刻改送另一 TG。Master 可能仍将该 TS 分配给 TG91；UI 需显示这一转发限制，不能承诺切换监听就会收到另一组。

### TX 组呼和私呼快捷切换

- TX 区提供常用组呼 TG 与私呼联系人快捷键。联系人显示 DMR ID 和可核实的用户备注；只有有来源的 callsign mapping 才能标为呼号。
- 选中卡片只发出 `tx_target` 更新请求，显示 request ID 和待确认状态。PTT 未按下时，核心确认后下一次 lease 使用该目标。PTT 已按下或 EOT 尚待确认时，选择器仍允许更改下一通待用目标；UI 同时显示“当前 lease 仍用旧目标”和“下一目标等待”。活动 lease 的所有语音与 EOT 保持原目标。EOT 正常完成并释放 lease 后，最新已确认的下一目标才用于下次 PTT。
- 只收策略中的 TG91 和 TG46001 要在每个行内 TX 动作、快捷入口和核心目标更新校验处都拒绝发射目标变更。
- 连续快速选择时，UI 保留每个请求结果并按 target revision 显示最后的已确认值；旧请求的晚到结果不得覆盖较新的目标版本。接收忙造成半双工阻塞时，核心单独报告 PTT 不可用；不能靠暂时锁死 TX 选择器掩盖媒体 owner 状态。
- RX 监听按钮和 TX 目标快捷键互不联动；不因监听某个 TG 自动发射该 TG，也不因更换 TX 目标改变 RX。

### 动态和静态订阅管理

- 静态订阅由 BM 静态订阅 API 读取/更新。界面明确显示 API 读取时间与结果，并提供“读取并预览差异”。差异预览分别列远端现有项、将添加项和将移除项；只有用户再点独立的“应用静态变更”才写入 BM。API Key 与 BM 热点设备密码分开管理，页面不回显秘密。
- 静态删除需单独使用“解除 BM 静态订阅”动作；本地停止监听不能复用该动作。若静态列表 API 能力或 API Key 不可用，界面显示不可用原因，不伪造列表。
- 动态加入通过 SharkRF Quick call 发出一次短 DMR 组呼，这是实际网络呼叫。第一次点击后先展示要呼叫的 TG/slot、将发送的加入动作及“会向网络发出组呼”说明；用户明确确认后才提交一次请求。来源发现、本地监听切换、核心启动都不能发起空呼。到期后不得后台自动续期。
- 动态行分别显示“已请求”“BM 远端尚未确认”“远端已确认/已观察”“失败/已到期”和“本机允许/屏蔽”。Quick call 请求返回 accepted 只表示核心接收了请求。只有核心的 BM 观察或明确远端结果可以推进远端状态；本机 allow 始终单独保存。
- “清除动态订阅”仅对动态条目显示，和“停止本地监听”分开。TG91 与 TG46001 的只收策略禁止 Quick call 动态加入，相关按钮禁用并给出说明。

## 配置和候选核心契约

以下字段名称来自 UI/core 讨论草案，必须由根会话冻结后再实施，不是现存 JSON schema：

```json
{
  "rx_policy": {
    "group_mode": "Selected",
    "private_mode": "selected_peers",
    "allow_groups": [{ "destination_id": 91, "slot": 2, "call_kind": "group" }],
    "allow_private_peers": [{ "source_id": 800001, "destination_id": 4611355, "slot": 2, "call_kind": "private" }],
    "blocked_groups": [{ "destination_id": 46000, "slot": 1, "call_kind": "group" }],
    "blocked_source_ids": []
  },
  "tx_target": { "destination_id": 460997, "kind": "private", "slot": 2 },
  "tx_target_revision": 1,
  "rx_policy_revision": 1,
  "network_subscriptions": [],
  "active_tx_lease": null
}
```

`blocked_groups[]` 的键为 `(destination_id, slot, call_kind=group)`，不可只传 TG ID 以免屏蔽同 TG 的所有时隙。`blocked_source_ids[]` 按 speaker ID 屏蔽所有接收路由。组呼准入使用 `group_mode` 与 `allow_groups[]`；私呼另由 `private_mode` 和 `allow_private_peers[]` 控制，入站私呼目的地址仍必须是本机 ID。候选 `network_subscriptions[]` 使用 `subscription_id`、`kind`（static/dynamic）、目标 TG 和独立的 `bm_subscription_slot`、desired/observed state、request ID、错误和过期时间。没有 API/readback 证据的已观察通道只标“订阅来源未知”，不造出未知的远端订阅记录。静态 API 原始读回快照另带来源和读取时间。动态 Quick call 记录“本机请求”与“BM 远端观察”两条状态；不能用请求成功代替 BM active。

提案命令包括 `rx_policy.replace`、`tx_target.replace`、`network_subscription.static_readback`、`network_subscription.static_set` 和 `network_subscription.quick_call_join`。每个状态变更有 request ID 和 policy/target revision。多次提交需要 CAS 或等效防乱序规则；按 `run_id` 与递增 `seq` 校验快照，停止/断开后马上将旧快照标为 stale。`network_subscription.quick_call_join` 会立即开始一次真实 TX；只在能力、TX 权限、媒体 owner、只收策略及用户确认都允许时调用，不排队稍后执行。

旧配置迁移必须保留 alpha.4 的逐类语义：旧 `receive` 为组呼时迁移为一个 Selected `GroupRoute(TG, slot)`；旧配置为私呼时保留 alpha.4 的“发往本机目的 ID、同 slot 的任意私呼 peer”收听规则，不能把本机目的 ID 当成远端 peer/source ID。未配置 receive 时按核心架构契约沿用原有回退规则。迁移不添加 BM 静态/动态订阅、不写远端状态，也不更改 TX；用户可之后保存更多 allow 通道、屏蔽组、私呼 peer 与联系人备注。

## 离线原型

[R105 离线 UI 原型源码](../ui/prototypes/r105-multi-route/index.html) 和 [本地评审副本](../build/_work/R105-ui-prototype/index.html) 使用固定模拟列表，全部样式与脚本内嵌。它们不请求网络，不读写本机用户配置、API Key 或浏览器存储；按钮只在当前页面演示本地监听、来源屏蔽、TX 下一目标、远端动作确认提示和静态 API 差异预览。远端 BM 写入或 Quick call 均不会执行。

原型交互回归脚本 [test_interactions.cjs](../ui/prototypes/r105-multi-route/test_interactions.cjs) 覆盖 Selected 多选、AllDelivered 排除、保留旧 block、新 TG 候选、同一 TG 的不同 speaker、speaker 全路由屏蔽、本地监听不改 BM 读回、停止 RX 后立即停播并保持 `rx_stopping`/owner busy、模拟 HRI T0 清理确认后才释放 owner、清理期间拒绝 PTT 且不回放旧流、私呼 RX/TX 分离、只收 TG91 的行内 TX/Quick call/目标更改防绕过、PTT active lease 目标冻结、忙时调整下一目标、release/EOT 保持租约和新目标在下一次 PTT 生效、Quick call 确认提示及静态差异只读预览。脚本使用已有 Playwright 与 Chrome 打开本地 `file://` 文档，不启 HTTP 服务；截图和 JSON 结果写入被忽略的 `build/_work/R105-ui-prototype`。这些验证只证明页面内模拟交互，不能证明 WPF、Native、BM API、真实 TX、音频或设备行为。

原型中的 BM、speaker ID、来话、动态状态和 API 差异都是虚构演示数据。模拟预览不证明 Qt、Native、BM API、Quick call、串口、音频、PTT 或 RF 行为。
