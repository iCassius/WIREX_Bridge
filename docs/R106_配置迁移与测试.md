# R106 配置迁移与测试

状态：2026-10-27，适用于 WIREX Bridge v0.1.0-alpha.5 第1步。配置层可以把旧 profile 映射为 schema 2；Native 核心仍只执行旧版单路接收路由。本文说明迁移、保存、启动检查和离线验证，不表示多路接收已经运行。

## 配置目录与文件

通用 alpha.5 包不含个人配置。第1步测试入口 `start-step1-test.cmd` 使用独立目录 `private/r106-step1-test-config`，本身不会查找、复制或覆盖 alpha.4 目录及个人配置。本机交付流程完成 manifest 审计后，可按白名单将 `connection-profile.json`、`audio-settings.json` 和 `password-file-path.txt` 三个配置文件复制到该隔离目录；不得复制实际密码文件。交付流程创建测试副本，个人原文件保持不变。

目录中的连接 profile 文件名为 `connection-profile.json`，音量设置为 `audio-settings.json`，密码路径指针为 `password-file-path.txt`。测试入口只决定配置目录；profile 的加载和保存由 WPF 设置页触发。读取 profile 不会把 schema 1 自动改写成 schema 2。

## Schema 1 到 Schema 2 的内存迁移

Schema 1 顶层必须有 `schema_version`、`connection`、`devices`；`receive` 和 `transmit_enabled` 可省略。对象不能含未知字段、重复 JSON 键或错误类型。文件最大 64 KiB。旧版字段结构如下：

```json
{
  "schema_version": 1,
  "connection": {
    "callsign": "N0CALL",
    "gateway_id": 460999901,
    "source_id": 4609999,
    "master": "example.invalid",
    "master_port": 62031,
    "destination_id": 91,
    "slot": 2,
    "color_code": 1,
    "call_kind": "group"
  },
  "devices": {
    "serial_port": "COM5",
    "wave_in_endpoint_id": "<设备端点 ID>",
    "wave_out_endpoint_id": "<设备端点 ID>"
  },
  "receive": { "destination_id": 91, "slot": 2, "call_kind": "group" },
  "transmit_enabled": false
}
```

上例只用于展示结构。`master`、设备端点和 ID 必须替换成用户配置中的值；不要把凭据或密码放进 profile。

读取时，程序验证旧对象并在内存中产生 schema 2 视图，保留连接身份、设备选择、TX 目标、RX 目标和发射许可。`transmit_enabled` 缺省时按 `true` 处理；`receive` 缺省时，组呼沿用 TX 目标与时隙作为 Selected 接收，私呼改为接收发往本机 `connection.source_id` 的私呼，并沿用 TX 时隙。旧私呼 TX 在发射许可开启时，迁移结果还会保留其准确回程 peer。

显式 `receive.call_kind="private"` 时，`receive.destination_id` 必须等于本机 `connection.source_id`。旧文件把本机私呼接收目标设成其他 ID 时，读取会拒绝迁移；程序不会替用户改写目标，也不会修改原文件。遇到此错误，应在测试副本上修正旧配置后再打开设置。

迁移后的对象带有 `migration_source_schema_version=1`，供 UI 说明“迁移预览”。只读打开时原文件字节保持不变。用户点击保存后才写入 schema 2，并保留原 profile 的 `.bak-<UTC时间>-<随机标识>` 备份。

## Schema 2 字段

Schema 2 顶层恰好包含 `schema_version`、`connection`、`tx_target`、`devices`、`rx_policy` 和 `transmit_enabled`。字段必须完整，不能含未知字段或重复键。整数必须以 JSON 整数表示；字符串中的数字不作为 JSON 数值接受。

| 对象 | 必需字段 | 含义 |
|---|---|---|
| `connection` | `callsign`, `gateway_id`, `source_id`, `master`, `master_port`, `color_code` | 呼号、网关号、本机 ID、服务器、端口和色码 |
| `tx_target` | `destination_id`, `kind`, `slot` | 发射目标、`group`/`private` 类型和时隙 |
| `devices` | `serial_port`, `wave_in_endpoint_id`, `wave_out_endpoint_id` | 串口及输入、输出端点的稳定选择值 |
| `rx_policy` | `group_mode`, `private_mode`, `allow_groups`, `allow_private_peers`, `local_private_routes`, `blocked_groups`, `blocked_source_ids` | 完整接收策略 |

`group_mode` 可为 `selected` 或 `all_delivered`；`private_mode` 可为 `disabled`、`selected_peers` 或 `all_peers_to_local`。`allow_groups` 与 `blocked_groups` 中每项恰好有 `destination_id` 和 `slot`；`allow_private_peers` 每项恰好有 `source_id`、`local_destination_id` 和 `slot`；`local_private_routes` 每项恰好有 `local_destination_id` 和 `slot`。`blocked_source_ids` 是 ID 数组。列表不接受重复路由；同一组呼不能同时出现在 allow 和 block 中。所有本机私呼目标都必须等于 `connection.source_id`。

主要取值范围：呼号为 1–8 个可打印 ASCII 字符；服务器为有效 IPv4 或语法正确的 ASCII 主机名；网关号为 1–4294967295，本机 ID、组呼和 peer ID 为 1–16777215；端口为 1–65535；色码为 0–15；时隙为 1 或 2。串口为 `auto` 或 `COM1`–`COM999`；音频端点必须是非空字符串，最多 4096 个字符。`transmit_enabled` 必须是 JSON 布尔值。

## 保存、备份与失败处理

连接 profile 保存前会再次完整校验。程序先在目标旁写 UTF-8（无 BOM）临时文件，再用文件替换完成原子更新；已有 profile 的原字节写入独立 `.bak-...` 文件。写入目标不存在时，临时文件通过同目录移动成为新文件。临时文件在成功或异常后清理。

设置页一次保存还会暂存连接 profile、音量和密码路径指针，以便多文件写入失败时恢复保存前状态。事务成功后，这些临时 `.ui-backup-...` 文件会删除；失败时尝试回滚，若回滚也失败，界面会提示重新打开设置核对。连接 profile 的正式 `.bak-...` 备份不会作为临时事务文件删除。

若 schema 2 中包含当前表单不能编辑的接收项，设置页会以只读摘要展示完整策略。保存音量或密码路径时，profile 不会重写；连接策略仍按原内容保留。UI 的单路由预设也不会覆盖只读策略。

## 旧运行核心的启动资格

alpha.5 第1步把 profile 投影到旧核心单路接收参数前，必须确认接收策略可以完整表达。无法完整表达时，启动准备阶段会报错并在启动 Native 核心之前停止；schema 2 文件仍可读取、预览和保存，程序不截断列表或忽略 block 规则。

旧核心只接受一个主接收路由：一个 `selected` 组呼，或一个发往本机 Source ID 的私呼路由。`all_delivered`、多个组呼、多个本机私呼路由、组呼与私呼主路由并存、组呼或发话源屏蔽规则都不能由旧核心执行，因此不能启动。

开启发射的私呼 TX 需要有被策略明确允许的精确回程：peer 的来源 ID 必须等于 TX 目标、本机目标必须等于 `connection.source_id`、时隙必须等于 TX 时隙；或者现有 `all_peers_to_local` 主路由已覆盖同一 TX 目标和时隙。多 peer、与当前 TX 不匹配的 peer、关闭发射后仍要求 selected peer 接收等情况都不能投影。校验通过只说明参数可以完整转换，不说明串口、音频、BM 或电台已经连接。

## 离线测试步骤

在仓库根目录执行。配置和启动资格检查不访问设备或网络：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\tools\test-start-user-config.ps1
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\tools\test-ui-targets.ps1
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\tools\test-ui-preparation.ps1
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\tools\test-ui-supervisor.ps1
```

WPF 渲染测试通过包目录里的 Native 文件满足启动器的包结构检查，但使用 `-OfflinePreview -RenderOnly`，不启动核心、不枚举设备，也不连接网络。结果目录会保留主窗口、设置窗口、模拟活动来话窗口截图和 `layout-info.json`：

```powershell
$package = 'C:\path\to\alpha5-package'
$render = 'C:\path\to\render-output'
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\tools\test-ui-render.ps1 `
    -PackageDirectory $package -RenderOutputDirectory $render
```

需要验证 WPF supervisor 与真实 Native 控制管道时，必须显式指定待测 `wirex_bridge.exe`；测试只以以下参数启动它：`--control-diagnostic --ui-pipe --ui-control-version 2`。测试执行 `control_ready`、`hello`、`status`、重放、拒绝/无效 ACK 校验、`shutdown` 和退出码检查，不会加载 profile、打开 COM 或音频、连接 BM 或其他网络：

```powershell
$native = 'C:\path\to\wirex_bridge.exe'
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\tools\test-ui-control-v2.ps1 `
    -NativeExecutable $native
```

UI 控制记录使用独立 `control_seq`，状态查询结果不会写入或刷新 media/status 状态。控制状态显示为“已确认”只表示 Native 接受了 IPC v2 握手；设备与网络状态仍从媒体状态记录显示。

Native 协议帧边界、缓存、去重和 EOF 规则见 [`R106_IPC第二版.md`](R106_IPC第二版.md)。第1步的用户交接表见 [`releases/v0.1.0-alpha.5-step1-handoff.md`](releases/v0.1.0-alpha.5-step1-handoff.md)。
