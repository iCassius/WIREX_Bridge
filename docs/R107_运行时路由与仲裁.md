# R107 运行时路由与仲裁

**状态日期：2026-10-27**

**阶段：Stage 2 核心路由与离线生命周期验证**

**代码基点：`main` / `510287c`；本轮工作树修改尚未提交。**

本文说明多路由策略如何进入现有 BM 语音管线、半双工 owner 如何保持到实际媒体清理完成，以及当前离线证据覆盖到哪里。Stage 2 不包含 UI/IPC 策略编辑，也没有进行 BM 网络、HRI 设备、音频设备或 RF/HIL 验收。

## 运行时边界

`talkgroup_routing::Router` 保存 RX/TX 策略、revision、RX generation、TX lease 和半双工媒体 owner。`BmVoicePipeline` 是策略路由与实际 DMRD/LC/codec/playback/TX 管线之间的适配层。外层仍负责 HRI、BM session、WinMM 和设备事件；外层必须将真实清理结果回报给管线，不能把停止请求当作清理完成。

管线的主要入口和确认点如下：

| API | 作用 |
|---|---|
| `enable_routing(local_source_id, rx_policy, tx_policy)` | 创建并启用路由器，安装初始策略。 |
| `replace_rx_policy(expected_revision, policy)` / `replace_tx_policy(...)` | 用 revision 检查并替换策略；撤销当前 TX 权限时会请求停止活动 lease。 |
| `routing_snapshot()` | 读取 router 状态和活动/停止中的 router generation ↔ pipeline generation 映射。 |
| `begin_routed_tx(identity_template, readiness, now)` | 检查 BM/HRI readiness 和本地身份后申请 TX lease；lease 的目标覆盖模板中的目标字段。 |
| `observe_routed_ptt_release()` | 报告真实 PTT 已松开，单独解除 TX release latch。 |
| `complete_routed_rx_cleanup(pipeline_generation, ok)` | 外层报告对应 RX generation 的 WinMM/HRI 清理结果。 |
| `complete_routed_tx_eot(lease_id, sent)` | 报告 terminator/EOT 实际发送结果。 |
| `complete_routed_tx_cleanup(lease_id, ok)` | 外层报告 TX 麦克风采集与 WinMM capture 清理结果。 |

这些 API 在单线程事件循环中调用。revision 用于拒绝过期策略更新；generation 和 lease ID 用于拒绝迟到或重复的 ACK。

## 接收路由与媒体 owner

1. DMRD 外层头、voice sync 或不完整的 embedded LC 只形成候选观察。voice sync A late entry 在 LC 验证前不会分配媒体 owner、启动播放或把语音喂给活动 Receiver。
2. 真实 DMRD/LC 解码确认 call identity 后，Router 按 group/private/source policy 进行匹配。通过策略且半双工 owner 空闲时，Router 和 pipeline 分别分配 generation，快照保留二者映射。
3. 只有准入后的流进入 codec 和播放队列。第二个 stream 抢占时被丢弃，不会改变当前 Receiver 的 call identity 或播放内容。
4. 自然收到 terminator 时，pipeline 进入 `rx_draining`，继续排空尾音并等待 playback ACK；播放队列排空后才进入 `rx_stopping`。策略撤销、主动取消或启动超时会立即清空待播队列并进入 `rx_stopping`，不等待自然排尾音。
5. `rx_stopping` 时活动媒体状态已结束，但 owner 仍被占用，映射保存在 `stopping_rx_mapping`。外层完成 WinMM/HRI 播放清理后调用 `complete_routed_rx_cleanup`。成功 ACK 才释放 owner；失败 ACK 保持故障/占用，允许外层清理重试。旧 generation 的 playback ACK 或 cleanup ACK 不会释放新 owner。

若准入后 HRI 尚未报告 playback ready，3 秒启动期限由 `playback_ready` 或后续收到的 routed packet 检查。即使外层没有及时调用 `tick`，期限后到达的包也会触发超时并进入 stopping；不能恢复该次播放，仍需完成外层 cleanup ACK。

被取消的 stream 会进入 retired-stream guard。同一 stream 的后续包只会被丢弃，并把该 stream 的静默到期时间向后延长 2 秒；只有连续静默超过 2 秒后，新的 call-start 才可重新申请 owner。因而持续到达的旧语音不能在 cleanup 后重新开启同一通话。

## 策略语义

- `GroupMode::selected` 只接受 `allowed_groups` 中匹配的 destination/slot；`GroupMode::all_delivered` 接受本地已收到的其他 group call。两种模式下 `blocked_groups` 和 `blocked_source_ids` 都优先拒绝匹配项。
- `PrivateMode::all_peers_to_local` 接受 `local_private_routes` 覆盖的本地目标/时隙，或 `private_peers` 中精确匹配的对端/本地目标/时隙；两张表按并集生效。
- `PrivateMode::selected_peers` 使用 `private_peers`，`local_private_routes` 必须为空。`PrivateMode::disabled` 时两张表必须都为空。与同 route allow 项冲突的 block 项属于无效策略。
- 策略更新通过 expected revision 防止旧 UI/IPC 状态覆盖新策略。当前还没有把多策略编辑接入正式 IPC 或 WPF 控件。

## TX lease 与停止收尾

`begin_routed_tx` 在 Router 分配 lease 前检查 pipeline idle、BM/HRI readiness、模板的 `source_id` 是否等于本地 ID，以及 color code 是否不大于 15。目标地址、呼叫类型和 timeslot 取自当前 TX policy 并写入 lease；模板里旧的目标字段不会绕过策略。已经开始的 lease 冻结其目标，后续改策略只影响下一次 TX。

主动停止或撤销 TX 权限会清除未发送音频并请求 terminator。`request_tx_stop` 不会伪造 PTT 松开；物理松手必须通过 `observe_routed_ptt_release` 单独观察。EOT 成功后 Router 进入 draining，仍持有 lease 和 owner，直到本地 TX 麦克风采集/WinMM capture 清理成功。EOT 发送失败会保持 fault/busy，即使外层报告本地 capture cleanup 已完成，也不能再分配 lease，直至 pipeline 重建。因此，BM 发送结果、采集侧 WinMM 清理和物理 PTT 松手分别确认。

新增 `talkgroup_routing_test` 和 `bm_routing_lifecycle_test`，在原有 36 项之后追加，CMake 与 `tools/build-bm-bridge.ps1` 均登记为 38 项并保持旧测试顺序。生命周期集成测试使用实际 codec、合成 DMRD 流、内存 PCM 和 fake playback/HRI/BM ACK；没有真实设备或网络。

当前定向证据：

- `talkgroup_routing_test`：通过，覆盖 Router 策略校验、block 优先级、RX/TX owner/lease、EOT 与 cleanup 分离、PTT release latch。
- `bm_routing_lifecycle_test`：最新 pipeline 与集成测试源重编、重链后通过。覆盖 voice sync A late entry、embedded LC 验证前无播放、竞争 stream、source 权限撤销、generation 映射与迟到 ACK、同 stream 持续包延长 retired 时间、静默超过 2 秒后重新准入、无 tick 的 3 秒 playback-start timeout、目标冻结/下一目标、权限撤销停止、EOT/cleanup/fault 和 Gate ready/busy 分离。
- `tools/test-ui-status.ps1`：通过。状态记录接受 `receive_media_state=stopping`，该状态不会被归为活动来话。
- `tools/build-bm-bridge.ps1 -CompileOnly`：在本轮早期编译对象成功。后续 pipeline/integration 定向重编也成功；lifecycle 最后追加两项 probe 状态修复后，使用 VS 2019 x64 工具对最新 `src/probe_main.cpp` 单文件重编，退出码 0。
- CMake 当前登记 38 个测试；最终干净目录的 38 项全量构建与执行尚待 root 在所有源文件冻结后完成。

这些结果是离线源代码/合成流证据，不覆盖 HRI 实机确认、BM 服务端读回、真实麦克风/扬声器、PTT 电气状态、RF 或用户现场行为。
