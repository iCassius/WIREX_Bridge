# R111 主界面与音量说明

## 主界面

- A 区显示本机当前收听目标、当前来话、最近来话和最多 50 条历史。历史按运行标识与接收代次去重，并保留来源 ID、组号或私呼目标、TS 和时间。
- B 区显示下一起呼目标、活动通话锁定目标、本机已配置组和频道收藏。选择起呼目标只更新 TX 策略；收到核心 ACK 后显示新的下一起呼目标。它不会开始呼叫，也不会改动 A 区的接收规则或发射许可；活动通话继续使用已锁定的目标。
- 如果要听某个组，请在主窗口底部“TG / TS 快速操作”栏中点“加入本机收听”，再选择相同 TG 与 TS。B 区收藏或起呼目标不会自动加入本机收听。
- 来话历史需点“设为呼叫目标”才会更新起呼目标。私呼使用历史来源 ID 作为回呼目标；组呼使用历史目标组号，并沿用记录中的 TS。
- 本机收藏文件为用户配置目录中的 `channel-favorites.json`，最多 64 项，以目标 ID、呼叫类型和 TS 区分。普通、动态、静态分类由用户维护；本版不会创建或修改 BM 订阅，也未读取服务器绑定列表。BM 连接与来话状态按核心实际报告显示。收藏文件缺失时保持不创建；保存或删除先写入文件，成功后再更新界面。
- “激活动态组”会发送现有 QuickCall 请求，界面显示本机请求已发送或核心返回的实际结果；其他终端是否看到该组仍未知。
- 每条 TG 或私呼路由保留自己的 TS。高级设置中的 Color Code 是 DMR 全局发射编码（0–15）；本机接收规则不使用它筛选来话，也不将它作为 FTX-1 C4FM DG-ID。

## 呼号资料

- 当前来话或所选历史项提供“查询资料”按钮。查询只按用户明确选择的一个来源 ID 发出，在后台任务执行；主界面显示缓存命中或 DMR ID 数字回退。查询结果显示可用的呼号、姓名、国家/州省/城市、来源和更新时间；当前话者及历史项目的工具提示提供完整详情。
- 过期缓存显示为旧资料。资料查询结果只更新匹配的历史项目；当前来话正文还要求运行标识、来源 ID、接收代次匹配，并且核心状态仍在运行且足够新。

## 音量与削波

- 主界面音频卡单行显示核心报告的当前播放增益、配置中保存的增益和削波计数；工具提示与设置窗口说明保存值在下次连接时生效。运行中的数字以核心当前报告为准。
- 主界面同时显示核心报告的播放削波样本计数；尚未收到计数时显示未知。已保存的较高增益不会自动套到当前会话，也不保证放大后仍有足够峰值余量。
- 本机最近一次已保存的播放增益为 5.959x；对应最近一次运行报告显示 1x，说明该设置尚未进入那次运行，需断开后重新连接才会应用。该运行有 0 个削波样本。现有日志没有提供对端输出音量或本机扬声器的 PCM 声学测量，因此无法据此确定听感偏小的完整原因。

## 当前验证状态

UI 目标与身份查询生命周期定向测试已在 Windows PowerShell 5.1 和 PowerShell 7 通过。覆盖了运行时目标只修改 TX 策略、RX/发射许可与活动通话锁定目标保持原样、收藏首增与末项删除、历史目标方向和 TS、历史去重，以及资料查询的取消/迟到结果保护。另有路由操作、状态与生命周期测试通过；RenderOnly 检查确认音频卡在 1024×728 使用一行文字显示运行值、保存值与削波计数，并在工具提示保留完整的下次连接说明。

隔离路由诊断测试通过 WPF 按钮、Supervisor 与 native diagnostic 进程核对 RX/TX 设置链和 QuickCall 两帧内存接收结果。测试没有连接 BM，也没有连接真实电台或音频设备；RenderOnly 单独运行时没有启动 native 进程。

RenderOnly 布局测试在 Windows PowerShell 5.1 通过，分别渲染 1280×900 与 1024×728。测试使用隔离配置和合成来话、合成收藏；复制已有 alpha8 文件到临时目录作为启动布局所需的包文件输入，没有启动核心或连接设备、BM、音频或网络。主面板 A/B、历史与收藏可见；1024×728 的底部 TG/TS 快捷操作通过面板滚动到达，展开“收听路由、来源管理与运行详情”后，最后的来源屏蔽操作也在可视范围内。布局报告同时检查了控件边界与非黑色渲染帧。
