## 用户明确反馈与产品约束

- alpha.8 的 TG91 收听听感正常但略小。对应运行记录的有效 RX gain 是 1.000x、clipped samples 为 0；保存的 5.959x 不能当作那次实际播放增益。用户同意保留此前 LED 观察，R111 不改机身 BUSY/TX LED 或串口写入行为。
- A“加入本机收听”与 B“起呼目标”互相独立。最近 50 条历史必须来自真实通话记录；目标列表对预设、已保存规则、动态输入、历史项和频道收藏标出真实来源，不能用空白或推测条目补齐。
- TS 按软件路由与目标分别保存。当前 `bm_session.Profile.slot_flags` 默认值及网络 metadata 均为 `4`（simplex）；UI 的 TS1/TS2 字段用于选择网络路由/目标，不能据此说 FTX-1 提供 DMR 双时隙 RF，也不承诺同时播放两个时隙。Color Code 是高级 DMR 发射编码/上报参数，不是 C4FM DG-ID；接收路由不按 CC 过滤。
- Dynamic Quick Call 是无语音 DMR 控制呼叫；公开 openSPOT3 手册与用户观察都表明 BrandMeister Dashboard 会显示 empty call。没有发现官方静默 AddDynamic endpoint/schema，不声称支持该方式。
- 多路由在界面中的排列只影响显示顺序，不设置收听优先级；当前活动来话不会被新流抢断，也不会延后补播。
- 将来若要做自动优先级，可先在短窗口收集已收到的新呼叫、校验候选并用有界原始帧缓存，之后按用户顺序只解码选中的流；这需要设计起播延迟与活动呼叫的停止/恢复规则。本版没有实现这套仲裁，本机也收不到 BM Master 未转发来的语音。
- RadioID 只由用户显式查询单个 DMR ID，缓存仅存当前 canonical `UserConfigDirectory/radio-identity-cache.json`，不进入 Git 或通用包。
- 用户维护的 `channel-favorites.json` 最多 64 项，本机 `normal`/`dynamic`/`static` 分类不等于 BM 服务器静态或动态订阅。文件只在 canonical 配置目录，缺文件时启动仅读取、不自动创建。
- LCD 研究只定位到 10 字节 `Src CallSign` 字段，电台屏幕实际显示仍未知。保留数字 DMR ID 作为呼号未知时的标签，不把它写成真实呼号。
