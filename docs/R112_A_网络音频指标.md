# R112-A 网络与语音基础指标

## 目的与范围

本次只增加传输与接收路径的观测字段，不更改音频增益、PCM 重采样、AMBE 编解码、播放排程或路由行为。指标用于区分网络往返、DMRD 序号缺口、本机队列状态与 PCM 削波；它们不提供 BM 服务器 CPU 或服务器内部排队状态。

## BM 往返时间

`RPTPING` 只有在 UDP `send` 返回成功后才建立 RTT 计时起点；计时使用单调毫秒时钟，不包含 Native 出站队列等待。收到来源地址及 gateway ID 均通过校验的 `MSTPONG` 时，以接收处理时刻减去成功发送时刻计算往返毫秒数。因此该值是客户端测得的往返时间估计，含网络往返和本机收包调度耗时，不能换算成单向延迟，也不能当成服务器 CPU 或性能指标。

BM `RPTPING`/`MSTPONG` 格式没有 nonce。实现同一时刻最多保留一个已成功发送的待测 ping，等待窗口为 10 秒；窗口过期后丢弃该 PONG 的 RTT 样本，但仍用有效 PONG 更新 BM 活性状态，下一周期继续发起探测。断线进入重连时清空本连接的 RTT 汇总。由于协议没有请求编号，如果旧 PONG 恰好在后续 ping 发出后才到达，客户端无法严格分辨它对应哪个 ping；字段因此只作为往返估计展示。

Native JSON 增量字段：

| 字段 | 可用时含义 | 无样本时 |
| --- | --- | --- |
| `bm_rtt_valid` | 是否已有有效样本 | `false` |
| `bm_rtt_last_ms` | 最近样本毫秒 | `null` |
| `bm_rtt_sample_count` | 当前 BM 连接的样本数 | `null` |
| `bm_rtt_min_ms` / `bm_rtt_avg_ms` / `bm_rtt_max_ms` | 当前 BM 连接的最小、平均、最大往返毫秒 | `null` |

界面标签使用“BM 往返”；`valid=false` 时隐藏数值。

## DMRD 序号与丢包估计

接收器对已校验、同一活跃流的 8 位 DMRD 序号作模 256 比较。新流首个被接纳的数据报建立起点，不推断首包之前缺了多少包。后续序号差 `delta` 为 1..127 时视为前进，推断缺包数为 `delta - 1`；差值 0 记作重复包，128..255 记作逆序或无法区分方向的旧包。重复和逆序单独累计，不加进丢包分母。正常 EOT 本身也是一个前进的 DMRD 数据报，会计入接收数和可能的 EOT 前缺口。

`received` 只计序号前进且通过接收过滤、路由准入的 DMRD 数据报；`missing` 是相邻已观察序号之间推断的缺口；`expected = received + missing`；`loss_pct = 100 * missing / expected`。不满足接收过滤、路由拒绝或路由忙碌的包不会进入统计。播放队列溢出等本机接收后的处理问题也不会被伪装成网络丢包。

| 字段 | 含义 |
| --- | --- |
| `rx_call_dmrd_valid` | 是否已有本次/最近一次通话序号观测 |
| `rx_call_dmrd_received` / `rx_call_dmrd_missing` / `rx_call_dmrd_expected` | 本次或最近一次通话的接收、推断缺包和分母 |
| `rx_call_dmrd_loss_pct` | 本次或最近一次通话的推断丢包百分比 |
| `rx_call_dmrd_loss_complete` | 仅收到正常 EOT 时为 `true`；通话进行中、watchdog 结束或被新流替换时为 `false` |
| `rx_session_dmrd_valid` | 当前 Native pipeline 实例是否已有接收序号观测 |
| `rx_session_dmrd_received` / `rx_session_dmrd_missing` / `rx_session_dmrd_expected` / `rx_session_dmrd_loss_pct` | 从 pipeline 实例开始累计的数据报总数和推断丢包比率，跨通话累计 |
| `rx_session_dmrd_duplicate` / `rx_session_dmrd_out_of_order` | session 累计重复和逆序/旧序号数；不进入 loss 分母 |

当 `valid=false` 时，相应数字与百分比输出 JSON `null`，界面应隐藏这些值。call 统计在收到下一通话首包时重置。正常 EOT 使 `loss_complete=true`；watchdog 或新流替换时，最后观察到的数据报之后是否还有包无法确定，所以不补算尾部缺包，保留已观测数值并令 `loss_complete=false`。一次性过滤或忙碌丢弃不产生可用序号观测，因而不会计入网络丢包。

## 当前可用的音频和队列观测

Native 状态继续输出既有 `rx_output_gain_milli`、`rx_audio_samples` 和 `rx_pcm_clipped_samples`。`rx_output_gain_milli=5959` 表示增益为 5.959x。最新记录 `run02544aa132df4e4f93a6169a3b10b331` 停止时记录了增益 5.959x、23,851,566 个 RX 音频样本、21,684 个削波样本，削波占样本约 0.091%。此前记录 `run1486d8ed26694c43bd8cac8d3e115186` 的运行快照同样记录 5.959x，1,362,492 个样本中没有削波。

最新记录说明输出增益后的样本确有削波，可能影响主观音质；总数无法显示削波是否集中在少数爆音或覆盖很多通话，也不能单独证明听感受损。应先把每次播放增益、削波比例与对应通话/时间关联测量，再决定是否调整增益或进入 EQ/AGC 实验。本次没有改 DSP。

新增队列字段复用已有 pipeline 快照：`rx_queue_bursts` 是排队的 60 ms DMR 语音 burst；`rx_queue_playback_frames` 与 `rx_queue_unconfirmed_playback_frames` 是 20 ms、960 个 48 kHz PCM 样本的播放帧数和待确认播放帧数；`rx_buffered_receive_frames` 是 AMBE/codec 20 ms 帧数，按每个收到或缺失补偿 burst 的 3 帧计算。当前没有已实现且可核实的播放 underrun 计数器，所以不导出 underrun 字段。

## 离线验收

源码检查发现独立的 `tools/bm_network_probe.cpp` 只发送 `PacketKind::control`，导致 `Session` 生成的 `PacketKind::keepalive`（`RPTPING`）被丢弃；启动阶段的诊断因此不能继续发心跳。现在探针把 keepalive 作为控制流量发送，启动控制包仍按前缀去重，keepalive 每个周期都可发送。探针只有在 UDP `send` 成功后才调用 `Session::record_outbound_sent`，所以 RTT 起点记录在成功发送之后。该修复只改变探针的发送分类和 RTT 记账，不改 BM 登录配置或语音路径。

本轮只对探针做离线编译检查；没有执行 `--run-network-only`，也没有向 BM 发送数据包。

本次离线覆盖包括 RTT 成功发送时刻、未成功发送、过期 PONG、断线/重连清空；DMRD 8 位回绕、重复、逆序、正常 EOT、watchdog 尾部未知、跨通话累计和过滤包排除。运行命令：

```powershell
pwsh -NoLogo -NoProfile -File .\tools\build-bm-bridge.ps1
```

该命令构建 `wirex_bridge` 和 `wirex_probe` 并运行仓库离线测试。整套测试通过，其中 `bm_bridge_loopback_test` 仅使用本机 localhost fake Master、合成 HRI 与音频 sink；没有连接远端 BM、COM、电台 RF 或真实音频端点。

本次执行时工作树包含开发改动，构建产物只作为开发验证，不作为发布构建。集成后的 clean build 由打包人员从干净源树重新运行并验收。
