# R112-A：来话身份自动查询与查询退出收尾

## 实施范围

本阶段只处理 RadioID 单条 ID 查询、来话与历史资料更新、查询错误隔离和退出收尾。没有修改 Native 音频处理、LCD 串口、BM 连接、发射控制或 RF 路径。

查询入口位于已接受的当前来话记录路径。界面先显示收到的 DMR ID，再异步查询资料；查询不依赖手动查询按钮。已有本机 `found` 或 `not_found` 缓存时直接使用缓存。相同 ID 的活动请求与排队请求会合并调用上下文；队列最多保留 16 个待处理 ID，同一时刻只运行一个请求，两个请求至少间隔 1 秒。HTTP 超时为 5 秒，失败冷却从 30 秒开始并按失败次数递增，最长 15 分钟。

查询只向 RadioID 官方单条查询端点发送指定 ID。请求保留应用标识和联系地址 User-Agent，不批量下载或镜像用户数据库。本轮没有向 RadioID 或 BrandMeister 发起查询。

## 结果与界面行为

- 收到来话时先显示 DMR ID。成功查询后，用呼号更新与结果仍匹配的当前来话和对应历史记录。
- 当前来话更新要求 `run_id`、DMR ID、`current_call_generation` 与最近状态记录一致。历史更新按 `run_id` 与接收代次定位原记录，迟到结果不会覆盖另一通来话。
- 超时、未命中和断网不会清除 DMR ID，也不会在自动查询时显示“查询中”或“查询失败”。如果本机已有旧资料，界面继续显示旧资料和缓存的实际更新时间。
- 身份详情只包含 DMR ID、实际有值的呼号、姓名、地区、来源和更新时间；不输出空字段、未知状态或占位说明。
- 当前来话结束后折叠当前来话行并保留历史。已有历史记录时折叠重复的最近来话卡。手动查询按钮仍保留控件名称和事件，但初始隐藏。
- 自动失败记录到 `Get-BridgeUserConfigDirectory` 返回目录下的 `identity-query-errors.jsonl`。该路径由运行时用户配置目录决定；本轮只使用临时测试目录，没有生成运行时查询日志。记录包含时间、阶段、错误代码、异常类型和清理后的短错误详情，不记录 DMR ID、呼号或完整用户资料。用户主动操作失败时才在界面显示简短错误。

## Runspace 与窗口关闭

每个活动查询持有自己的 MTA runspace 和 PowerShell 管线。Dispatcher 收到完成结果后先收取 `EndInvoke` 或 `EndStop`，释放 PowerShell 管线，再关闭并释放该 runspace。Dispatcher 查询完成入口有顶层异常隔离；后台失败不会直接退出 UI 进程。

选择“停止并退出”或关闭窗口时，先丢弃排队项并停止活动查询。窗口在查询结束、资源释放后关闭。查询收尾超过 8 秒时只记录一次诊断；只有用户已请求退出且核心进程、设备检查均已收尾，才保留最后的强制退出兜底。

## 验证

`tools/test-ui-identity.ps1` 使用真实 WPF Window、Button、Dispatcher 回调和独立后台 runspace，并只连接本机 HTTP 夹具。用例覆盖来话自动查询、按钮点击合并到活动 ID、成功更新、5 秒超时后保留原 ID、取消并关闭独占 runspace、窗口退出收尾和 Dispatcher 异常隔离。以下两条命令均已通过；PowerShell 5.1 命令由主会话独立复跑确认。

```powershell
pwsh -STA -NoLogo -NoProfile -File tools/test-ui-identity.ps1
powershell.exe -NoLogo -NoProfile -STA -ExecutionPolicy Bypass -File tools/test-ui-identity.ps1
```

`tools/test-radio-identity.ps1` 在 PowerShell 7 和 Windows PowerShell 5.1 各通过 37 项离线断言，使用合成响应和 `127.0.0.1` HTTP 夹具。真实 WPF 的 `tools/test-ui-identity.ps1` 在 PowerShell 7 与 Windows PowerShell 5.1 STA 均通过。`tools/test-ui-targets.ps1`、`tools/test-ui-lifecycle.ps1`、`tools/test-ui-status.ps1`、`tools/test-ui-render.ps1` 和 `tools/test-ui-routing-actions.ps1` 均通过 PowerShell 7；主会话独立复跑 `test-ui-status.ps1` 与 `test-ui-targets.ps1` 的 Windows PowerShell 5.1 测试也通过。

这些结果只覆盖离线脚本、WPF Dispatcher 和本机 HTTP 夹具；没有运行真实 RadioID/BM 请求，也没有触碰 COM、电台、音频设备或 PTT。alpha9 的原始异常日志未包含可核对的异常文本，因此本次 WPF 夹具捕获的参数绑定异常和 Context 集合异常只能作为本阶段实现中已复现并修复的问题，不能当作 alpha9 根因的确认。
