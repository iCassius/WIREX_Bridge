# R112-A 集成总交接（alpha10）

## 范围和结果

R112-A 增加来话 DMR ID 的后台 RadioID 查询及退出收尾，报告 BM 客户端往返估计、DMRD 序号缺包、接收队列和既有 PCM 削波数据，并精简主窗口数据行。没有更改 DSP、音频排程或已存在的语音路径。

来话出现后先保留并显示数字 DMR ID，再在后台查询单条 RadioID 资料。单次请求最多等待 5 秒；超时、未命中或查询错误时继续显示数字 ID，查询失败不会停止音频、路由或发射许可。退出时清空查询队列、结束后台管线并释放独占 runspace，使用已有的 8 秒收尾上限。

Native 只报告成功发送 RPTPING 后收到有效 MSTPONG 的客户端往返估计，并按已接受的相邻 DMRD 序号推算缺包。它不把往返估计当作单向时延，也不把被过滤、busy 或 watchdog 之后的数据计作缺包。无有效样本时输出 null，界面收起无数据项；有效的 0% 缺包仍然显示。

主窗口只显示核心上报的实际数据和已经实现的操作。收听来源列表默认收起，有实际条目时才显示；切换来源、block 和 TX 操作保留。界面没有 LCD、FM RF 或 C4FM RF 状态入口。FTX-1 LCD 呼号显示、FM RF 发射和 C4FM RF 发射链尚未实现。Native 没有运行时增益 IPC；音量设置在下次连接时使用。

## HRI 静态分析的最新结果

固定样本 HRI_UART.dll 的 SHA-256 为 56e0050ef6afc53ba9c68ea51c7a13ec263f580b609f81146b897b58ae4effed。本轮在 REA 6.7.0 中对 Ghidra 12.1.4 的 FUN_10014b50 只重试一次；外层约 116 秒收到完整 Evidence。此前 90 秒停止等待是调用方取消，不是 REA 返回的超时。REA 6.7.0 源码将 Ghidra startup 默认绝对时限设为 330 秒，覆盖导入、分析、桥接和 ready 阶段。约 116 秒不能拆分成导入和 decompile 耗时；provider 没有返回内部阶段进度。
