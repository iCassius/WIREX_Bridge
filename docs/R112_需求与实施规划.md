# R112 需求与实施规划

日期：2026-10-29  
调查范围：alpha.9 来话身份查询退出报告、自动呼号查询、音频指标、单页 UI、HRI LCD 与后续 RF 路径。  
本轮只读查看源码、已有非敏感运行日志和 R111 文档；未改代码，未发起 RadioID/BM 网络请求，未运行设备、PTT、音频或 RF 测试。

## 当前身份查询与异常证据

指定源码位于 `app/ui/windows/bridge-ui.ps1` 与 `app/ui/windows/RadioIdentity.psm1`。调查时 app HEAD 为 `2f288e74282b15351e87ab6327a7387c1f9cda49`，Git 工作区干净。

### 已确认

- 当前来话和历史记录默认只从本机 `radio-identity-cache.json` 读取资料。冷缓存时界面保留 `DMR ID <source_id>`；网络查询仍须用户点“查询资料”。`Add-UiCallHistoryRecord` 没有启动网络查询，模块注释也将 `Invoke-RadioIdentityQuery` 标为显式刷新入口。
- 用户点击查询后，UI 在独立 PowerShell runspace 调用 `Invoke-RadioIdentityQuery`，设置 5 秒请求超时。按钮回调会捕获同步错误并显示在查询状态栏；异步收取结果也会捕获异常。RadioIdentity 模块会把传输、响应解析等错误转换为缓存旧资料或 `unavailable` 结果；调用失败时保留数字 DMR ID。
- 本机缓存当前正向 TTL 为 30 天、未命中 TTL 为 1 天，最多保留 128 条。查询返回字段包括呼号、姓名、国家、州/省、城市、来源和更新时间。资料查询不应改动音频、目标选择、RF 路由或 PTT。
- 身份任务有 5.5 秒 UI 截止时间和 8 秒硬清理时间。仅在窗口关闭/停止流程已等待身份 runspace 清理、且身份任务超过 8 秒仍未释放的分支会调用 `Environment.Exit(2)`。普通网络超时路径应更新资料状态并保留数字 ID。

### 日志没有确认异常原文或调用栈

- `app/private/user-config/startup-errors.log` 最后写于 2026-10-25，内容只有 `exit-code=`，没有异常正文或调用位置。
- `app/private/user-config/ui-runs/` 下最近的 `.jsonl` 文件记录 BM 与核心运行事件，例如来话、播放、HRI 状态和 `runtime_snapshot`。其字段不包含 UI 身份查询异常或 PowerShell 调用栈。较早的一次核心日志有 `master_rejected` 状态，但无法把它和身份查询或 UI 退出联系起来。
- 因此现在不能确认 alpha.9 点击查询时报错退出的异常文本、触发调用点或根因。需要后续用带时间、run_id、查询阶段、异常类型/消息和退出码的最小诊断日志复现；不得把密码、profile 正文或完整 RadioID 用户资料写进日志。

### 需要验证的生命周期疑点

`Complete-UiIdentityQueryResources` 在 `bridge-ui.ps1` 884-886 行附近先调用 `PowerShell.Dispose()`，随后读取该对象的 `Runspace.RunspaceStateInfo.State`。这个顺序可能触发已释放对象异常，但本轮没有复现；函数的外围 `catch` 会把错误记入 `stop_error` 并继续等待清理，所以它本身还不能解释普通查询为何退出。另一个需要覆盖的路径是用户在查询进行中关闭窗口或点“停止并退出”：UI 会请求停止查询，8 秒硬期限到达后才可能强制退出。

另外，`Start-UiIdentityQuery` 在已有任务时会抛出异常。自动查询若直接从来话状态回调中逐次调用它，第二条来话可能进入未保护的 UI 定时回调。因此自动查询必须经过去重、有界队列和单 worker 调度，不能把网络操作直接放进来话/音频热路径。

## P0：修复退出风险并自动查询来话 ID

1. 先用离线 fake transport 和 UI 生命周期夹具定位并修复可复现的退出分支；明确区分查询失败、查询超时、用户取消和应用关窗。任何 RadioID 错误都只更新身份状态，不能停止接收、播放、路由或发射许可。
2. 每次收到新的、有效的 `current_call_source_id` 时，先立即显示数字 DMR ID，再由后台 worker 解析呼号/资料。UI 线程不得等待 DNS、HTTP、正文读取或缓存写入。
3. 对同一 DMR ID 合并重复请求；最多一个在线请求同时执行；维护有界等待队列，队满时仍显示数字 ID 并说明资料待查或略过。保持现有 5 秒网络上限和 8 秒清理硬期限，不以网络等待来延迟来话音频。
4. 命中缓存时不发请求。保留现有正向 30 天、未命中 1 天和 128 条上限；对网络错误增加仅驻留内存的短冷却/退避，避免同一 ID 在服务不可用时每次来话都重试。每个请求只查一个 ID，不下载或打包全库。
5. 查询完成时按 `run_id + current_call_generation + source_id` 判断结果是否仍属于当前来话；迟到结果可更新对应历史记录和缓存，不能覆盖新话者。用户取消或关窗后停止回调 UI，并保证 runspace、HTTP 响应和计时器都完成收尾。
6. 超时、无网络、未命中、缓存写入失败或服务响应不合规时都保留 `DMR ID <source_id>`；有旧资料时明确标为旧资料。身份解析结果不得用于设备认证或控制 PTT。
7. 按用户授权，新来话可自动触发一个 DMR ID 的查询。遵守 RadioID 官方 Normal lookup 要求，使用标明应用和联系地址的 User-Agent，并节制请求；通过缓存、同 ID 合并和限流避免重复查询，不批量下载或镜像数据库。R111 的“用户点击后才联网”在 R112 调整为来话自动单 ID 查询。本轮没有向 RadioID 或 BM 发起查询。

## P1：先补齐网络与语音质量指标，再改 DSP

当前音频路径和指标需求：

- PCM 路径为 48 kHz PCM16 与 8 kHz 间重采样，使用 127 tap Blackman FIR，截止频率 3.5 kHz；codec 帧间隔 20 ms，使用 AMBE+2。当前没有 EQ、AGC 或压缩器。
- 下行启动缓存为 2 × 60 ms；缺少 voice burst 时补入 3 × 20 ms 静音。
- 当前 `rx_call_missing_packets` 只记录 terminator 前最后一段 gap，不是整通话累计丢包数。应先修正统计，并分别记录 8 位序号回绕后的缺包、重复包、乱序包、过滤包和忙时丢弃，避免把不同原因合并成一个计数。若 watchdog 没有收到结束包，就无法确定尾部缺包数，界面应显示“未知”。
- BM 每 10 秒发送 ping，60 秒超时；当前没有 RTT 指标。测量发送成功到对应 pong 收到之间的单调时钟间隔，界面标为“客户端至 Master 往返时间”；不显示服务器 CPU 等本机无法测得的数据。
- 先取得往返延迟、每通话缺包/乱序、PCM 分段响度、峰值、削波和重采样结果，再决定是否调整 EQ、削波处理、重采样参数、PLC 或抖动缓冲。先测量后改 DSP，保留现有稳定路径作为比较对象。
- 原始 PCM 只用于离线 fixture，或在用户知情的短时样本中采集；不默认保存或上传通话音频。

## P1：单页 UI 信息布局

- 顶部显示连接健康状态与最近更新时间。
- 左侧 A 区集中显示本机当前收听目标、当前来话和来话历史；来话身份先显示数字 ID，资料返回后再更新呼号与可用字段。
- 右侧 B 区集中显示下一发射目标、频道收藏和组号输入；明确区分当前锁定目标与下一发射目标。
- 底部集中显示音量和削波信息；设置项放到设置窗口集中维护。
- 设计稿可稍后提供，可用 Figma、截图、草图或带缩放尺寸、状态和交互说明的 HTML。设计稿不阻塞 P0 的崩溃修复和身份查询。

## P2：经串口实路径传送 HRI 呼号字段

- 现有研究定位到 HRI 头部 `Src CallSign` 十字节字段，尚未确认 FTX-1 LCD 实际显示。T3 当前只携带 ID 标签；RadioID 呼号尚未接入该串口路径。
- 先把 RadioID 可核对的呼号映射到已定位的十字节字段，执行 ASCII、长度和字符校验，并保留原始 DMR ID 作为 UI 回退。姓名、城市、州/省、国家等字段只有在静态路径或官方资料证明设备/协议有相应字段后才能发送，不得把用户资料写进未命名偏移。
- 单独跟踪“软件构造了呼号字段”“串口写入成功”“电台屏幕显示呼号”三种证据。当前 `lcd_source_identity.display` 仍为 `unknown`，完成代码和离线检查后也不能直接声称 LCD 已显示。

## 并行 RF 研究：先确认 FM 可行性，再完成最短闭环与 C4FM

- 当前 DIRECT 路径只证明 BM DMR 解码后的 PCM 可以送到 FTX-1 WaveOut 扬声器；RF 尚未形成完整运行链。
- 先查清 FTX-1 在 FM 模式下的音频端点、HRI 模拟音频接口和 PTT 控制是否可用，再验证 `BM DMR 网络 → PCM → HRI 模拟音频接口 → FTX-1 FM` 的最短闭环。没有模式、端点、PTT 和音频证据前，不能承诺只加一个开关就能发射 FM。
- C4FM 路径待研究为 `DMR 语音参数或 PCM → C4FM 帧 → HRI 数字接口 → FTX-1 C4FM`。先确认 AP/PC 与 HRI 实际接收的输入格式；不预先规定电脑必须生成完整空口 IQ 或波形，目标是由电台负责 RF 调制。电脑不能把 DMR 调制信号直接交给电台当作 FTX-1 的 C4FM 输入。
- 没有第二台电台。本规划不要求用户现在准备额外设备；最终空口验收另行确定可用接收机或仪表方案，并把该验收与离线协议、串口和音频验证分开记录。

## 里程碑与验收门槛

| 里程碑 | 范围 | 可接受的完成证据 |
|---|---|---|
| A | 稳定性、来话自动 ID 查询、网络/语音基础指标 | 离线覆盖超时、取消、迟到结果、重复 ID、队满、cache 读写失败和关窗清理；验证查询失败时音频状态与数字 ID 保留；指标字段有来源、方向和单位。 |
| B | 测得音质后的 DSP 调整与单页 UI | 指标足以解释问题后再改 DSP；在规定缩放尺寸下核对布局、状态和交互；保留 A/B 区收听目标与发射目标的独立语义。 |
| C | HRI 呼号串口实路径与 LCD 观察 | 先有字段校验和串口写入证据，再用设备观察记录 LCD 实际内容；未观察前状态保持未知。 |
| D | FM 与完整 C4FM RF 运行链 | 每条链分别记录设备模式、输入格式、PTT、音频/数字帧路径和接收端观察；RF 结论只按实际完成的链路填写。 |

实现阶段先做离线验证，不从离线测试推导网络、设备或 RF 结果。最后由用户合并后再进行经授权的实机验收；每个里程碑单独记录已完成项、未验证项和阻塞项，不承诺一次交付全部功能。可复用 R111 既有身份模块 fake/local 测试、UI 生命周期测试和 RenderOnly 检查，但本轮没有运行这些测试。
