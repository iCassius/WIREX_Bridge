## 功能范围

1. UI 通过 schema 2 专用 `radio_identity.cache_upsert` 命令，将已有的 fresh RadioID 呼号映射异步送入 Native。该命令在普通 control 请求缓存之外处理，不消耗共享控制请求预算。
2. Native 在本次 run 内按 revision 接受映射和 `callsign:null` 权威删除，最多保留 128 个呼号映射并按 LRU 淘汰。呼号只接受大写 ASCII 字母、数字或连字符，长度 1–10 字节，且至少有一个字母。
3. UI 同时只发送一条映射并等待 ACK，单条等待上限 5 秒；待发送队列和跨 run 暂存队列各最多 128 个不同 ID。超时不会阻塞媒体、路由或关闭流程。
4. Native 只在后续来话 `callStart` 命中缓存时，将规范呼号写进现有 mode 4 T90 `SrcCallSign` 十字节字段。未命中或权威删除后仍使用原来的数字 ID 标签。活动通话身份冻结，不追加 T 记录或热写当前显示。
5. `lcd_source_identity` 有八个状态字段；`display` 固定为 `unknown`。`serial_write_state=sent` 只记录完整 T 帧写出，不代表 FTX-1 LCD 已绘制呼号。UI 不显示 LCD 成功或未知卡片。

功能没有更改其他 T90 字节、工作模式、声路、播放和 PTT 时序。FM/C4FM RF 发射未实现，UI 没有对应入口。mode 4 的正式 LCD 显示语义尚未证实。
