## 用户最新实测

以下是用户报告的现场观察，不延伸为完整语音或 RF 验收结论：

- 在相同的 HRI/DIRECT 连接下，官方 WIRES-X 程序的电台屏幕也没有内容或图标，屏幕底部按键没有反应。
- BrandMeister 网络有来话时，用户看到 FTX-1 红色指示灯亮起。单凭这次同步观察，不能确认指示灯为何亮，也不能把它当作 RF 发射或空中语音已通过的证明。
- 用户确认 AP 模式下网络语音可经电台 RF 输出，并认为 AP RADIO/AP PC 设置决定语音走无线电路径还是电脑路径。本文记录这个观察和解释；当前尚未读出设备当时的 Node Mode，也未闭合实际模式、PTT、空中语音之间的证据链。

## 后续开发顺序与验收门槛

### P0：明确运行模式与状态语义

1. 查清当前 HRI 会话能否通过受支持的接口读取 FTX-1 实际 Node Mode 和调制设置，并在内部日志记录读值来源、更新时间；读不到时记录 `unknown`。
2. 主界面只显示实际取得的数据，无读值时隐藏对应字段。需要人工确认模式时，通过已实现且确有作用的操作收集确认；没有现成入口时，先保留内部 `unknown`，不伪造读值，也不由 Bridge 暗中切换 Node Mode。
3. 把 `BM transmit_enabled` 限定为 BrandMeister 网络上行许可，不将它当作禁止电台 RF 发射的全局开关。用户已确认 AP 模式下网络语音可经电台 RF 输出，因此要另行定义软件是否向 AP 转发射频语音的许可，并记录用户对 DIRECT 模式的现场确认；软件选项不能被描述为锁定物理 DIRECT 或禁止电台 RF。
4. 分开记录 BrandMeister 上行/下行、HRI 音频播放、PTT 状态和已观测的 RF 发射。界面只显示实际取得的状态和已经实现的操作，不加入当前不会生效的模式切换或 RF 禁止按钮。保留与官方程序一致的指示灯行为，不以“网络呼入应亮蓝灯”为修复目标；通话方向使用实际 BM/HRI 字段显示。指示灯本身不能替代 PTT/RF/空中语音验收。

**验收门槛：**在设备上核对一次实际 Node Mode 和 RX/TX 调制设置，证明状态来源可靠；若无法读取，则验证内部日志保留 `unknown`，主界面隐藏无读值字段，并在存在有效操作入口时记录用户人工确认。明确区分 BM 网络上行许可、AP 射频转发许可和 DIRECT 确认，不得宣称一个软件设置能锁定实际 Node Mode 或阻止所有 RF 发射。

### P1：沿现有音频链验证 FM 双向路径

优先核对 BM 下行语音如何经现有音频链进入 FTX-1、HRI 的 FM 音频端点和 PTT 如何配合。按 BM→电台与电台→BM 两个方向分别检查目标/组选择、PTT 拉起与释放、超时清理和音频回灌。确认 TG91 的只监听语义以及选定的 RX 来源会不会由 AP 转发；不能从组名或 BM 上行开关推定 AP 不发 RF。先固定一种已记录的 FM 配置，不新增电脑 FM/IQ 调制器，也不把数字帧、HRI 播放和实际 RF 混成同一状态。

**验收门槛：**分别验收 BM→FTX-1→FM RF 与 FM RF→FTX-1→BM 两个方向，记录 Node Mode、调制、音频端点、目标/组和 PTT 设置，观察预期接收端的语音；每次呼叫结束后确认 PTT 释放，并确认没有本机回灌形成的持续占用。不要用已通过的手咪 DIRECT 双向回声代替这两条网络语音路径。FM 单向发射或网络呼入红灯不算双向通过。用户已确认 AP 模式下网络语音可经电台 RF 输出；RF→BM、空口语音、调制结果和通话结束后的 PTT 释放仍待验收。空口验收届时需要可观察的接收手段，具体方式在实机验证前另定；当前开发不以第二台电台或 MMDVM 为前置条件。

### P2：独立核对 C4FM 数字语音链

另行确认 HRI 数字接口所需的 AMBE/帧格式、通话元数据、收发方向和结束语义，再让 FTX-1 按实际 C4FM Node Mode 承担 RF 调制。不能用 FM 成功推断 C4FM 或 DMR/C4FM 转换成功，也不假定电脑要生成完整 RF 波形或 IQ。当前计划无需新增 MMDVM 或第二台电台。

**验收门槛：**先有协议/帧证据，再分方向观察数字帧进入 HRI、电台 RF 状态和接收端语音；把帧送入、RF 发射与空口语音接收分别记为独立结果。

### 并行：继续调查 LCD 支持范围

LCD 仍是核心功能目标，继续与声路及 RF 路径并行推进；它不阻挡声路/RF 的实现和分阶段验收。先查清屏幕行为属于 USB HRI、PC 端 PDN 还是普通 RF 节点模式，分别列明官方程序版本、所需 Node Mode、显示触发、列表字段和按键行为；HRI 复测时单独确认 `WIRES-X HRI` 状态字样。普通 RF 节点的 `ALL`、`SEARCH`、`ENTER ID` 流程及 PDN 的连接节点信息不能直接套用于 USB HRI/DIRECT。

R114 记录了 Native 完整写出身份 T 帧、但用户观察到 LCD 两个内容区仍空白；`sent` 不说明电台已接受、解析或绘制。现阶段不要再重复同一 mode 4 十字节字段写入尝试。获得相应模式的显示触发和字段证据后，再决定应追查的软件路径或屏幕协议，并由用户观察实际显示。

## 后续实机核对所需配置与记录

- 记录 FTX-1 固件版本、Bridge 与官方 WIRES-X 程序版本、连接方式、实际 Node Mode、HRI MODE 状态及 RX/TX 调制设置；模式读不到时由操作者现场确认，并在记录中注明为人工确认。
- FM 声路测试记录 BM 目标/组、音频端点、PTT 起止与超时清理、预期接收端以及通话后是否仍有占用，并明确 TG91 只监听和 AP 转发策略。
- C4FM 测试另记录实际 Node Mode、DG-ID/频率等电台设置、HRI 数字帧和元数据方向，以及接收端观察；这些设置不能从 FM 测试结果推定。
- LCD 观察需注明 USB HRI、PDN 或 RF 节点模式，以及触发动作、可见字段、按键响应和设备状态。避免读取或复制密码正文；只记录不含凭据的必要设置和值。
- 本轮没有新代码、构建或新包。后续源码变更通过离线检查后，仍须按以上实际设备门槛逐项验收，不能把未完成实机验收的代码或发射指示灯写成完整语音/RF 通过。
