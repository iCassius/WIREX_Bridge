# R116 电台控制界面

更新日期：2026-10-30

## 页面位置与设备选择

电台 CAT 控件位于独立的“设置”窗口。只有 `RadioCat.psm1` 成功加载时才显示该面板；模块缺失或加载失败时，面板会隐藏，BrandMeister 与 HRI 原有启动流程继续使用现有配置。

用户可从 Windows 当前枚举出的串口中选择 CAT-1 候选口。设备名称和 COM 号只用于选择候选项；每次 CAT 操作都会单独打开串口，读取电台 ID，并要求 ID 为 `0840`。当前识别为 HRI 的串口不能选作 CAT-1。界面不扫描未选择的串口，也不会把某个固定 COM 号当成电台身份。

默认 CAT 偏好为 COM11、38400 波特、2 个停止位、25 W。COM11 只作为初始偏好；当系统没有枚举出该端口时，列表提示“选择 CAT 串口”，不会创建假的 COM11 设备项。CAT 操作前还会核验端口身份。

## 独立偏好文件

CAT 偏好保存在用户配置目录的 `radio-control-preferences.json`，字段为 `schema_version`、`cat_port`、`baud_rate`、`stop_bits` 和 `desired_power_watts`。打开设置窗不会创建文件；用户按“保存设置”时才保存有效偏好。25 W 是待应用的用户偏好，不会在启动、读取状态或保存偏好时自动写入电台。

如果偏好文件损坏，界面禁用 CAT 设置和偏好保存，并在 CAT 面板内显示简短错误。用户仍可使用原有 BrandMeister/HRI 设置。CAT 代码不修改 `connection-profile.json`、`audio-settings.json` 或密码路径文件；损坏的 CAT 偏好文件会保持原样。

## 可读取的电台状态

“读取电台”通过 CAT-1 查询 ID、MAIN/SUB VFO 频率、MAIN/SUB 模式和 CAT 功率设定。界面只显示本次操作确实读到的字段，并为每项保留数据来源和读取时间。无读取值的字段隐藏。

CAT 功率字段显示 `PC;` 返回的电台功率设定。它记录电台配置的功率值，不是射频输出测量。读取和设置各使用一次短期 CAT 会话，串口关闭状态需确认后才报告操作完成；单个 CAT 操作最长 2.5 秒，不自动重试，也不创建常驻服务。

## 功率偏好与手动应用

功率滑块范围为 5–50 W、每格 1 W，初始目标功率为 25 W。电台返回的 CAT 功率路径决定当前可应用范围：Field Head 为 5–10 W，SPA-1 在本界面限于 5–50 W。界面不会把超范围目标改写为较小值；例如当前路径最多 10 W 而目标为 25 W 时，25 W 目标仍保留，并要求用户先明确选择当前合法范围内的数值，之后“应用功率”按钮才可用。

手动应用需要已读取的同一 CAT-1 端口和串口格式。核心进程运行时，界面还需要最近 3 秒内的状态确认：PTT 已释放、没有当前通话、接收媒体处于空闲或已过滤状态、接收队列为空。若新状态显示核心忙碌，或最近的状态超过 3 秒，界面会取消在途功率任务；在途操作的结果显示为未知。CAT 模块在本次串口会话内重新核验 ID、读取 `TX;` 并要求电台处于接收状态，发送一次功率命令，再读回精确值。只有精确读回且串口关闭成功才显示确认。

功率写入被拒绝时，若本次会话仍确认 ID、PC 读值、设备路径和串口关闭，设置窗会更新实际读到的功率值及路径范围，同时保留“rejected”操作结果并禁用再次应用。若这次会话未读到有效 ID 或 PC 值，设置窗清除旧功率能力和可写状态。

## MAIN VFO 模式与频率

模式控件只提供 MAIN VFO 的 `FM`、`FM-N`、`C4FM-DN` 和 `C4FM-VW`。频率控件接受 MHz 十进制数，最多 6 位小数，并将数值精确转换为整数 Hz；允许范围为 30 kHz–470 MHz。界面不截断小数，也不从 BrandMeister profile 的频率元数据填入电台频率。

模式和频率写入会改变 MAIN VFO，因此核心进程仍运行时，按钮会显示“断开并应用”。点击后，界面先检查最近核心状态为空闲，再启动现有 `StopAsync(5000)` 流程；确认核心进程已退出并释放资源后，才用冻结的 CAT-1 端口、波特率、停止位和 MAIN VFO 请求执行一次设置及读回。核心停止失败时不发送 CAT 设置。成功或失败后都保持断开，不自动重连。

CAT 设置作用于 MAIN VFO；HRI Voice CH 模式由另一套 HRI 配置管理。当前没有公开 CAT 命令能够切换 HRI MODE 或 WIRES-X Node Mode，所以设置窗不显示这些按钮。重新连接 HRI 后是否覆盖 MAIN VFO 的 CAT 设置仍需单独测试。

## 取消与退出

任一时刻只运行一项 CAT 操作。关闭设置窗会请求停止进行中的 CAT 任务，并在其结束和串口清理后关闭窗口。主窗口“停止并退出”会同时请求 CAT 清理和原有核心停止；CAT 清理不延迟核心的 `StopAsync(5000)`。关闭过程中若 CAT 任务超过 3 秒仍未结束，界面记录清理超时并强制退出，避免留下后台 runspace 或串口句柄。

用户在模式/频率断开流程完成前关闭设置窗或选择“停止并退出”时，待执行的 CAT 请求会撤销。CAT 查询、写入、偏好保存都不会自动重试。

## 验证边界

以下测试在 fake CAT transport 或 RenderOnly 环境中执行，没有连接真实 CAT 端口：

- Windows PowerShell 5.1 STA 和 PowerShell 7.6.5 STA 均通过 `tools/test-radio-cat.ps1`，各完成 52 项 fake transport 断言。
- Windows PowerShell 5.1 STA 和 PowerShell 7.6.5 STA 均通过 `tools/test-ui-radio-cat.ps1`。测试调用真实 WPF 设置窗口和 CAT UI 流程，覆盖 40 W 偏好在 Field Head 路径下保持不变、用户明确选择合法功率、拒绝结果刷新能力、断开成功/失败、关闭与退出撤销待办、并发拒绝、取消清理及状态过期处理。
- Windows PowerShell 5.1 STA 通过 `tools/test-ui-render.ps1 -PackageDirectory build\_work\r116-ui-only-fixture -RenderOutputDirectory build\_work\ui-render-r116-cat`。主窗口和设置窗口在 1280×900 与 1024×728 下渲染；缺失 CAT 模块与损坏的 CAT 偏好不会阻止原设置窗使用。
- Windows PowerShell 5.1 STA 通过 `tools/test-ui-status.ps1` 和 `tools/test-ui-lifecycle.ps1`。

这些检查没有启动 BrandMeister 核心、触发 PTT 或进行射频测试。本轮没有向真实电台发送 CAT 设置命令；真实设备设置写入行为仍未验证。此前的 COM11 操作仅为 CAT 查询，没有写入电台设置。
