# R117：BM 服务器与组控制

日期：2026-10-30

## 服务器下拉

MMDVMHost 仓库说明它是运行 MMDVM 的 host program；DMRGateway 仓库说明它把一个 MMDVM 系统接入多个 DMR 网络。这两项软件本身不对应一套必然存在的单一操作 GUI。本轮把 Pi-Star Dashboard 和 WPSD 中的 BM 管理界面当作 MMDVM 生态的操作参考。

Pi-Star 维护的公开 `DMR_Hosts.txt` 于 2026-10-28 更新。本地于 2026-10-30 获取该文件，并确认文件列出 `BM_4602_China`、`4602.master.brandmeister.network` 和 UDP `62031`；同一文件也列出 4501、5021、3102 和 2022 等实际 BM Master。对 `4602.master.brandmeister.network` 作 A 记录解析得到 `43.129.83.124`。该解析只核对 DNS，没有连接 BM 服务。

`ui/windows/BmServers.psm1` 将以上五个 Master 固定为离线目录；启动时不下载服务器清单。BM China 4602 排在首位。目录保留主机名和端口，并将 `43.129.83.124` 作为 4602 地址别名，这样当前 profile 可映射到正确下拉项。

本仓库当前 schema 2 连接字段为 `connection.master` 与 `connection.master_port`。`Resolve-BmServerSelection` 只判断下拉选中项并原样返回 profile 当前字段，不会因打开设置页而改写服务器。`New-BmServerSelectionValues` 只用于用户明确选择某项或保存自定义地址的操作；选择当前 4602 时保留 `43.129.83.124:62031`，明确选择另一 Master 时返回该目录项的 hostname 与端口。函数把 `bm_server_selection_id` 放进 `ui_preferences`，不把新字段加到 strict profile。

未列入目录的手工地址会作为 `custom` 保留。自定义项接受手工端口；目录中的地址清单不约束用户可使用的服务器。

## 三种组状态

下列操作分别作用于本机、BM 网络动态状态或 BM 服务端静态订阅。UI 应用明确字段名和各自动作标记：

| UI 操作 | 作用范围 | 实际动作 | 结果措辞 |
| --- | --- | --- | --- |
| 加入本机收听 | 本机 RX 过滤策略 | 发送 `rx_policy.replace`，编辑 `allow_groups`/`blocked_groups` | 本机允许/屏蔽规则已更新 |
| 激活动态组 | BM 动态组会话 | 发送 `network_subscription.quick_call_join`，一次无语音 Quick Call | 激活请求已发送；后续 BM 来话另按状态报告 |
| 添加/删除静态组 | BM 设备账户的持久列表 | BM API v2 `POST` / `DELETE` | API 接受后读取列表，只有读回目标状态才标为已确认 |

R109 已规定本机 RX allow/block 更新不发 Quick Call；动态组 Quick Call 不改本机 RX/TX 策略、下一发射目标或语音发射许可。一次 Quick Call 成功只确认 Bridge 的 UDP transport 发送了两帧，不确认 BM 已接入该组，也不提供会话驻留时间。

静态组列表从 BM 网络侧取得；它不是 profile 中的接收 allow 规则，也不是本地收藏。静态列表的添加、删除需要显式 BrandMeister 用户 API v2 token。BM 官方说明该 key 可读取和更新账户资料，并能访问用户的 SelfCare/sysop 功能。应用只接收用户明确配置的 key 文件路径，不读取旧配置、密码文件或任意 API key。API key 正文不会进入 UI preference、profile、日志、异常或返回结果。

## BM API 客户端

`ui/windows/BmManagement.psm1` 只用 PowerShell/.NET 内置 HTTP 类型，不引入第三方依赖。其 API origin 固定为 `https://api.brandmeister.network`，device id 只能是十进制数字，禁止外部提供 host 或 URL，并关闭 HTTP redirect。默认请求上限 3 秒，最大 10 秒；调用方可用 `CancellationToken` 取消在途任务。

API key 文件必须由用户显式指定完整路径。模块接受完整 raw BM v2 JWT，或 Pi-Star `[key]` 段中的 `apikey=...` 形式；缺文件、格式错误或非 v2 key 会在 transport 前失败。用户 preference 只保存该文件路径。该文件必须排除 Git 与发行包。

| 命令 | BM v2 请求 | 输入 | 返回 |
| --- | --- | --- | --- |
| `Get-BmStaticGroups` | `GET /v2/device/{deviceId}/profile` | key 文件路径、profile `connection.gateway_id`、timeout/cancellation | `groups` 仅含 `device_id`、`talkgroup`、`slot`、`type=static` 与读取时间 |
| `Add-BmStaticGroup` | `POST /v2/device/{deviceId}/talkgroup`，JSON `{ "slot": 1|2, "group": TG }` | key 文件路径、设备 ID、TG、TS1/TS2 | 一次 POST 和一次 GET；返回 `write_accepted` 与 `readback_status` |
| `Remove-BmStaticGroup` | `DELETE /v2/device/{deviceId}/talkgroup/{slot}/{TG}` | key 文件路径、设备 ID、TG、读回的 slot 0/1/2 | 一次 DELETE 和一次 GET；返回 `write_accepted` 与 `readback_status` |

设备 ID 使用当前冻结 profile 的 `connection.gateway_id`，与普通用户 `source_id` 分开。API profile 只提取 `staticSubscriptions`，不把其它账户资料传给 UI。GET 会校验 TG 与时隙范围、重复项和 1 MiB 响应上限。静态组写操作只在用户按添加或删除时发生，不自动重试。若写请求得到成功 HTTP 响应但读回失败，结果保留 `write_accepted=true`，状态仍为未确认；若等待首个写响应时发生超时或取消，写入结果可能未知，UI 应要求用户手动刷新后再判断，不应自动重发。

`ui/windows/BmManagementUi.ps1` 把 API 操作放进单独的 PowerShell runspace，并由 Dispatcher 轮询结果。无 API 文件路径时隐藏静态组区域；路径有效但尚未取得列表时，只显示刷新和状态。只有 GET 成功后才呈现远端列表和 Add/Remove；GET 返回空列表时仍视作已读取，允许添加。写操作被服务器接受但读回失败时，界面清除旧列表并要求用户刷新确认，不会生成本地假记录或自动重发。动态组区域保留 Quick Call；它不使用静态订阅 API。设置连接字段在核心运行时锁定；音量保持 `audio-settings.json` 的播放增益语义，CAT 功率继续由 R116 的 CAT 控制流程管理。

## 验证范围

- `tools/test-bm-servers.ps1`：PowerShell 7.6.5 与 Windows PowerShell 5.1 各通过 32 项断言。
- `tools/test-bm-management.ps1`：PowerShell 7.6.5 与 Windows PowerShell 5.1 各通过 39 项断言。Fake transport 覆盖只读列表、添加、删除、写后读回、取消、超时、错误响应、slot 0 显示、显式文件 key 与 token 不回显。
- `tools/test-bm-management-ui.ps1`：PowerShell 7.6.5 与 Windows PowerShell 5.1 各通过 35 项断言。用实际 WPF 控件、fake transport 和临时 synthetic token 覆盖无 key 隐藏、空列表 GET、Add/Remove 单次写入与回查、未确认状态、取消和资源清理。
- 可复核命令：`powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -STA -File tools/test-bm-management-ui.ps1` 与 `pwsh -NoLogo -NoProfile -STA -File tools/test-bm-management-ui.ps1`。
- 三项测试脚本均检查 UTF-8 BOM。测试只使用临时 synthetic key 文件与 fake transport；没有调用 BrandMeister API，没有读取本机真实 key，没有添加或删除用户静态组。
- WPF fake 测试没有加载主窗口 XAML，也没有启动桥接核心；主界面接线由后续集成步骤确认。本轮没有 BM 登录、Quick Call、PTT、COM、音频设备或 RF 测试，也没有真实 BM API 响应证据。
