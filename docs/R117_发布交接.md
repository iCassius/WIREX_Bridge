## 冻结后构建与包级启动命令

`tools/build-bm-bridge.ps1` 不带 `-CompileOnly` 时，从当前源码提交创建新的时间戳构建目录、编译并运行 profile 中的 40 项 Native 测试，再写入 `build-provenance.json`。从干净源码提交运行，并将整个控制台输出重定向到 `build/_work` 中的新日志。打包器会核对 source commit、`source_tree_clean=true`、`compile_only=false`、40 项通过结果、日志顺序、warning/error 和 EXE 哈希。

```powershell
$shortCommit = (git rev-parse --short=7 HEAD).Trim()
$buildLogPath = Join-Path 'build/_work' ('alpha13-clean-build-{0}-{1}.log' -f $shortCommit, (Get-Date -Format 'yyyyMMdd-HHmmss'))
pwsh -NoLogo -NoProfile -File tools/build-bm-bridge.ps1 *> $buildLogPath
if ($LASTEXITCODE -ne 0) { throw 'Native 40 项 clean build 失败。' }
```

从构建日志的“构建产物”行取得实际 BuildDirectory，再将该目录和日志传给 `tools/package-release.ps1`：

```powershell
pwsh -NoLogo -NoProfile -File tools/package-release.ps1 `
  -Version v0.1.0-alpha.13 `
  -BuildDirectory 'build/_work/<fresh-native-build-directory>' `
  -BuildLogPath 'build/_work/<fresh-native-build-log>' `
  -YFixturePath private/fixtures/device-y.bin
```

打包器生成直接文件夹 `build/releases/v0.1.0-alpha.13`，不生成 ZIP，也不创建 tag 或 GitHub Release。实际包生成后，使用 Windows PowerShell 5.1 通过唯一 CMD 运行 PrepareOnly 与隔离 RoutingDiagnosticAutoTest：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File tools/test-package-startup.ps1 `
  -PackageDirectory build/releases/v0.1.0-alpha.13
```

`tools/test-package-startup.ps1` 已扩展支持 Alpha 13，并检查 CAT/BM 运行模块的 UTF-8 BOM。Windows PowerShell 5.1 独立复跑通过：12 个 PowerShell 文件解析成功，唯一 ASCII CMD 在带空格和中文的路径下运行 PrepareOnly 与隔离 RoutingDiagnosticAutoTest，退出码为 0。
