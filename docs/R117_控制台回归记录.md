# R117 控制台与 CAT 同步回归记录

## 运行命令

```powershell
pwsh -NoLogo -NoProfile -STA -File tools/test-ui-console.ps1
powershell.exe -NoLogo -NoProfile -STA -File tools/test-ui-console.ps1
pwsh -NoLogo -NoProfile -STA -File tools/test-ui-console.ps1 -LiveSerialReadOnly
powershell.exe -NoLogo -NoProfile -STA -File tools/test-ui-console.ps1 -LiveSerialReadOnly
```

本轮最新复验中，PowerShell 7.6.5 与 Windows PowerShell 5.1.26100.8737 的普通模式各通过 78 项真实 WPF 行为断言；两个环境的 `-LiveSerialReadOnly` 各通过 16 项断言。Live 测试使用生产串口 runspace 读取本机注册表/CIM，并通过真实 WPF 发布目录；没有打开 COM、启动 CAT poll/worker 或 native supervisor。

## 已验证行为

- 脚本通过 `-UiTestFixture` 创建真实主窗口和 DispatcherTimer。连接配置、CAT worker、设备列表都使用隔离临时目录；测试结束前检查临时目录绝对路径，再清理该目录。
- 设备测试走 `Start-UiDeviceDiscovery -UseProductionOrchestration` 和共享结果发布函数。SerialEnumerator 与 AudioQuery hook 只替换设备 IO。音频返回 error 或 timeout 时，COM11 Enhanced CP2105 仍显示并自动选择；两个同级 Enhanced 端口同时存在且没有保存选择时，程序不任意挑选。
- CAT 端口控件接受没有被枚举到的手动 COM99，并通过同一 CAT 操作入口完成 fake query。COM5 被识别为 HRI 时，CAT 操作拒绝复用该端口。
- 设置偏好里保存 COM11，但当前串口目录没有 COM11 时，CAT 下拉不会恢复过期 COM11；只有用户实际选择或编辑端口才标记为手动输入。串口目录没有唯一推荐设备时，控件保持空白供用户手动填写。
- 测试通过真实 `ConnectButton` 进入 NativeSupervisorFactory fake。连接后，左侧 CAT 串口配置变灰，右侧读取操作仍可用。连接成功触发首个 CAT 全状态查询，核验 ID 0840 和 25 W 观测值。
- 默认轮询间隔为 1 秒。合成的下一次硬件读值从 25 W 变为 30 W 时，观测显示更新；用户将滑块调到 24 W 后，轮询保留 24 W 草稿。测试把保存偏好改回 40 W，再点击真实“应用功率”按钮，结果仍写入草稿 24 W；fake readback 确认 24 W 后，草稿被清除。
- SPA-1 上 25 W 请求返回 `rejected/power_out_of_range`，并携带已关闭串口、ID 0840、FieldHead 实际 5 W 和最大 10 W 的有效读回时，界面合并真实观测和能力范围，但保留 `rejected` 结果并撤销所有写入许可。再次 query 确认 FieldHead 后，滑块上限为 10 W，用户显式选择 9 W 才能应用。
- 后续 query timeout 会清除模式、频率和功率全部写入许可，保留最近一次成功读值及其原始来源时间；在未重新成功读取时，三个写入口都不能启动 CAT worker。
- 用户点击 MAIN 模式写入后，测试核验先停止 fake HRI，再执行一次 CAT query，只有 query 确认后才发起一次 setMode，并检查 FM-N readback。MAIN 频率也需先确认 query，再对 145.600 MHz 执行一次 setFrequency 和 readback。
- 停止轮询会取消在途 worker；`Complete-BridgeStop` 收尾会停止 CAT 轮询并恢复左侧配置。核心延迟退出期间，真实“停止并退出”事件立即停止轮询；测试确认没有新的 CAT query，并在 fake supervisor 完成后关闭窗口。
- `-LiveSerialReadOnly` 会由实际 WPF `Start-UiDeviceDiscovery -UseProductionOrchestration` 启动生产串口 runspace，runspace 导入真实 `RadioDevices.psm1` 并调用无输入的 `Get-RadioDeviceCatalog`，读取本机串口 Registry/CIM 目录，再经 Dispatcher 发布到 CAT 下拉。AudioQuery 仅使用返回空列表的 fake；SerialEnumerator 没有替换生产 runspace。PS7 与 Windows PowerShell 5.1 各通过 16 项断言；没有启动 CAT poll/worker 或 native supervisor。

## 测试边界

CAT 操作全部由 `CatOperation` fake hook 返回协议模块结果结构，并经过 UI worker、结果校验、UI 控件和 readback 状态处理。本轮没有打开真实串口，也没有发送 CAT 命令或执行电台设置。

测试没有启动真实 native 核心、BrandMeister 请求、PTT、RF 或真实电台硬件；没有读取或写入 canonical profile，也没有读取密码正文。真实设备、真实 CAT 串口和 HIL 行为仍未验证。调用者身份/API 目录与 BM 静态组由各自的独立回归覆盖。
