# R117 旧 UI 回归兼容与执行记录

## 范围

本记录覆盖 `test-ui-status.ps1`、`test-ui-lifecycle.ps1`、`test-ui-identity.ps1` 和 `test-ui-radio-cat.ps1`。测试只在本机 PowerShell/WPF、独立临时目录和 fake CAT transport 中运行；identity HTTP fixture 绑定 `127.0.0.1`。这些脚本不打开真实 COM 端口，不连接 BrandMeister，不触发 PTT，也不读写用户配置目录。

## R117 兼容调整

- 状态与生命周期脚本仍从 `bridge-ui.ps1` 选取被测函数，检查状态字段、序号/新鲜度、日志保留和异步取消行为。
- 身份脚本显式初始化主界面运行时的可选 `settingsWindow`、CAT 与 BM timer 状态。它保留真实 WPF 按钮、Dispatcher、身份查询 runspace、Native ACK 队列和本机 HTTP fixture；CAT/BM timer 收尾回调用空 fixture 隔离。
- CAT 脚本同时加载 `bridge-ui.ps1` 和 `RadioCatUi.ps1` 中的函数，并用真实 `MainWindow.xaml` 承载 CAT 控件。`SettingsWindow.xaml` 只作为路由弹窗加载。fake 设备目录给唯一合成 CAT 端口 `COM11` 标记匹配等级，以符合 R117 的 `auto` 默认选择行为。
- CAT 断言区分已保存功率偏好和用户编辑草稿。FieldHead 首读显示真实读数；无草稿时保留 40 W 偏好并禁用 Apply。用户把真实滑块改到 9 W 后，测试检查 9 W 草稿形成且 Apply 立即启用。
- HRI 停止后的 mode/frequency 回归按当前实现检查完整顺序：停止并释放核心、先查询 CAT，查询确认后再执行唯一冻结的 MAIN 请求；查询确认前不得写入。
- `Cancel-SettingsWindow` 与路由窗口 Closing handler 不再取消 MainWindow 所有的 CAT worker，也不清理 MainWindow 的待执行 MAIN mode 请求。测试检查关闭路由 modal 后 query 继续运行，并在 CAT query 确认后按冻结参数执行请求。
