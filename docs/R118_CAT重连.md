# R118 CAT 串口断开与重连

## 目标

CAT 串口暂时消失、读取超时或重新枚举时，主窗口保留最近一次实际读取的模式、频率和功率。程序不会因每秒轮询而反复重建控件，也不会把失败的读取当作写入许可。端口恢复后，轮询重新执行 CAT 读取。

## CAT 状态处理

- 串口目录处于 `ready` 或 `empty` 时，后台读取只针对当前目录中存在的 CAT 端口启动。选中的端口暂时不在目录中时，轮询保持等待，不创建新的 PowerShell worker；明确手动读取仍走独立的 CAT 操作入口。
- 同一时刻最多运行一个 CAT worker。已有读取结束前，计时器不会再启动第二个查询。端口或配置变化会使旧上下文的结果失效；迟到结果不能覆盖当前端口的状态。
- 串口离开目录时，写入许可和上次查询结果被清除，但最近一次成功读取的观测值、时间戳和用户草稿继续保留。目录出现相同端口后，控制器开始新的查询；确认结果后再恢复写入按钮。
- CAT 串口真实离开目录、查询由成功转为失败、查询从失败恢复时，分别使用现有 `Add-UiEvent` 记录一次短事件。相同状态连续多个轮询周期不会重复写事件；主窗口没有事件列表时，短事件会显示在现有页脚文字区域。
- CAT 观测区域随模块可用状态显示，不随查询忙闲或超时反复隐藏。可见值只显示模式、频率和功率；电台身份、CAT 角色、来源及时间戳仍在内部结果校验和新鲜度判断中使用。
- 期望功率、观测功率与用户编辑草稿各自保存在原有独立字段中。查询或超时不会覆盖用户草稿，也不会自动写入频率、功率或 PTT。
- CAT 波特率默认 38400，可按配置调整；8N2 停止位固定为 `Two`。界面不要求存在停止位控件；配置保存继续使用 `cat_stop_bits: 'Two'`。

## 自发断开与恢复

HRI native supervisor 报告进程退出后，UI 在这次状态转换中停止 CAT 轮询并请求取消未完成的查询。计时器后续周期不会重复清理 CAT 面板或锁定连接按钮。旧 CAT worker 完成收尾后，用户可以重新连接；新会话会执行 CAT 首读。真实 WPF fake 验证了 COM11 在途查询收尾后重新枚举为 COM12，并在新会话中完成首读。

用户明确提交的 MAIN 模式或频率请求会先等待 HRI supervisor 成功退出并释放旧 CAT worker，再对冻结请求中的同一个 CAT 端口和串口参数执行一次新查询。如果停止期间旧 CAT 查询仍在途，UI 会先取消并收尾旧 worker，然后启动新的查询；旧查询结果不会消费冻结请求。只有新查询确认身份、端口和当前连接键后，才发送该请求并读取回执。HRI 停止失败、CAT 查询失败或用户取消时不发送设置；端口或参数发生变化时旧查询结果不能授权写入。普通离线 CAT 操作仍需当前端口的确认读取许可。

## 验证记录

- `tools/test-radio-cat.ps1`：Windows PowerShell 5.1 与 PowerShell 7.6.5 各通过 54 条 CAT 协议和串口 fake 断言；脚本没有打开物理串口。
- `tools/test-ui-console.ps1`：Windows PowerShell 5.1 STA 和 PowerShell 7.6.5 STA 各通过 115 条真实 WPF 交互断言。测试覆盖串口目录变化、查询超时、COM11 恢复及短状态事件显示、HRI supervisor 自发退出时的在途 CAT worker 清理，以及重新枚举为 COM12 后的新会话首读。模式请求竞态测试让旧 CAT query 延迟 5 秒，在其在途时发起 HRI 停止；旧 worker 收尾后才启动新的 CAT query，再执行唯一的模式设置和读回。
- 上述 CAT 协议和 WPF 测试使用合成串口与 fake supervisor，没有打开真实 COM、连接 BM、触发 PTT 或发射 RF。
- 未执行真实 COM、BM、PTT 或 RF 操作；本文件不声明硬件联测结果。
