# R118 统一便携配置

## 目标与交接

R118 把 WIREX Bridge 的连接、凭据、设备、音频、频道、发送目标和界面偏好收进软件目录根部的 `config.json`。用户移动整个软件文件夹时，文件一同移动。当前源码不保存用户运行配置；开发和自动测试只在临时目录建立合成配置。

模块由 `ui/windows/PortableConfig.psm1` 提供，界面使用以下两个入口：

```powershell
$config = Get-WirexPortableConfig -Path (Join-Path $packageRoot 'config.json')
$config = Save-WirexPortableConfig -Path (Join-Path $packageRoot 'config.json') -Config $config
```

文件不存在时，读取函数返回含默认值的对象，不创建文件。界面保存后才创建 `config.json`。读取遇到无效 JSON、重复字段、损坏结构或不支持的版本时会报错；保存函数会先读取并验证当前文件，通过后才写同目录临时文件并原子替换。任一校验失败都会保留原始文件。保存时会把磁盘文档中界面不认识的字段合并回来。

## 文档字段

当前版本为 `schema_version: 1`，主要字段如下：

| 字段 | 内容 |
| --- | --- |
| `connection` | 呼号、Gateway ID、Source ID、BM Master 和 UDP 端口、色码、BM 密码和 BM API key。Master 默认 `43.129.83.124:62031`，选择标识默认 `bm-china-4602`；呼号和 ID 可留空暂存，连接时再验证。凭据作为输入值保存在同一文档中，不存凭据文件路径。 |
| `devices` | HRI 串口、CAT 串口、CAT 波特率、音频 endpoint、期望功率。HRI 同时保留 `serial_port` 兼容字段并与 `hri_port` 同步；CAT 停止位固定为 `Two`，不显示为界面选项。 |
| `audio` | `radio_playback_gain` 和 `mic_transmit_gain`，单位是倍数，范围 0.25 到 16.0，最多三位小数。默认值是 1.0x 和 16.0x。 |
| `channels` | 按列表顺序保存 `{id,kind,slot,name}`。列出的频道可收听，也可选择为发送目标；空列表表示没有已配置频道。运行期间临时静音只保存在内存中。 |
| `tx_channel_id` | 频道 tuple key：`kind:id:slot`。默认是 `private:460997:2`；空列表时必须为空。默认频道是私呼 460997、TS2。 |
| `routing.blocked_source_ids` | 独立保存的来源 ID 屏蔽列表。 |
| `ui.bm_server_selection_id` | BM Master 下拉框选择标识。 |
| `ui.legacy_rx_policy` | 迁移时留存的旧 RX policy 快照，供审计与人工检查；运行时频道监听规则不会从它派生。 |
| `window` | 界面窗口偏好扩展对象。未知子字段随配置保存。 |

频道 tuple key 由 `kind`、`id`、`slot` 组合，因而同一数字 ID 用于不同呼叫类型或时隙时仍可区分。配置接受 1 到 16777215 的合法 group/private ID，包括 TG91、TG46001 和 TG4000；保存 TX 目标只记录下一次用户操作选择，不会自动发起发送。UI 根据当前频道列表生成实际 `rx_policy`，其中 group 对应 `allow_groups`，private 对应 `allow_private_peers`。旧策略中的 `allow_groups`、`allow_private_peers` 等路由只作迁移参考，不会暗中增加频道；`blocked_source_ids` 单独迁移到 `routing.blocked_source_ids`。

## 旧设置迁移

调用方只有显式提供 `-LegacyDirectory` 时，缺少目标 `config.json` 才会读取指定目录中的旧文件：连接 profile、音量设置、电台控制偏好、BM Master 偏好、BM API 文件路径偏好和 `password-file-path.txt`。模块不搜索其它目录，不遍历备份，不迁移旧频道收藏，也不改写或删除任何旧文件。显式旧配置迁移由源码仓库中的模块执行；alpha14发行包不带旧连接配置读取模块，常规启动也不传入 LegacyDirectory，因此实际迁移必须在 root 单独批准后使用源码入口完成。

连接 profile 的 TX target 始终作为新频道列表的首项，并保持为当前起呼目标；之后依次加入旧组呼频道和明确配置的私呼 peer。local_private_routes 描述本机接收目标，不是远端 peer，不会转换成频道。完整旧 rx_policy（含本机私呼路由）放在 ui.legacy_rx_policy；来源屏蔽 ID 迁至 routing.blocked_source_ids。旧音量保持相同的倍率含义；旧 CAT 停止位值按当前要求改为内部固定的 `Two`。旧收藏不复制进频道表，旧收藏文件保持原样。

迁移密码只会读取旧 `password-file-path.txt` 明确指向的单行完整路径。迁移 API key 只会读取旧 BM API 偏好明确指向的文件。读取后新文档保存密码或 API key 值本身，不保存旧路径。源文件正文不会写进日志或错误信息。只有目标配置不存在并且调用方传入旧目录，迁移才会运行；本轮代码与测试没有读取或改动当前机器的 canonical 用户配置。第一次发布时是否从旧 canonical 目录迁到新 release 根目录，由 root 独立批准执行。

## BrandMeister 静态组 API

`ui/windows/BmManagement.psm1` 的 `Get-BmStaticGroups`、`Add-BmStaticGroup` 和 `Remove-BmStaticGroup` 支持 `-ApiKey` 字符串参数。界面可以从 `connection.api_key` 读取内存中的值，并在进程内 runspace 调用 API；不要把 key 放进进程命令行、结果对象或日志。操作结果只包含静态组、HTTP 写入接受状态和读回结果。

现有官方 HTTPS 地址、请求超时、取消、响应大小限制、单次写入后一次 GET 读回都保持不变。旧 `-ApiKeyFilePath` 只保留给合成兼容测试和明确的旧迁移入口；新界面使用 `-ApiKey`。

## 本地验证

- `tools/test-portable-config.ps1`：PowerShell 7.6.5 和 Windows PowerShell 5.1 各通过 55 项断言。测试只用临时目录、synthetic 连接值和 synthetic 凭据；覆盖默认频道、有序/空频道、TX tuple key、自定义 TG91/TG46001/TG4000 值、未知字段保留、大小写变体凭据路径拒绝、损坏或缺字段源不覆盖、显式迁移、TX 首项与默认目标、本机私呼目标不生成 peer 频道、旧 RX policy 原样留存、旧凭据指针、路由合并、固定 CAT 停止位和旧收藏不迁移。
- `tools/test-bm-management.ps1`：PowerShell 7.6.5 和 Windows PowerShell 5.1 各通过 45 项断言。Fake transport 检查内存 key 的 Bearer 头、静态组读取和写后读回、取消/超时、旧 key 文件兼容、拒绝双来源和错误不回显 key；没有网络请求。
- 两个 PowerShell 源码和测试脚本都要求 UTF-8 BOM。当前仓库 `.gitignore` 只排除根目录 `/config.json` 和 `/config.*.backup*`，不会忽略模板文件。

验证命令：

```powershell
pwsh -NoLogo -NoProfile -File tools/test-portable-config.ps1
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File tools/test-portable-config.ps1
pwsh -NoLogo -NoProfile -File tools/test-bm-management.ps1
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File tools/test-bm-management.ps1
```

以上为离线合成验证。没有迁移本机设置、连接 BM API、打开串口、启动 HRI、播放音频、PTT 或 RF。
