# R119 实时音量调整

日期：2026-11-01。范围：UI v2 控制协议和 Native BM/HRI 主循环的播放、麦克风 PCM 增益。CLI 参数、默认值和既有配置读取方式保持原样。

## 控制命令

Native 仅在本次运行实际接入音量 handler 后，才会在 `control_ready.supported_commands` 和 `hello.supported_commands` 中报告 `audio.gains.set`。旧 Native 没有该 handler 时继续使用旧命令集，不能把滑块值显示成已应用值。

UI 发送单个原子请求，`request_id` 固定为 `audio-gains-{revision}`：

```json
{"schema_version":2,"run_id":"当前run_id","request_id":"audio-gains-1","command":"audio.gains.set","parameters":{"revision":1,"radio_playback_gain_milli":1250,"mic_transmit_gain_milli":8000}}
```

`revision` 必须是大于零的 JSON 无符号整数；两路增益必须是 250 至 16000 之间的 JSON 无符号整数，单位为千分之一倍率。Native 只保留本次运行中最后一次成功的 revision、请求值和实际读回值，不占用普通控制命令的 512 项重放缓存。同 revision、同一对值会返回幂等成功；同 revision 的不同值会报 `audio_gain_revision_conflict`；更小 revision 会报 `stale_audio_gain_revision`。Native 每次新运行从 revision 0 开始。

成功回执的 `audio_gains` 对象包含 Native 实际应用的 revision 和两路值：

```json
{"schema_version":2,"type":"control_result","run_id":"当前run_id","control_seq":9,"request_id":"audio-gains-1","command":"audio.gains.set","result":"ok","replayed":false,"audio_gains":{"revision":1,"radio_playback_gain_milli":1250,"mic_transmit_gain_milli":8000}}
```

`status` 回执在 `snapshot.audio_gains` 返回同一组字段；启动读回使用 revision 0。范围错误返回 `invalid_audio_gains`，revision 冲突或过期分别返回 `audio_gain_revision_conflict`、`stale_audio_gain_revision`，handler 未成功或没有给出合法读回值时返回 `audio_gain_update_failed`。UI 只在成功回执与两路读回值都通过校验后，才把实际值写入现有桌面配置；Native 不写配置文件。

UI 在 control version 2 的 ready 和 hello 都确认该命令后才启用滑块。拖动持续时，每 200 ms 最多发送一组最新值，一次只等待一个确认；等待期间合并到最新的一对值。失败或本地等待超时后，UI 查询 `status` 并按 Native 实际值校准，不把请求值当成成功值。

## 实时生效位置

- BM 下行播放增益在每个新解码 PCM 帧送入 WaveOut 前应用。
- 电台麦克风上行增益在每个新取出的 WaveIn PCM buffer 送入 BM voice pipeline 前应用。
- 两个参数经同一个主循环回调一并更新。处理后续 PCM 时使用新值；已提交给 WaveOut 的帧按提交时的旧值播放完毕。
- 命令不重置 codec、不重开串口或音频端点、不改变路由、通话 owner 或 PTT 状态。音量仍是软件 PCM 缩放，超出 PCM16 的样本按现有增益模块饱和到 PCM16 范围。

## 验证边界

协议单测使用内存 handler 验证范围拒绝、幂等重放、revision 冲突/拒绝、handler 失败和异常、回执读回，以及超过 512 次增益更新仍不增加普通缓存。测试还将两路新值送入现有 `pcm_gain::apply`，逐样本核对播放和麦克风方向的缩放。

`--routing-diagnostic` 使用内存音量 handler，可通过真实 Native IPC 验证能力发布、ACK、status 和传输白名单；该诊断不访问 BM、COM、WaveIn 或 WaveOut。这里的验证不包含真实设备声音、PTT、RF 或实机听音。
