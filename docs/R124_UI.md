# R124 主界面交互与布局验收

## 增益滑块

`PlaybackGainSlider` 与 `TransmitGainSlider` 使用灰色圆角轨道、蓝色当前值填充、28 px 白色圆形旋钮和七个装饰刻点。禁用时，轨道、填充和旋钮都会变为低饱和灰色。模板保留 WPF `PART_Track`，两只滑块仍使用 0.25–16 的原范围、0.05 键盘微调和连续鼠标定位；刻点只用于显示，`IsSnapToTickEnabled` 为 `False`。现有 `ValueChanged` 处理器继续处理运行中的增益请求。

## 下拉框和频道预设

主窗口内每个 ComboBox 的输入主体都可打开 WPF Popup。可编辑频道 ID 和 CAT 频率保留文本焦点，展开列表时可继续输入。频道预设项用中文名称显示，`TextSearch.Text` 为纯 ID，`Tag` 仅保存 `ID|类型`（例如 `46001|group`），不包含时隙或名称。选择预设后编辑框显示纯 ID，原有 `SelectionChanged` 处理器负责同步频道类型。

## 频道卡片和固定布局

- 频道面板保持 3 列 × 2 行，卡片固定约 109 px 高。
- 标题显示 ID、已知名称以及已确认的静态组或动态组状态。过长名称在标题中省略，悬停提示保留完整文字。
- 来话区域与 2×2 操作区上下边界对齐；来话历史仍完整显示 5 行并按每页 5 条分页。
- 主窗口不增加可滚动区域；下方连接配置与日常控制仍各占一半。

## 验收方式与证据

- `tools/test-ui-render.ps1` 运行 Windows PowerShell 5.1 STA RenderOnly，检查主窗口与说明窗口实际边界、文字对比度、无重叠、固定频道卡和历史行、增益滑块模板合同；它也比较两次渲染的位置。
- `tools/test-ui-r124.ps1` 通过 Windows SendInput/SendKeys 和真实鼠标输入展开每个 ComboBox，选择中文频道预设，点击和拖动滑块、使用方向键，并把运行增益命令交给内存假核心检查。
- `tools/test-ui-audio-gain.ps1` 检查既有增益请求、读回、超时和热调状态处理。

本轮结果：RenderOnly 通过 1,951 项布局与边界断言；实体 UI 输入回归通过 63 项断言；增益专项通过 85 项断言；R123 固定布局回归通过 54 项断言。长频道名称的 RenderOnly fixture 显示省略号，并在完整 Tooltip 保留原文。

root 接受此前 63 项实际 WPF 输入回归结果。后续另一次交互尝试时 Dota 2 在前台，WPF 窗口没有收到输入事件；该尝试不形成新的交互结果，也不推翻此前通过的 63 项。没有再次抢占或注入前台输入。
