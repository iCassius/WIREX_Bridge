## 实现

- 将用户已授权的既有 100 字节 HRI Y 模板作为只读 `constexpr` 数组编入程序。启动默认使用内置模板；明确传入的外部模板仍要求绝对路径。两种来源均核对模板长度、标记和固定 SHA-256。
- HRI Auto 继续从注册表和 SetupAPI 目录中选择唯一已识别的 HRI COM 口；CAT Auto 每次连接前重新枚举，只选择唯一分类候选，并排除 HRI 口。CAT 只有在只读查询确认成功后才发布 `CatState.connected=true`。Auto 无唯一候选时返回错误，不逐口试连。
- 主连接操作通过既有 ViewModel `start()`/`stop()` 同时编排 Engine/HRI 与 CAT。两侧状态仍分别来自 Engine `Snapshot` 和 `CatState`；CAT 连接任务带代次，停止后会取消排队任务并丢弃过期完成回调。GUI 对部分成功分别显示，单侧成功不会被改写成整机连接成功。
- CAT 新配置和 `from_document()` 缺字段合并使用 38400 baud，CAT 仍支持 4800、9600、19200、38400、115200。磁盘配置的严格 shape 检查仍要求 `devices.cat_baud_rate` 存在；已存配置缺该字段会作为不完整配置拒绝并保留原文件。HRI 串口仍使用 115200、8N1。
- 音频端点切换命令在当前媒体占用时最多等待 30 秒，待音频路由空闲后再验证并切换；超时或停机时明确失败。切换成功后 Snapshot 发布实际 HRI COM、WaveIn/WaveOut endpoint ID 与端点 revision。若旧 WaveOut 报告清理失败但句柄已关闭，快照和配置仍切到已打开的新设备，并向界面报告清理警告；若旧句柄仍打开则保留旧路由。
- RX/TX meter 发布最近 200 ms、增益处理后 PCM 的归一化峰值（0–1），削波样本计数仍保留累计值。

## CAT 读回与编辑控件联动增补（2026-11-04）

- CAT 服务只把本次 CAT 结果明确确认过的 MAIN 模式、频率和 PC 功率控制值发布为新观测。普通的连接、忙碌或错误状态沿用 `CatState.revision`；只有接受了可信读回或使旧读数失效时，才递增独立的 `CatState.observed_revision`。
- ViewModel 在构造时同步已有可信读数，之后只在 `observed_revision` 改变时更新模式、频率和功率控件。频率用 MHz 十进制显示，最多保留 1 Hz 精度；功率仅匹配 5、10、15、25、50 W 档位。没有读数或功率不属于这些档位时，控件保持未选择，不代填默认功率。
- `CatForm::power_index` 默认 `-1`。CAT 断开或身份不符时清空可信读回并更新观测版本；干净控件回到未知，仍在编辑或有用户草稿的字段保留当前内容。重连成功并完成可信只读查询后，干净控件再显示新值。查询失败不会以响应中的未确认值覆盖表单。
- UI 每帧报告控件是否仍处于编辑状态，值改变时标记该字段为用户草稿。异步 CAT 读回跳过正在编辑或仍为草稿的字段。Apply 成功后，仅清除本次确实提交、且提交后没有再次改动的字段草稿，再从服务状态同步确认值；Apply 失败不清草稿，也不覆盖控件。
- 查询失败会保留最近一次可信读数并更新错误状态，不把失败响应携带的部分值当成新鲜数据。若电台 ID 不匹配，服务会清除旧观测并递增观测版本，未编辑的表单字段随之回到未知状态。CAT 功率写操作虽被拒绝，但若服务确认完成只读回读且串口正常关闭，可以更新实际读回的功率档位。
- 频率输入框为空时沿用既有 service 语义：Apply 不提交频率。UI 仍需对 mode 和 power 都有有效选择后才允许 Apply；不可把未知功率钳成任一档位。

验证：`pwsh -NoLogo -NoProfile -File tools/build-app-tests.ps1` 全部通过，0 warning。`gui_cat_form_sync_test` 通过 22 项检查，覆盖初始未知、模式/频率/功率映射、断开清除可信读数、用户草稿保护、重连后新读回、提交后再次编辑的版本保护、失败查询不更新读数、身份不符使旧读数失效，以及已关闭串口的拒绝功率操作仍可采用其确认读回。测试使用纯数据和 fake 结果，没有打开实体串口或连接电台。

## BM-only 来话、本地播放与 HRI 诊断增补（2026-11-05）

- BM 收到有效 DMRD 来话后，即使 HRI 电台未连接，Engine 仍会处理来话、发布活动呼叫和通话历史。用户选择的 WaveOut 可用时，解码后的 PCM 送往该本机输出播放；这一路径不打开 HRI 串口，也不发送 HRI T3/T0 或电台命令。
- 本地 WaveOut 未能唯一解析、打开失败、提交 PCM 失败或设备丢失时，Engine 保留网络来话和通话历史。不可播放的 PCM 会被有界静默排空并确认，BM 运行状态不因本机输出故障退出；快照保留本地音频错误，后续重新选择可用输出可恢复播放。Auto 只接受唯一解析结果；需要时可明确选择电脑扬声器，不会在多个候选中任意挑选。
- HRI 会话异常停止时，`radio_error` 记录具体停止原因，例如版本/模板/记录确认超时、串口写入或传输失败。快照的 `hri_t3_record_observed`、`hri_t0_record_observed` 只在 Engine 观察到对应 HRI T 记录后置位。对仍被隔离的 WaveOut，只有 T0 已确认、pipeline 中排队及未确认 PCM 都为零，且输出设备报告已排空或关闭，才释放来话 Router 占用；如果句柄状态仍不确定，则继续跟踪句柄、阻止播放并保留错误，避免把未完成的电台清理当成成功。
- `tests/engine_test.cpp` 使用 fake Master、FakeSerial 和 FakeWaveOut 覆盖 BM-only 来话/重连、输出不可用仍显示并排空、PCM 提交失败仍保留来话，以及 HRI-ready 时 WaveOut 被隔离的首通和后续 DMRD 呼叫。FakeSerial 回送 T3/T0 记录，测试检查 Engine 快照的实际观察标志、queued/inflight PCM 与设备 drain 门控、Router lease 释放和停机清理。健康 HRI/PCM/T0 顺序由 `tests/bm_bridge_loopback_test.cpp` 的假 Master、pipeline 和 HRI stream session 集成用例验证；它没有实例化 Engine 或打开 WinMM WaveOut。部分端点切换后的 PTT 输入与快照由独立 Engine 用例验证。
