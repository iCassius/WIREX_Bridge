# R129 启动组呼自动激活

## 行为

ViewModel 创建时冻结配置中已保存的频道顺序。BM 第一次进入 `connected` 后，本次进程启动一次性按此顺序发送组呼 Quick Call。首次 BM 连接之前不设超时、不发送任何 Quick Call；状态持续显示等待首次连接。运行期间后来添加的频道不加入队列；BM 重连只继续尚未处理的队列项，不重发已经完成的项。

启动触发只看 BM link，不等待电台/HRI `ready`；Engine 仍要求 BM transport ready、TX/RX pipeline 与 router 空闲、HRI stream cleanup 空闲。BM-only 运行时 HRI 未连接，且这些 Engine 条件满足时，队列仍可执行。

队列忽略私呼、TG4000、无效组呼目标，并将重复的 `(TG, TS)` 合并为一次发送。TG4000 是动态组断开控制，不能作为自动激活目标。静态组 API 不参与筛选；本功能遵循“自动激活所有已保存组呼频道”的配置语义，不读取或推断 BM 当前静态/动态订阅状态。

`accepted` 表示本机 Engine 已将 Quick Call 的两帧发到 UDP transport。它不表示 BM 服务端确认了动态组，也不表示已收到该组语音。发送失败和部分发送不会自动重发当前目标；Busy 在没有发送帧的前提下每 500 ms 重试，BM 保持连接且持续 Busy 达 30 秒后，当前及其余目标一起跳过。若 BM 断开，未处理队列无限期暂停，不计入 Busy 超时；同一进程内重连后继续。应用退出时队列结束；重新启动应用会根据当时保存的频道重新创建一次队列。

## 可见状态与限制

主界面状态应分别报告等待首次 BM 连接、正在本机发送、因 BM 断开而暂停、重连后续做和队列完成的计数。错误详情保留 Engine 的具体结果。任何状态都不得把本机 Quick Call 发送描述成“BM 已订阅”或“服务器已确认加入”。

## 验证与边界

最新 `pwsh -NoLogo -NoProfile -File tools/build-app-tests.ps1` 的 13 个测试目标全部通过、0 warning。`gui_startup_group_activation_test` 验证启动频道筛选、顺序、重复合并及忙碌/断线状态；`gui_startup_group_view_model_test` 验证首次 BM connected 后触发、无 HRI ready 仍可开始、同一时刻仅有一项 Quick Call、掉线暂停和重连续接。Native 离线回归的 41 个目标也全部通过。

以上检查使用纯状态机、fake Engine/Service 和 localhost 假 Master。没有连接真实 BM Master、CAT/HRI 串口、音频端点或电台，也没有进行 RF 验收。因此尚未证明服务端确认动态组、BM 语音确实到达或电台实际发射。
