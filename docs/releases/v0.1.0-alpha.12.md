# WIREX Bridge v0.1.0-alpha.12 本机测试版

alpha.12 在现有 DIRECT 桥接界面中加入 FTX-1 CAT-1 查询和设置。用户可查询 ID、TX 状态、MAIN/SUB 频率、无线机模式与功率控制值；可设置 MAIN 频率、无线机模式及 CAT PC 功率控制值。FM、FM-N、C4FM-DN、C4FM-VW 分开显示。

每次 CAT 操作使用一个短时串口会话并核对 ID0840。写操作还要求 TX0，最多发送一条设置命令，之后必须精确读回；超时或读回不符时不自动重发。修改 MAIN 频率或无线机模式时，UI 会停止核心并在设置后保持断开；功率设置则要求最近 3 秒内核心状态空闲、无活动通话、接收媒体空闲或已过滤且接收队列为空。CAT 模块在写入前仍会重新核对 ID/TX 状态。PC 表示无线机功率控制设置，不是射频输出测量值。HRI MODE 与 WIRES-X Node Mode 没有本版可用的公开 CAT 命令，界面不提供自动开关，也不发送猜测的 EX 地址。

CAT-1 模块使用固定串口角色和显式端口，不按 COM 数字判断它是否为 CAT。UI 保存的 radio-control-preferences.json 位于本机用户配置目录；打开设置窗不会创建该文件，只有点击保存设置才会写入。初始偏好为 COM11、38400/8N2、期望功率 25 W。应用不会在启动、查询或保存偏好时自动发送该期望值；写入前仍须读取当前 PC 路径及可用上限。

R113 的 RadioID 缓存与后续 callStart 呼号写出继续保留。Native 只将缓存呼号写进既有 mode-4 T90 SrcCallSign 字段；这个记录不证明 FTX-1 LCD 已显示呼号。本轮将 LCD 降为独立实验方向，不作为 alpha.12 主线功能。用户在 DIRECT/HRI 检查中观察到 LCD 没有来话或列表内容，底部软键无响应，红色指示灯行为与 Bridge 环境相同。没有据此推断灯的底层含义，也没有为 LCD 增加成功状态。

## 证据与验收范围

- 官方 CAT 命令和值域按 FTX-1 CAT 手册核对。软件 CAT fake 测试在 PowerShell 7 和 Windows PowerShell 5.1 各通过 52 项断言；测试注入 SerialPort-like fake，没有打开真实串口。
- 根会话另有一次 COM11、38400/8N2 的只读观察：ID0840、MAIN 模式 MD04、功率路径 2 / 25 W、TX0。串口已关闭，CAT 设置写入为 0。该快照没有验证 CAT 写操作、射频输出或 HRI 音频行为。
- 随后根会话用 Windows PowerShell 5.1.26100.8737 在 COM11、38400/8N2 完成另一次 CAT 查询：来源字符串 `FTX-1 CAT-1`、ID0840、MAIN FM、SPA-1 路径设定 25 W，FA/FB 查询均读回；清理状态 `closed`、错误 `null`、CAT 配置写入 0。FA/FB 具体频率值未记录。此次观察没有执行设置命令，也没有验证射频输出、HRI 服务切换或 LCD 内容。
- `tools/test-ui-radio-cat.ps1` 对真实 WPF 控件与 fake callback 生命周期的检查在 PS5 STA、PS7 STA 通过，根会话 Windows PowerShell 5.1 独立运行退出码 0。RenderOnly 两种窗口尺寸、缺少模块和坏偏好文件测试通过并经根会话视检；现有 UI status/lifecycle 检查通过，局部依赖 stub 没有放宽 status 断言。独立审查与修复后复审通过，没有 P1/P2 阻塞。
- 发行下载器离线测试通过 1783 项断言；发布器离线预检通过 109 项断言，未调用 GitHub 网络或凭据。
- alpha.12 profile 沿用 alpha.11 完整 40 项 Native 测试顺序。当前记录没有 alpha.12 clean build、本机测试包目录或 Windows PowerShell 5.1 包启动验收；本轮没有执行电台 CAT 设置命令。上述打包验收仍须完成后才能填写结果。

没有创建 ZIP、Git tag 或 GitHub Release。
