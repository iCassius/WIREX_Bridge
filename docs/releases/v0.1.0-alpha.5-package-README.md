# WIREX Bridge v0.1.0-alpha.5（R106 第1步测试版）

本目录是 alpha.5 独立便携测试包。请将它与 alpha.4 放在不同目录；alpha.5 不会替换 alpha.4 文件或启动入口。

## 无设备协议诊断

双击 `test-control.cmd`。脚本会启动本目录的 `wirex_bridge.exe`，通过匿名 stdin/stdout 管道完成 IPC v2 的 ready、hello、status 和 shutdown 检查，并输出结果及退出码。此检查不需要电台、串口、音频设备、BrandMeister 账号或网络连接。

## 配置迁移和主界面

旧用户配置的 `schema_version: 1` 读取后会迁移到 `schema_version: 2` 模型；单路接收配置保留旧版选择。保存新配置前会备份旧文件，再以原子替换更新目标文件；读取配置不会写入磁盘。音量设置仍使用独立的 `schema_version: 1` 文件。

迁移有一项明确限制：旧 schema 1 私呼接收目标必须等于连接的 `source_id`。若旧文件显式设置了其他私呼目标，程序会拒绝迁移并提示修正，不会把该目标改成 `source_id`，也不会写回原文件。请先在独立测试目录中修正副本。

主界面配置迁移请双击 `start-step1-test.cmd`。通用包完成 manifest 审计后，本机交付流程会把已批准的 `connection-profile.json`、`audio-settings.json` 和 `password-file-path.txt` 副本放入本包的 `private/r106-step1-test-config`。`password-file-path.txt` 只引用原密码文件的绝对路径；不会复制或读取密码文件内容。通用 manifest 包不含这些个人文件。启动脚本显式使用这个独立目录，不会探测或复制其他配置；无需手工编辑 JSON。配置字段与 `Selected` 单路兼容规则见 `docs/R106_配置迁移与测试.md`，IPC v2 消息及退出语义见 `docs/R106_IPC第二版.md`。

这一步没有多组接收策略编辑器或运行功能。读取复杂 schema 2 策略时，主界面只读展示摘要；保存其他设置时完整保留这些策略。若策略不能无损转换成旧核心支持的单路接收参数，程序必须在启动核心前报告不支持并拒绝启动。用户无需手动修改 JSON 来执行本步骤验收。

## 本版状态

本测试版只覆盖 IPC v2 的 hello/status/shutdown 和配置 schema 迁移。原来的 v1 Q/EOF 停止协议保留为默认兼容路径。离线构建测试清单为 36 项：alpha.4 原有 35 项及 `ui_control_protocol_v2_test`；实际结果记录在 `build-provenance.json`。

本版没有多组运行时流水线、BM live API、quick-call 或新增的串口、音频、PTT、RF 联测结果。不要依据 UI 状态、`accepted` 回应或已保存的配置判断设备/网络连接成功。

不要复制或分享密码文件。个人配置副本仅供本机隔离测试，位于 `private/r106-step1-test-config`，不属于通用包清单，也不应分享；测试期间产生的日志留在本机。
