## 默认诊断入口修复与验证

修复前，`param` 默认值表达式使用 `$PSScriptRoot` 解析同目录 Native 文件，在 Windows PowerShell 5.1 的包内调用时发生参数绑定错误。修复后，未传 `-ExecutablePath` 时脚本正文才把路径解析到同目录的 `wirex_bridge.exe`。`test-package-release.ps1` 检查参数 AST 不再把 `$PSScriptRoot` 放在默认值中，并可对指定本地包执行真实入口集成检查。

Windows PowerShell 5.1 实际运行以下命令通过 252 项打包器离线断言，并启动包目录中的 `test-control.ps1`，没有传 `-ExecutablePath`：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\tools\test-package-release.ps1 `
    -ControlPackageDirectory .\build\releases\v0.1.0-alpha.5
```

包内 Native 诊断完成 `control_ready`、`hello`、`status`、`shutdown`，以退出码 0 结束；状态明确报告没有启动 BM、HRI、串口或音频。`test-control.cmd` 的成功窗口会显示 ASCII 提示并等待按键；`start-step1-test.cmd` 不会在成功启动 UI 后额外暂停。

根会话还通过包内 Native 文件完成 WPF `BridgeSupervisor` 的 `ready/hello/status/replay/shutdown/exit 0` 管道验收。此检查使用诊断参数，不加载个人 profile，不打开串口或音频，也不连接 BM 或其他网络。
