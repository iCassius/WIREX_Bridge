# WIREX Bridge v0.1.0-alpha.6 合并测试版

alpha6 合并了完整 schema 2 接收策略运行时和桌面运行页。它用于本机合并测试；串口、音频、BrandMeister、PTT 与 RF 的受控联测仍需单独完成。

## 启动和初次设置

双击 `start-merged-test.cmd` 打开本包 UI。该入口把本次测试配置保存到 `private/r108-merged-test-config`，与 alpha5 测试目录和通用用户配置目录分开。入口沿用正常启动和自动连接流程。

首次启动或需要补全设置时，在单独的“连接、路由与音量设置”窗口填写连接信息，并从设备列表选择 HRI 串口、音频输入和输出。可点击“刷新设备”重新枚举设备。用“选择文件”指定本机已有的 BM 密码文件，再点击“保存设置”。配置由 UI 读写；不需要手工编辑 JSON，也不需要把密码内容复制进测试目录。

## 运行页

主窗口的运行页显示核心、FTX-1/HRI Direct、音频和 BrandMeister 的本次运行状态。状态来自核心报告；报告尚未到达或已过期时会显示未知或等待，不根据已保存的设置推断连接成功。HRI 状态区分别显示串口和 HRI 是否打开、是否就绪，并显示本次运行的 HRI 来源标签。

页面会分别显示本机接收策略、“下一发射目标”和“当前发射目标”。下一发射目标供之后开始的发送使用；已经发出的发送仍保留自己的活动 lease，页面不会把新目标显示成正在进行的目标。页面也显示当前来话、核心观察到的来源和运行记录。

点击“停止并退出”会请求核心执行关闭流程并等待资源清理；使用窗口关闭按钮也会走停止流程。不要用任务管理器强制结束进程来代替正常关闭。

## 修改接收路由和发射目标

在“本机接收策略”中选择 `Selected`，只接收列表中的 TG/TS；选择 `AllDelivered`，接收已送达的组呼，再按 TG/TS 添加本机组呼屏蔽项。跨组来源屏蔽使用独立的 Source ID 列表；被屏蔽来源的呼叫不会因为组呼模式而放行。

私呼可选择关闭、只收指定 peer，或接收发往本机 Source ID 的私呼。精确 peer 项按对端 Source ID、本机 Source ID 和时隙匹配。`all_peers_to_local` 允许满足本机目的与时隙的私呼路由，精确 peer 项也可额外放行其对应 peer；两种规则按并集计算，跨组来源屏蔽仍优先生效。

发射目标与接收策略分别设置。点击“设为下一发射目标”应用新 TX 目标和发射许可。运行中的 RX 策略和 TX 目标经核心确认后立即生效；UI 等待确认期间会保留最近一次已确认状态。收到确认后，UI 把运行值保存到本机连接配置。连接参数、设备选择和音量设置保存后用于下次连接。

所有这些操作都通过 UI 控件完成，不要求修改配置文件。`TG91` 和 `TG46001` 是只收组呼目标，不能设为允许发射的组呼目标。

## 独立协议诊断

双击 `test-control.cmd` 可检查本包 native 的 `ready`、`hello`、`status` 和 `shutdown` 控制管道往返以及进程退出码。此诊断不打开电台、串口或音频设备，也不连接 BrandMeister 或其它网络服务。绿色包不要求安装源码测试或编译环境。

## 验收范围

alpha6 源码验收按固定顺序运行 39 项 C++ 离线测试；最终构建 provenance 和 package manifest 记录本次实际结果。UI、配置迁移、launcher 和协议测试分别记录。离线结果不记录串口、音频、BrandMeister、PTT 或 RF 的真实设备行为；这些项目需在包和本机配置完成审计后另行安排受控联测。
