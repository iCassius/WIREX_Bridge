# WIREX Bridge v0.1.0-alpha.6 合并测试版

alpha6 将 R108 完整接收路由策略接入 native，并合并桌面运行页、设置窗口和隔离的本机测试入口。本文记录当前实现范围与后续验收步骤；不作为已完成构建或实机联测的证明。

## 当前功能

- 手工 profile 启动时，launcher 在独立运行目录写入 `routing-state.json`。文件保留完整 schema 2 RX 策略、独立 TX 目标和发射许可；Native 在打开设备前校验文件和 CLI 连接字段。
- 桌面设置窗口可编辑 Selected/AllDelivered 组呼接收策略、按 TG/TS 屏蔽组呼、按 Source ID 屏蔽来源，并配置指定私呼 peer 和发往本机的私呼路由。组呼来源屏蔽独立于组呼路由，私呼的两种允许规则按各自策略处理，来源屏蔽优先。
- 运行页依据本次核心报告显示核心、FTX-1/HRI、音频和 BrandMeister 状态，并分开显示 RX 策略、下一发射目标与当前活动 TX lease。未收到或已过期的核心状态会保留为未知或过期状态。
- 运行期间更改 RX 策略或下一发射目标时，UI 向核心提交带预期 revision 的替换请求；界面在收到核心确认后更新活动状态并保存到本机 profile。请求未确认时，不把草稿显示成已经生效。连接字段、设备选择和音量设置保存后用于下一次连接。
- “停止并退出”和窗口关闭流程会向核心请求停止，并等待进程清理设备资源。
- `start-merged-test.cmd` 使用 `private/r108-merged-test-config` 启动本包 UI。它保留正常启动与自动连接流程，配置与 alpha5 测试目录及通用个人配置分开。`test-control.cmd` 仍是独立的本地 IPC 诊断入口。

UI 保存连接、路由和音量设置时不要求编辑 JSON。alpha6 不加入 BrandMeister 订阅 API 或 QuickCall 功能。

## 兼容与测试记录

alpha1 至 alpha5 的历史 profile、文件清单和测试顺序保持原样。alpha6 profile 在 alpha5 清单上增加 R108 技术文档与合并测试入口。源码构建验收计划按固定 builder 顺序运行 39 项 C++ 离线测试；实际数量、顺序与每项结果要在最终构建后由 provenance 和绿色目录 manifest 记录，本文不预记为已通过。

Launcher、profile 迁移、Native routing、UI preparation、控制协议和 package inventory 检查分别记录结果。离线检查不验证真实 HRI Direct 通讯、串口自动匹配、音频播放/采集、BrandMeister 登录和来话、PTT 或 RF。

## 下一步联测

完成源码审查后，先执行最终 clean build 和固定 39 项 C++ 测试，再生成绿色目录并审计 manifest。manifest 审计通过后，才把 `connection-profile.json`、`audio-settings.json` 和只含既有绝对密码文件路径的 `password-file-path.txt` 放入隔离配置目录；密码内容不复制到绿色包。

随后在受控本机环境用 `start-merged-test.cmd` 验证设置保存、HRI Direct 状态报告、实际串口与 USB 音频选择、BM 连接与音频通路、当前来话和 TX lease 状态、运行时 RX/TX 策略确认以及正常停止退出。每项结果应分别记录；在这些步骤完成前，不对本机设备或 RF 行为作通过声明。
