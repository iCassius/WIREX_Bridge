# WIREX Bridge v0.1.0-alpha.7 合并测试版

alpha.7 包含 R109 动态组控制和无语音下行收尾切片，供本机合并测试。本文说明预期功能范围；实际源码测试、包审计和设备行为以各自的验收记录为准。

## 启动和配置

双击 `start-merged-test.cmd` 启动本包 UI。alpha.7 入口把设置保存在 `private/r109-merged-test-config`，与 alpha.6 的 `private/r108-merged-test-config`、alpha.5 测试配置目录及通用 `private/user-config` 分开。入口沿用正常启动和自动连接流程。

首次连接或需要调整设置时，使用独立设置窗口填写连接信息、选择 HRI 串口和音频输入/输出设备，再保存设置。发布包通用 manifest 不包含个人连接配置；如本机合并测试需要已有设置，应在包 manifest 审计后再单独准备。`password-file-path.txt` 仅保存现有密码文件路径，密码文件内容不复制进通用包。

## 动态组控制

运行页的“动态组控制”区域接受组呼 TG（1 至 16777215）和 TS1/TS2。两个按钮执行不同操作：

- “加入本机收听”只请求核心把 TG/TS 加入本机接收 allow 规则，不发送 BM 动态组激活包。
- “激活动态组”只请求核心发送一次无语音 Quick Call：一个 header 和一个 EOT。它不打开语音发射许可，也不自动修改本机 RX allow 规则。需要接收该组时，还要将该 TG/TS 加入本机收听规则。

只有核心报告本次运行的控制能力可用、BrandMeister 状态为 ready 且呼叫资源空闲时，激活操作才可用。界面按核心返回结果显示已发送、被拒绝或未完整发送；超时或结果未确认时不会自动重发。TG4000 用于断开动态组，不可作为激活目标。TG91 与 TG46001 禁止作为语音发射目标，但仍可使用“激活动态组”按钮发送一次无语音 Quick Call（一个 header 和一个 EOT）；此激活不会打开语音发射许可。

## 下行空语音收尾

下行呼叫获准后，核心等待有效语音 burst 成功进入接收媒体管线后才启动 HRI T3。若呼叫没有语音并先以 EOT 或接收 watchdog 结束，核心跳过 T3，并由现有取消流程清理接收资源。运行记录分别包含 `rx_call_end_reason`、`rx_call_missing_packets` 和 `rx_call_accepted_voice_bursts`。

这个切片只处理尚未接收任何有效语音的呼叫结束路径。它没有确认 TG91 所有中断的原因，也没有修复或解释红色 LED；较早的 `local-hri-downlink-0304eff` 也曾出现红灯。不要依据离线测试或 T3/T0 记录推断实际 LED、HRI 发射或 RF 状态。

## 状态与诊断边界

运行页从本次核心报告读取核心、FTX-1/HRI、音频、BrandMeister、路由和当前呼叫状态。尚未收到或已过期的报告会显示未知或过期状态，不根据保存的设置推断连接成功。

`test-control.cmd` 是独立的本地 IPC 诊断入口，只检查本包 native 的 ready、hello、status、shutdown 往返和退出码；它不枚举串口或音频设备，也不连接 BrandMeister。alpha.7 固定 C++ 测试仍按 alpha.6 的 39 项顺序记录；本地正式构建结果以最终 build provenance 和包 manifest 为准。

离线测试不覆盖真实串口、音频输入输出、BrandMeister 网络连接、PTT、LED 或 RF。需要设备联测时应按受控计划逐项记录结果。
