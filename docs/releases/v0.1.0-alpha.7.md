# WIREX Bridge v0.1.0-alpha.7 交付说明

alpha.7 汇总 R109 动态组控制与无语音下行收尾切片，供后续本机合并测试。此文档和发布 profile 说明目标范围，不证明 alpha.7 已完成构建或硬件验收。

## 本次范围

- 运行页提供动态 TG 输入，以及“加入本机收听”和“激活动态组”两个独立操作。前者只更新本机 RX allow 规则；后者在核心和 BM 就绪、呼叫资源空闲且目标合法时发送一次无语音 Quick Call（一个 header 和一个 EOT），不会授予语音发射许可。TG4000 是断开控制命令，不能作为激活目标。
- 下行呼叫获准后，核心等待首个有效语音 burst 成功进入接收管线，再启动 HRI T3。仅有 header、在收到语音前以 EOT 或接收 watchdog 结束的呼叫会跳过 T3，并沿用现有取消与音频清理流程。
- 结构化运行日志记录下行结束原因、缺包数和本次接收代接受的语音 burst 数，便于区分结束方式和实际进入媒体管线的语音量。

alpha.7 沿用 alpha.6 固定的 39 项 C++ 测试名称和顺序；本次测试结果须以之后获准执行的 clean build provenance 与包清单为准。发布包 profile 增加两份 R109 技术说明，并把本机入口配置目录映射到 `private/r109-merged-test-config`。`include/wirex/quick_call.hpp` 是源码构建输入，不属于运行包文件清单。

## 已知未解决项

- 红色 LED 没有在 R109 中修复或解释。用户对更早的 `local-hri-downlink-0304eff` 也观察到红灯，因此不能把它归因于 alpha.6，也不能从 R109 的离线结果推断 LED、实际 HRI 发射或 RF 状态。
- TG91 的所有中断原因仍未查明。无语音呼叫收尾只覆盖文档所述的一种情况，不能宣称它修复了所有 TG91 中断。
- 串口、音频设备、BrandMeister 实际连接、PTT 和 RF 行为都没有由本次离线证据验收。

## 交付与后续验收

alpha.1 至 alpha.6 的既有发布 profile 保持原样。alpha.7 的个人配置仍应在通用包 manifest 审计通过后，单独放入本机隔离配置目录；密码文件内容不进入通用包。未完成源码审查、授权 clean build、39 项测试及绿色目录 manifest 审计前，不把候选描述为已验收。设备联测须另行安排受控流程。
