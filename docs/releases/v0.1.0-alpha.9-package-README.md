# WIREX Bridge v0.1.0-alpha.9

## 启动与本机设置

双击包根目录唯一的 `start-wirex-bridge.cmd`。没有本机配置目录指针时，连接、音量、频道收藏和 RadioID 缓存使用包内 `private/user-config`；需要多个版本共用设置时，可在 `private/user-config-directory.txt` 写入一行 canonical `UserConfigDirectory` 的绝对路径。该个人指针、个人配置、`channel-favorites.json`、RadioID 缓存和密码路径都不属于通用包。

## 收听与起呼目标

“加入本机收听”和“起呼目标”是独立控制。A 项选择本机允许收听的路由，并显示最近 50 条真实通话记录；B 项选择起呼目标。B 区将内置预设、本机 RX `allow_groups`、用户手动输入的 TG/TS、明确选择的历史项，以及本机频道收藏分别标出来源。收藏保存在当前 `UserConfigDirectory/channel-favorites.json`；`normal`、`dynamic`、`static` 只整理本机收藏，软件不会因这些标签创建或修改 BM 服务器订阅。当前 UI 没有 BM 静态订阅 readback，不显示伪造的“静态已订阅”条目。每条本机路由保留自己的 DMR 时隙设置。

TS1/TS2 是软件路由与起呼目标的时隙选择字段。当前 `bm_session.Profile.slot_flags` 默认值及网络 metadata 都是 `4`（simplex）；这不表示 FTX-1 提供 DMR 双时隙 RF，也不表示程序能同时播放两个时隙。Color Code 是高级 DMR 发射编码/上报参数，不是 C4FM DG-ID；本机接收路由不按 CC 过滤。多个收听路由只是本机允许接收的集合，不构成播放优先级。当前单一媒体播放会话正在处理来话时，后来的流不会插队、延后补播或自动抢断。

动态组 Quick Call 会发送无语音的组呼控制帧。openSPOT3 手册说明这类 empty call 会出现在 BrandMeister Dashboard；本机用户也观察到网页记录。其他 DMR 终端如何展示仍未知。没有声称存在静默添加动态组的官方 REST 操作，也没有声称 UI 能读取 BM 静态订阅配置。

## 资料查询和显示边界

RadioID 查询只在用户点击“查询资料”时按单个 DMR ID 发起；来话与音频处理不会自动请求网络。有限缓存保存于当前 `UserConfigDirectory/radio-identity-cache.json`，过期资料标为旧资料，失败时保留数字 DMR ID。呼号来源于 RadioID 匹配，不是设备身份认证。缓存和两个 RadioID 离线/HTTP 测试脚本均不放入通用包。

官方 HRI 静态记录定位了一个 10 字节 `Src CallSign` 字段。Bridge 可将用户查询到的呼号作为显示路径候选；当前 FTX-1 屏幕上的实际内容仍未知。FTX-1 机身 BUSY/TX LED 沿用既有行为，本版本没有更改 LED 或串口控制。

## 音量与验收范围

alpha.8 已有音量滑块。alpha.8 的 TG91 用户反馈为正常但略小；对应本机运行记录显示有效 RX 增益为 1.000x、clipped samples 为 0，而保存配置为 5.959x。alpha.9 在状态卡和设置页分别显示运行时实际增益、保存值与削波计数，并提示修改后需要重连才能生效。界面显示改进不能代替新版本的实机听音确认。

离线构建、页面预览、mock RadioID 查询及包检查不连接 COM、音频设备或 BrandMeister，不触发 PTT，也不验证 FTX-1 LCD、机身 LED 或 RF 行为。实际使用前请在受控条件下自行验证设备、音量与 RF 行为。
