## 优先级与验收

### P0：音量和 PCM 电平

- **当前实现：** 源码 `5e33433` 已允许独立设置 BM→电台回放增益和手咪→BM 发送增益，默认分别为 `1.0x` 和 `16x`，范围均为 `0.25x–16x`。`audio-settings.json` 只存 schema 版本和两项数值；启动器参数 `-RadioPlaybackGain` / `-MicTransmitGain` 覆盖并保存，后续启动恢复。TX 统计在 BM 语音管线接受样本后累计，RX 统计在 WaveOut 成功排队后累计；无运行时热调。clean build、26 项测试和包审计通过。
- **缺口：** 新增的独立设置还没有通过实机听音验证。`005c5e8` 曾有一次清晰回声，但它不覆盖本次两路增益的分别调整、正常说话时的削顶或音量恢复。
- **下一步：** 用 TG91 测试电台回放增益；用 `parrot-cn` 测试手咪发送增益。每次只调整目标方向，通过参数保存后重新启动确认数值恢复，记录正常说话时的回声电平和削顶统计。
- **验收：** 默认值正确；边界内参数生效，越界输入被拒绝；覆盖值在下一次启动保留；正常音量讲话时用户确认回声清楚、音量合适，日志中的上行 `clipped_samples` 为 0。另用较高电平检查削顶统计能指出削顶，不把软件计数当成人耳结果。
- **设备配置 / 用户：** FTX-1 HRI ON、Node Mode DIRECT；确认 COM5 与 USB Audio 的 WaveIn/WaveOut 端点；使用 `parrot-cn` 460997 单呼。需要用户以正常手咪距离说话并评价回声音量；无需 RF 发射。

### P0：断网恢复与退出稳定性

- **当前实现：** `Session` 已实现 transport loss 后清 BM 应用队列、指数退避和重新登录；native `handle_network_loss` 会关闭 PTT gate、要求重新观察松开、取消 TX/RX/HRI 下行、清播放状态并关闭 WaveOut。正常停止在 BM 已 ready 时排队并尝试本机发送 `RPTCL`。离线测试已验证这些软件分支及旧播放完成通知不能污染新一代音频。
- **缺口：** 用户实机只通过了一次约半分钟的单通话闭环；真实长时间待机、BM 网络中断后恢复、断网时有媒体排队，以及 `Q` 在空闲/通话中的退出都未现场验证。
- **下一步：** 先用只收不发的 `listen-91` 做 30 分钟待机；然后各做一次空闲时断网恢复和接收播放期间断网恢复。最后分别在空闲和单通话期间按 `Q`。若测试私呼上行，只使用 `parrot-cn` 的 460997，不向 TG91/TG46001 发射。
- **验收：** 日志显示 ready 丢失后断开状态、重连次数和恢复 ready；断网后旧队列与旧播放回执不产生新声音；恢复后新通话正常开始/结束；手咪必须先松开再按下才能建立新上行。`Q` 在有界清理内退出，报告区分 T0/RPTCL 本机调用结果与电台/Master 是否确认；确认 COM/WinMM/native 进程已关闭。每次失败保留准确日志路径和故障现象。
- **设备配置 / 用户：** 只收测试用 HRI ON、DIRECT、TS2 TG91 静态订阅；Echo 恢复测试用 `parrot-cn` 460997。用户需手动安排短暂网络断开并恢复、观察回声及退出状态；不发 RF。

### P1：LCD 显示当前话者

- **当前实现：** BM 收包和 `CallConfig`/`ReceiveEvent` 能提供远端 Source ID、目标、呼叫类型、TS/CC；日志能记录最近一个已解码头。HRI DLL 的屏幕字段 serializer、消息发送窗口和 FTX-1 LCD 写入链尚未闭合。BM 事件当前没有远端呼号/TA；本机呼号不能代替远端话者。
- **缺口：** 还没有实现或验证 FTX-1 LCD 的呼号/TG/时隙显示、更新和清屏。不能仅凭 HRI PC DigiPanel 的 `Direct:ON/OFF` 文本推断电台显示字段。
- **下一步：** 基于已保存的 HRI DLL 证据，继续追踪 EXE 导出槽和 serializer 的调用关系至串口写入路径。若官方数据源没有远端呼号，先显示 Source ID，并将单 ID RadioID 查询作为可选后续；无查询结果时保留数字 ID。之后才实现消息并验证 call-start/update/end/disconnect 清屏。
- **验收：** 合成单元测试覆盖已知 ID 映射、未找到时数字回退、同一通话资料更新、通话结束/断线清除；使用一个已知 BM 呼叫检查真实 FTX-1 LCD 的当前话者、TG/TS 和清屏。不得拿演示快照或历史呼叫填当前显示。
- **设备配置 / 用户：** HRI ON，使用已确认可接收测试呼叫的 FTX-1 模式；当前屏幕 serializer 未确认前不发送新显示写入。需要用户提供一通可控的 TG91 或私呼接收观察并确认 LCD 文本。

### P1：会话启停与 DIRECT/RF 路由观察

- **当前实现：** 自动手咪 PTT、BM 上行、BM 私呼返回和 FTX-1 扬声器回放已通过一通 DIRECT 端到端闭环。HRI T3/T0 与下行播放完成顺序有离线测试；`radio_state` 仍保留 `unknown`，T3/T0 记录不作电台 ACK。
- **缺口：** 用户已确认 Node Mode 为 DIRECT，并确认 145.1 MHz RF 音频是在 Bridge 关闭后出现；尚未比较 Bridge 运行待机、下行播放和退出后的 RF 音频/S 表变化。S 表是否与已听到的 RF 音频同时出现仍未知。HRI `NDDIRECT` 尚未映射到三态 Node Mode，不能据该字段判断 Bridge 对 RF 路由的影响。
- **下一步：** 在相同 VFO、频率和 RF 设置下，对照 Bridge 关闭、Bridge 运行待机、单通 BM 下行和 Bridge `Q` 退出后的 RF 声音/S 表。已有 Node Mode 记录为 DIRECT；无需重新确认该项。记录每个阶段的时间和 VFO/频率，不发送模式写入。
- **验收：** 报告每个阶段的 Node Mode、VFO/频率、时间、RF 声音和 S 表观察，以及 BM 下行是否只在所选回放端点播放、结束后是否停止。若测试发现设备模式变化，记录具体变化和恢复结果；没有测量 RF 发射时不要声称“未发射”。
- **设备配置 / 用户：** FTX-1 HRI ON、Node Mode DIRECT；RF 接收测试使用用户选定的 145.1 MHz FM 已知信号，按本机当前合法接收条件设置。需要用户观察 Bridge 运行与退出前后的电台状态；本阶段不要求 RF 发射。

### P2：C4FM RF 节点

- **当前实现：** `listen-91` 是 BM 组呼的被动网络收听预设；`parrot-cn` DIRECT 个人终端走手咪上行和扬声器下行。两者均没有完成 C4FM 空中节点验收，不能将网络下行播放当作 RF 节点转发。
- **缺口：** FTX-1 C4FM RF 节点的收音到 BM 上行、BM 下行到 FTX-1 RF 发射的完整路径尚未验证；官方流程应选择 AP RADIO 还是 AP PC 仍待研究。目前只有 DIRECT 用途的一通实测闭环。
- **下一步：** 在 P0/P1 通过后，先依据官方流程确定 AP RADIO/AP PC 及相关节点设置，再冻结合法测试频率/功率、BM 目标/TS/CC、上行控制和超时策略；随后分开验证 RF→BM 与 BM→RF，避免回环或无界占台。
- **验收：** 以一台测试手持台发起一通受控 C4FM 呼叫，确认 BM 端呼叫头和音频；再验证 BM 下行时 FTX-1 按规定发射并在呼叫结束/超时后停止。检查呼叫类型、目标、TS/CC、尾部和再次呼叫门控，记录 RF 测量/观察，不用软件状态代替 RF 证据。
- **设备配置 / 用户：** 先按已查明的官方流程选择 AP RADIO 或 AP PC；当前不预设节点模式。用户指定合法频率、功率、目标和附近测试电台。涉及 RF 发射，需用户现场参与并在测试前明确确认具体范围。

### P2：配置持久化与 UI

- **当前实现：** native 提供 `parrot-cn`、`parrot-global`、`listen-46001`、`listen-91` 和逐项输入的 `manual`；launcher 可发现/选择 COM 与 WaveIn/WaveOut，并保存两项本机音量设置。native 控制台显示运行状态并写脱敏 JSONL。仓库内 PySide6 UI 与 HTML 预览只使用离线快照；没有核心 IPC、设备控制或真实状态适配。
- **缺口：** 固定预设覆盖有限的参数组合；`manual` 每次逐项输入，没有一般化的 Gateway/Master/TG/TS/CC/呼号与设备配置保存。除音量设置外，通用配置恢复尚未实现。运行状态和诊断已有 console/JSONL 来源，但 UI 不读取它们，也不监督 native 生命周期。
- **下一步：** UI 按用户决定推迟。待 P0/P1 稳定后，先由用户确定需要记住的非秘密配置；保留密码在现有 private 文件管理，不把凭据写入一般设置。之后再将 native 的真实 run 快照/有序事件接到 UI，并让 UI 只管理本次创建的一个核心进程。
- **验收：** 离线测试验证 profile 保存/加载、无效值提示、配置与本机凭据分离；UI 只在当前 run 收到有效状态时显示 ready，旧事件/旧 run 不覆盖新状态。停止按钮和窗口关闭走同一有界收尾，并等待本次 native 进程退出；演示数据始终明显标记为模拟。随后由用户确认实际设备发现、启动、状态和退出行为。
- **设备配置 / 用户：** 离线阶段无需硬件；确定要保存的 profile 字段需要用户选择。真机 UI 联测再用 HRI ON、DIRECT 与现有 `parrot-cn`/`listen-91` 配置，需要用户确认设备、音频端点及当前 run 状态。
