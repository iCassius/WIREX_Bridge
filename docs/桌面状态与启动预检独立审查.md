审查对象：当前工作树中的 `app/ui/windows/bridge-ui.ps1`、`app/src/probe_main.cpp`、`app/src/bm_udp.cpp`、`app/tools/bridge-user-config.psm1` 和 `app/tools/start-bm-radio-bridge.ps1`。代码审查时 HEAD 为 `d6a9eb35fc1184d4b9ba480c532d0e47d4429728`；桌面 UI 和部分配置文件仍有未提交改动，因此结论适用于本次审查的工作树快照。

审查状态：状态类型、时间戳与完整 `run_id` 修复已静态复核，并通过独立 Windows PowerShell 5.1 mock 回归（`tools/test-ui-status.ps1`，退出码 0）。该脚本不启动核心、设备或网络。当前字段校验与记录消费切片已闭合；新 native timestamp 字段与 UI 的集成验证仍待 root clean build 后在 COM999 失败路径执行。

## 已核对的状态行为

- native 每秒写一次 `runtime_snapshot`，状态记录携带递增 `seq`、`elapsed_ms` 和 UTC 毫秒时间戳（`probe_main.cpp:4559–4568, 5244, 5980–5982`）。UI 严格检查必需字段类型、枚举和数字范围；只接受子进程 PID 前缀匹配、完整 `run_id` 稳定且不早于当前时间 5 秒、不超过当前时间 3 秒的记录。重复或倒退的序号会被忽略；最近状态超过 3 秒后，BM、HRI、音频和电台状态改为未知；子进程退出后也会显示未知和退出码（`bridge-ui.ps1:223–270, 492–545, 611–624`）。
- `preflight_passed` 记录只确认音频端点通过格式检查；它的 HRI 状态仍为未打开、未就绪。UI 展示“端点已核验”，没有据此显示电台或 BM 已就绪（`probe_main.cpp:5028–5046`）。运行状态来自单独的状态字段。
- 当前工作树已修复两类状态误报：完整 `run_id` 在首条有效记录后锁定；布尔值和状态时间戳有严格类型检查，旧记录不能靠 UI 读取时刻伪装成新状态。`tools/test-ui-status.ps1` 覆盖字符串 `"false"`、错误时间戳、过期 ready、同 PID 不同完整 `run_id`、非法枚举，以及当前 run 的新状态正常更新；由本轮独立运行通过。

## 启动和退出边界

- native 在读取密码、创建状态文件和枚举音频端点前检查已排队的 Q/EOF；`run_bm_bridge` 在启动 BM session 前、以及打开串口前还会检查一次。早期预检实测中，预先排队的 Q 和 EOF 都以退出码 0 返回，未创建状态文件；非法 `T` 以退出码 2 拒绝。
- 打开串口后，应用设置了串口读写超时；预读串口输入最多运行 250 ms、最多丢弃 4096 字节。WaveIn/WaveOut 头清理每个头最多重试 20 次，每次间隔 5 ms。UDP socket 设为非阻塞，接收等待上限为 100 ms，native 收尾 deadline 为 3 秒（`probe_main.cpp:568–600, 823–853, 1110–1148, 5195–5216, 4001, 5763, 6368`；`bm_udp.cpp:47–84, 112–128`）。
- 最后一次启动前 Q/EOF 检查位于串口打开之前。若 Q 在这次检查之后才到达，代码可能先打开串口、完成预读并打开 UDP socket，再在主循环响应 Q。该竞态不改变“Q 到达后进入有界收尾”的行为，但启动入口不承诺跨进程启动瞬间完全不打开设备或 socket。
- 代码没有给 `CreateFileW`、WinMM 的实际 `waveInOpen`/`waveOutOpen` 调用设置调用级超时；串口超时和 UDP 非阻塞设置不能限制驱动打开调用的耗时。桌面 Supervisor 在后台等待 5 秒；届时关闭本次启动拥有的 Job，再等 1 秒，必要时调用 `TerminateProcess` 并最多再等 1 秒。这个机制可收回 UI 自己启动的核心进程，但不会给 Windows 驱动调用本身设置时限。静态审查没有发现应用控制的同步等待超过 5 秒，也没有运行证据显示驱动调用会超过 5 秒。
- 用安全的 `COM999` 失败路径、临时合成密码文件和已枚举端点做过 CreateNoWindow 集成检查：先写入 `preflight_passed`，随后以 `serial_open_or_configure_failed` 退出；没有打开 UDP、HRI 或音频流，状态行没有包含合成密码。测试材料位于 ignored 的 `app/build/_work/ui-pipe-no-console-audit-20261025-164449/`。没有启动真实 COM、BM 或电台。
- UI 每次运行在本机配置目录 `ui-runs/<GUID>/` 新建 `connection-profile.json`、`preparation.json` 和 `status.jsonl`；native 每秒追加状态，当前没有自动轮转或清理旧 run 目录。长时间使用会积累本机状态文件；这属于 alpha.2 后续维护项，不阻塞当前功能验收。本轮未读取状态日志，未测量单行或目录实际大小。

## 配置复核

桌面模块和 launcher 的 profile schema 与约束一致：只接受已知字段，拒绝重复 JSON key、未知字段、非整数 ID、越界值、无效 master、COM1–COM999 以外端口及缺失 endpoint。写入方在同目录写临时文件，再用 `File.Replace` 或 `File.Move` 替换；launcher 加载后重新校验。未发现二者当前有字段或范围语义差异。`PrepareOnly` 写入运行参数文件后由 UI 启动核心；参数包含密码文件路径，不包含密码文本。
