# 本机配置与桌面操作

alpha.2 已正式发布。后续启动修复保存在本机开发候选目录；alpha.1 与 alpha.2 的发布文件保持原样。

## 启动

在便携目录根目录双击 `start-ui.cmd`。如果连接资料或 BM 密码文件尚未选择，界面会打开“设置”。填写连接资料、选择密码文件并保存后，界面会开始连接。

连接配置记录呼号、Gateway ID、Source ID、Master、端口、目标 ID、时隙、Color Code 和呼叫类型。串口 `auto` 优先选择已确认的 HRI COM5，其次选择唯一 HRI 串口；音频 `auto` 只在唯一 USB Audio 端点出现时自动选择。没有 USB Audio 或存在多个候选时，请在“设置”中明确选择设备。已保存的稳定音频端点仍存在时会优先恢复；端点缺失时会显示缺失提示，不会换用电脑麦克风或扬声器。

主界面目标菜单提供中国鹦鹉私呼、TG91 收听、TG46001 收听和保存目标。选择新目标后按“切换目标”重新连接；运行会话中的目标仍显示当前核心实际使用的目标。TG91 和 TG46001 按接收模式运行。

## 用户配置和音量

桌面配置默认保存在便携目录的 `private/user-config`。若使用跨版本入口，可用 `-UserConfigDirectory` 指定同一个外部目录；`bridge-directory.txt` 选择当前便携版本。`connection-profile.json` 保存连接参数和稳定设备标识，`audio-settings.json` 保存两路增益，`password-file-path.txt` 只记录 BM 密码文件路径。

桌面启动器传入 `PackageDirectory` 时，本次启动使用该便携目录里的核心和启动脚本；没有传入时才读取 `bridge-directory.txt`。跨版本入口先读取该指针，再启动选中的便携目录。

“设置”中的电台播放增益控制 BM 音频送到电台扬声器的音量，手咪发送增益控制手咪上行音量。范围为 0.25x–16x，默认分别为 1x 和 16x；保存后在下次连接时生效。密码正文保留在所选本机文件中。

设置文件只适合在本机保存。不要将个人连接配置、密码文件或 `private/user-config` 分享给他人。

## 状态与退出

核心、HRI 串口、HRI 握手、音频输入/输出流和 BM 连接分别显示核心报告的状态。电台 RF 状态保持“未知”，因为核心不读取该状态。最近来话区域显示最近一次收到的呼叫头信息。

状态报告超过 3 秒未更新时，界面将设备和连接状态标为未知；运行核心退出后立即清除本次连接状态。界面只接受当前运行进程的递增状态序号，并忽略字段类型错误、其他运行会话或时间戳过期的记录。

使用“停止并退出”或关闭窗口结束程序。界面请求核心停止并等待其完成收尾；核心只接受 UI 的 Q 换行或管道关闭作为停止请求。停止过程中不启动第二个核心进程。

## 离线界面验收

仓库维护者可用 Windows PowerShell 5.1 运行以下命令，生成主界面和设置窗口截图并检查 1024×728 小工作区布局。测试使用空白临时配置和 `OfflinePreview`，不会启动 native 核心或访问设备：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\tools\test-ui-render.ps1 -PackageDirectory .\build\releases\v0.1.0-alpha.1
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\tools\test-ui-status.ps1
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\tools\test-ui-lifecycle.ps1
```

## 本机启动修复候选

用户在 alpha.2 启动界面看到“设备预检返回的启动参数不完整”。启动器为每次运行生成独立目录和 `status.jsonl`，界面先前仍按另一条固定路径核验状态文件，路径不同导致界面拒绝启动。现在界面验证状态文件位于本次运行目录内、扩展名为 `.jsonl`，并与唯一的 `--status-file` 参数一致；界面还核验本次 native 可执行文件路径。

设备列表、稳定音频 endpoint 选择、0.25–16 倍增益滑块和便携目录优先规则已更新。显式传入便携目录时，界面使用该目录的 native 核心和启动脚本；跨版本入口先读取本机版本指针，再显式启动所选目录。

本机候选目录：`build/candidates/startup-fix-62b045f`。native 来自 clean 构建提交 `62b045fbe6fae49e17d5c48750111e699b54513f`，29 项离线测试全部通过；WPF 与启动选择修复来自提交 `a995c3c57478d36b99238776eba46dd2f4384686`。候选共 23 个文件，候选清单 SHA256 为 `74df632445e4232ffa1aae9adf67261dcb8fdad2eb7c3668810c53f8308a128d`。候选使用外部 `app/private/user-config`，不包含用户连接配置、密码文件或运行日志；候选启动入口默认只打开界面，不自动连接。

候选 Windows PowerShell 5.1 检查已通过：启动版本选择测试、主界面和设置窗口 render、真实 PrepareOnly 参数生成与 UI 校验。检查没有启动 native 核心，也没有打开串口、音频流或 BM 连接。候选尚未进行新的完整实机验收；正式下个 Release 仍需完成 LCD 菜单和 RF 模式功能接入。
