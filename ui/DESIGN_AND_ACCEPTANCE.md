# UI 设计与验收记录

## 范围与依据

本切片只实现屏幕、不可变离线状态和固定演示快照。已确认的单页深色面板、独立设置窗口、“停止并退出”以及未来按上次配置尝试连接等选择，来自用户确认；核心状态与生命周期边界参考外层项目的 [绿色运行与退出生命周期](../../docs/14_绿色运行与退出生命周期.md) 和 [UI 与核心状态契约](../../docs/15_UI与核心状态契约.md)。两份文件定义的是提案，Named Pipe、JSON 消息、进程监督和设备生命周期均未实现或冻结。

画面采用深炭灰底、浅色粗体文字、大号呼号、矩形分区和带下沿的实体按键。琥珀色用于核心不可用，蓝色用于演示提示，绿色只保留给以后有核心证据的状态。构图参考了 [Blackmagic Design ATEM Mini 软件界面](https://www.blackmagicdesign.com/products/atemmini/software) 与 [Vizrt Control Panels](https://www.vizrt.com/products/control-panels/) 的控制台分区思路；本稿没有复制其商标或面板图案。

## 已确认的 UI 选择

- 主窗口为单页操作台。顶部用途选择默认为“FTX-1 个人终端”，另列“C4FM RF 节点”；当前因核心能力未实现而禁用，既不连接设备，也不声称 RF 可用。设置从独立对话框打开，只展示未来项目结构，不提供保存、应用或硬件动作。
- 顶部四个状态区分别显示核心、FTX-1 电台、音频与 BrandMeister。电台区独立显示 HRI、CAT 组件状态，并展示 WIRES-X 模式和 FTX-1 型号、固件、HRI MODE、Node Mode、GM/X 字段；默认没有核心快照时这些读数均待核心确认。
- 中央通话区显示发话呼号、方向、TG、TS 和持续时间。默认没有通话快照时显示破折号与无数据来源说明。
- 下部保留目标控制和运行记录。“重试连接”和“应用目标”目前禁用并解释原因。
- “停止并退出”位于底部右侧；点击与窗口关闭执行相同动作，直接退出离线 UI。本版本不驻托盘、不启动后台线程或核心进程。
- 页脚说明未来启动策略：按上次配置尝试连接；当前离线 UI 不执行该策略，也不保存配置或凭据。

## 状态字段来源规则

| 屏幕字段 | 默认画面 | 演示快照 | 未来来源要求 |
| --- | --- | --- | --- |
| 用途 | 默认显示“FTX-1 个人终端”；选择禁用并注明等待核心能力 | 同样默认个人终端；RF 节点选项保持禁用 | 核心未来需提供支持能力；选项本身不表示设备连接或 RF 可用 |
| 核心 | `不可用`；说明“核心未就绪（尚无可执行核心）” | `无核心`，并标明模拟预览 | 当前 UI run 的核心/IPC 生命周期快照；没有核心时不能显示 ready |
| FTX-1 | 状态未知；型号显示为用户选择的设备类别 `FTX-1`，固件待确认 | `FTX-1（示例）`、固件“示例标记（无版本值）”，电台未连接 | 核心实际读取的设备身份、固件及状态；读数需附来源和更新时间 |
| HRI / CAT / WIRES-X | HRI、CAT、HRI MODE、Node Mode、GM/X、WIRES-X 状态均待核心确认 | HRI/CAT 显示模拟状态；`ON`、`DIRECT`、`GM-X` 均带“示例”或持续模拟横幅 | 当前 run 核心的明确状态；不得从历史配置、原始 EX 数字或 UI 点击推断 DIRECT 已生效 |
| 音频 | 未知，尚无端点读取来源 | 虚构端点、未打开 | 核心音频组件状态；核心 ready 不能代替音频 ready |
| BrandMeister | 未知，等待核心提供连接状态 | 未连接；演示目标 TG 91 / TS 1 | 当前核心快照中的连接、目标与时隙状态；不能把合成通话视作网络连接 |
| 通话 | 无数据来源；呼号、方向、TG、TS、时长均为空 | 虚构呼号 `DEMO-01`、本地到网络、TG 91 / TS 1、00:12 | 当前 run 的通话快照；来源状态、方向和更新时间需要由核心提供 |
| 运行记录 | 尚无核心事件或记录来源 | 只显示固定演示条目 | 当前 run 的脱敏事件；不得把演示记录写入正式日志 |

`state.py` 中的快照是展示模型，不是 IPC schema。所有默认未知项保持为空/未知；`--demo` 是唯一会选择固定演示快照的入口。静态 HTML 的状态切换只改变 DOM，不写文件或调用外部服务。

## 核心需要提供的状态

真实 UI 接入前，核心需要给出当前 `run_id` 的初始快照和后续有序事件，带 `seq`、组件名、时间/新鲜度和错误说明。核心生命周期、HRI、CAT、音频、BrandMeister 应分别报告；断开 IPC 后 UI 要立即把旧快照标成 stale。旧 run 或倒退序号不能覆盖新状态。

核心还需要明确提供 FTX-1 设备身份与固件读数，HRI MODE、Node Mode、GM/X 和 WIRES-X 状态；音频端点状态；BrandMeister 连接、目标与时隙；通话方向、发话呼号、TG、TS 和时长；以及脱敏运行事件。若某读数不存在或无法确认，核心要返回未知/失败及原因，不能复用历史配置填充当前状态。

业务控制要等核心声明能力并给出参数约束、request id、错误和异步结果语义后才能启用。`accepted` 只说明接收，不代表 `completed`。核心自动启动、重试、配置和状态恢复，以及 Stop/Close 的有界 shutdown 全部等待真实监督与核心接口；此 UI 仅关闭自身窗口。

## 未实现

本切片没有核心进程、IPC、Named Pipe、JSON codec、状态事件适配、配置/凭据持久化、串口/USB、CAT、音频 I/O、PTT、RF、BrandMeister 网络、运行日志写盘或进程收尾。没有通过设备、HIL 或生产验证。PySide6 未安装，因此未运行原生窗口；HTML 视觉稿与离线状态模型不证明任何硬件状态。

## 本地验证结果（2026-10-22）

- Python 3.12.14：`python -m unittest discover -s ui/tests -v` 通过，3 项状态隔离测试全部通过；`python -m py_compile ui/state.py ui/main.py ui/tests/test_state.py` 通过。
- `python ui/main.py --help` 正常列出默认与 `--demo` 参数。直接运行 `python ui/main.py` 返回 2，并提示当前环境没有 PySide6；未安装依赖，因此没有运行或截图原生 Qt 窗口。
- 预装 Node.js v24.19.0、Playwright 与 Chrome 打开本地 `file://` 评审稿。`tools/capture_preview.cjs` 在默认/演示两种状态和 1280×900、1024×768 两种视口分别保存截图；四种布局检查均无文档滚动尺寸超出、无可见元素越过视口边界。
- 这些验证只覆盖离线状态隔离、Python 语法和静态稿布局。核心进程、IPC、串口/USB、音频、PTT、RF、BrandMeister 网络、真实运行日志、HIL 与生产行为均未验证。
